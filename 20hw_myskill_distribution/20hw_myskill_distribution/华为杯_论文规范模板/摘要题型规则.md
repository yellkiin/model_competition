# 摘要题型与关键词门禁

这是项目写作规则，不是赛事官方题型限制。摘要总长 **800--1600 个可见字符**为硬门禁，最终排版为 1--2 页。可见字符沿用审计器口径：汉字、英文字母和数字，不含 TeX 标记及标点。

每个 `role=problem` 章节在 `论文输入.json` 中声明 `abstract_type`。按题面主要科学任务选择，不能为了通过检查改题型；混合问题选择主要题型，在段落中补充其他任务。题型选择与实际证据在求解计划中说明。

每问摘要以`\textbf{针对问题X}，`开头；X为按真实问题数量生成的中文序号。以下每个分号分隔的词组均须出现，其中斜线表示任选一个；词汇必须对应真实内容，不得只堆关键词。每问另须包含方法词“采用/运用/依据”和结果词“得到/获得/证明/揭示/给出”。

| abstract_type | 任务 | 必备词组 |
| --- | --- | --- |
| optimization | 优化、调度、规划 | 模型/规划；目标函数/为目标/最小化/最大化；约束 |
| statistics | 描述统计、因素分析 | 指标/统计量/分布；统计/分析/检验；差异/关联/趋势/特征 |
| prediction | 回归预测、分类识别 | 模型/分类器；特征/输入；预测/分类/识别；验证/误差/准确率/召回率/F1 |
| mechanism | 机理推导、参数辨识 | 假设/机理/守恒；方程/关系式/模型；推导/辨识/求解；边界/量纲/验证/成立条件 |
| simulation | 随机过程、数值仿真 | 模型/过程；仿真/模拟/采样；场景/参数/分布；验证/收敛/误差/一致性 |
| evaluation | 综合评价、评分、排序 | 指标/准则；评价/评分/排序/决策；权重/偏好/标准；敏感性/稳定性/一致性/验证 |
| interpretation | 特征解释、机制分析 | 特征/机制/因素；解释/归因/分析；贡献/作用/关联/影响；消融/扰动/验证/证据/边界 |
| theory | 理论证明、判据与界 | 假设/条件；推导/证明；命题/定理/关系式/判据/界；成立条件/边界/适用范围/反例 |

`abstract_result_mode` 默认 `quantitative`：给出真实的核心数字与单位，不以固定2--4个数字配额要求补数。成果为解析式、条件、定理或反例时可选 `analytic`，不受题型枚举限制，但对应结构化结论的status必须为analytic且正文有推导/证明。原 `qualitative` 仍限mechanism、interpretation、theory的非数字机制/解释结论；不是跳过验证的例外。每问说明科学验证或可复核解析证据，不能将训练内结果、预测分配或工程校验冒充独立准确率。

`depends_on_previous` 默认 `false`。真实依赖前问时设为 `true`，并用“基于问题X”“进一步”“引入...约束”等表述写出依赖；独立问题不得虚构递进。

总起句仍以“本文针对”开头，包含“建立/构建/推导/提出”“采用/运用/依据”“得到/获得/证明/揭示/给出”三组词及具体成果。有定量任务时包含核心数字；全篇均为定性模式时可用可核验的解析结论。创新表述由真实方法差异和证据支持；全篇定性模式允许用证明、边界或反例说明差异。科学验证及其关键结果融入对应问题；不另写“最后……”式验证、局限或交付结尾。条件和理论判据作为真实结论的组成部分可以保留，但不专门讨论模型局限、数据不足、研究范围限制、未来工作或改进计划。

关键词检查只能确认写作结构，不能证明模型正确、因果关系成立或预测准确。最终必须核对词汇、数字、题型和真实证据的一致性。旧 manifest 应依据真实任务逐章补充 `abstract_type`，不得统一自动填成优化题。


## 四类短加粗与内容边界

每问必须用独立短`\textbf{...}`强调逐问引导语、核心方法名称、主要结论短语，以及关键数值连同必要单位。取消“总共2--8处、仅方法名”的旧限制；数量随问题数和真实证据变化。一个片段不超过40个可见字符，不含完整句末标点，不能整段或全局加粗。数值出现在总起句、逐问或创新表述中时均按同一事实核对。

禁止专门的局限/未来工作段落以及交付文件、哈希、打包、构建、内部验收、尺寸压力测试等工程检查内容；这些进入正文相应章或验收材料。未经真值验证的输出明确写“预测结果”，不得写成已证实真实类别或准确率。保留科学意义上的独立重算、验证、误差、扰动或解析证明，但须对应具体问题和真实证据。

## 摘要证据协议

manifest新增必需`abstract_evidence_path`，相对论文目录，指向符合`摘要证据.schema.json`的JSON。根字段为`schema_version=1.0`、`questions`；questions按manifest问题章顺序精确对应`chapter_id`，每问有statements数组。

每项statement记录`kind=method|conclusion|value|validation`、`text`（将用于摘要的TeX短语）、`source_path`（相对项目根目录的当前结构化JSON）、`source_sha256`、`source_pointer`（RFC6901 JSON Pointer）。method和validation指向字符串；conclusion指向含`text/status`的对象，status为verified、prediction或analytic；value指向含`value/unit/status`的对象，status为verified、prediction或setting。value可指定`decimal_places`（0--4，默认2）和`key`（默认true）；真实核心结果不能标为非关键。数值按明确的小数舍入与原单位比较，不静默换单位或从图读数；设置项允许不加粗，但仍须可追溯。

每问至少登记方法、结论、科学验证；定量模式另有真实关键数值。相同短语还必须出现在对应正文展开后的TeX中。解析结论需有真实推导结果，不能因为不要求数字而降低证据门槛。不可先写摘要再反向创建“结果”JSON迎合它；来源是已完成的计算或推导及独立验证。哈希与字符串一致只证明关联与当前版本，不证明研究结论为真；科学复核必须实际检查输入、方法及独立证据。

`audit_abstract.py`检查四类加粗、全部数值的结果关联、问题依赖、题型、禁写内容与关键词。生成器和TeX审计复用它。`audit_paper.py`再调用`audit_abstract_pdf.py`，匹配实际摘要字符流，并逐个检查预期短语的PDF加粗字形，同时拒绝全段加粗；源码中有textbf而实际被宏清除的情况不能通过。无法可靠映射的公式/宏会报告失败，须修复解析或表达并实际复核，不能填PASS替代。
