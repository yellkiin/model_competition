# 前三章写作、接排和实际 PDF 验收

这是题目解析、Phase 4 写作和 Phase 5 审校共同加载的详细规则。两端总控读取同一文件；正式源仍为 `论文/章节内容/*.tex`。本文覆盖旧的“所有一级章另起页”、无类别符号表和“问题的提出”命名，其他求解、绘图、摘要、文献、附录、35页正文及图数门禁保持。模板维护可修改共享资源；解题只读共享资源，不批量改历史 workshop。

## 题意依据与写作闭环

读题时复用 `求解/题面约束清单.md`，在 `求解/题意写作依据.json` 保存可核验的结构化补充。来源路径相对工作区；论文位置相对论文目录。登记题目正文、附件说明与真实核验的外部来源，逐项记录原文页码/段落/子项及摘录。扫描 PDF 须实际看页，提取文本不能代替原件核对。缺口放入 `gaps`，不得填造事实或预先授予 verified。

四种信息严格区分：题目给定的事实/要求、已核验的外部背景、作者选择的方法/假设、实际求解结果。原题规定的简化条件属于任务；作者新增假设属于第二章或对应建模位置，不能倒灌为题意。题定方法必须保留，不能因禁止提前介绍解法而删除。

每问及子项记录原始编号、输入、动作、对象、关键条件、输出、原题要求的验证、题定方法和真实依赖。共用信息包括时间、空间、观测方式、标签状态、变量和研究排除范围。问数与顺序服从题面，不固定四问；并列任务不得写成递进。保留年份、时间窗、数量、单位、“至少/至多”“且/或”“定性/定量”、必做/可选等限定，不随当前日期更新题定年份，不擅加准确率/显著性/实验数量。预测不等于解释、分类不等于因果、描述不等于优化。

写作顺序：读取原件和依据 → 内部安排段落功能及任务覆盖 → 写两个小节 → 对照原题逐项审查忠实性 → 审查表达 → 局部修订 → 再核条件。沿用总控的根因修复机制，避免无限换词；未解决硬错保留 FAIL，未核实保留待核验，不能用文风抵消事实错漏。

### 1.1 问题背景

尽快进入具体系统、工程对象或过程。通常按“场景与对象 → 具体矛盾及原因 → 已有条件能支持什么、尚需回答什么 → 本题研究需求与范围”组织。功能可以合并，通常从3～4个自然段起步，简单题可更少；不固定段数、字数或句式，不靠填字凑页。

困难要解释“某种条件使哪个判断/决策变难”。数据题突出真实数据特点和分析需求，机理题突出必要原理和关键作用，优化题突出目标、约束和冲突。仅凭材料讨论现有方法局限；不编造行业数据、研究空白或“传统方法失效”。某些题目就是给定条件下求解，不必包装成学术突破。

每段一个主线，后一段解释、承接、转折或收束前段具体信息。落到本题后不要退回行业科普。背景不是综述、方法章或结果摘要；不提前罗列每问、具体算法、实验结果或贡献。理解题意不需要的公式/表格移到建模处，不为了模仿范例硬塞。

### 1.2 问题重述

必要共同条件导语后，按原题顺序写连贯任务句：关键条件下，对什么对象做什么，需要什么输出、是否要求验证。共同条件少时可省导语；简单任务一两句、复杂任务数句，不机械输出“输入/目标/约束/输出”字段表，不强增三级标题或总体思路小节。

重新组织条件与任务，不整段照抄或逐词同义替换；可压缩故事，不能改变任务性质。作者自选算法、指标、调参工具及结果不写成原题要求；题目明定模型类别、物理效应或算法照实保留。总体路线图仍按现有规则放在本节，其图与说明须明确为本文研究安排，不能冒充原题要求；两小节任务性 prose 不提前作答。第一章总体路线图必须从当前运行时 scibox-diagram 的 assets 模板库选型适配：完整浏览目录和预览、比较候选、登记模板ID、参考预览及适配依据，保留主要视觉风格并忠实调整实际问题结构；不得虚构步骤，须实际复核成图及论文尺寸可读性。详细契约见[结构图工作流](../华为杯_求解规范/结构图工作流.md)和[模板选型协议](../华为杯_求解规范/总体路线图模板选型协议.md)。

### 自然表达与语义审查

正式、准确、克制，使用具体对象、动作、原因、影响。“意义重大/提供依据”需说明对谁、什么判断有用，否则删改；常用词不一概禁用。减少无信息的“随着发展/赋能/多维全面创新”等包装。不靠“首先其次最后”制造逻辑，不机械控制句长或连接词数量。术语、称谓和指代一致，避免任务堆叠、每句同一开头或刻意切碎。

不得把“我们已完成/结果表明/准确率达到/显著优于”的本文结果塞入背景和重述。引用已有研究应明确归属，复用现有真实文献证据机制，引用支持相邻陈述，不虚构编号；题干事实无需每句强配外引。

硬审查：问/子项覆盖，范围/数值/单位/逻辑限定，来源真实，方法/假设/成果不倒灌，依赖/输出/验证准确。柔审查：快速进入对象、段落主线、原因清晰、自然收束、少重复共同条件、没有换领域仍成立的空话，不越界到方法/结果。硬错退修，风格建议局部调整，不能只凭关键词或静态 PASS 宣称自然度达标。

## 数据接口和真实调用

manifest 增加 `first_chapters_evidence_path: "../求解/题意写作依据.json"` 和 `first_chapters_review_path: "验收输出/前三章.v1.review.json"`。每轮编译使用新的 review 路径，保留旧证据。

依据文件顶层字段：

| 字段 | 内容 |
|---|---|
| `sources` | `{id,path,kind}` 数组；kind 为 `problem/attachment/verified_external`，外部来源沿用文献核验 |
| `context` | `object_scene/difficulty_causes/scope_exclusions/shared_conditions` 数组；每项 `{text,source}`，没有的范围/共用条件明确说明，不臆造 |
| `tasks` | 按原题顺序；`order,original_id,source,inputs,action,object,conditions,outputs,validation,depends_on,required_methods,subtasks,coverage,literal_requirements`；无验证/方法/依赖时用空数组且在审阅中解释 |
| `claims` | 第一章关键事实主张 `{text,kind,source,citation_key?}`，kind 只允许 problem 或 verified_external；题外作者选择不能冒充题意 |
| `gaps` | 未解决材料/题意缺口数组，非空阻断写作核验通过 |
| `symbols` | 下述符号与首次定义登记 |
| `review` | 实际审阅者、时间、逐维观察、未解决问题及源绑定 |

`source` 统一为 `{source_id,location,quote}`。文本来源会验证摘录确实存在；PDF、表格和图像需要实际原件查看，并在观察中写清位置，不把哈希当语义证明。

每个 task 和 subtask 的 `coverage` 为 `{status,restatement_quote,observation}`：摘录必须对应当前1.2正文，观察具体说明输入/条件/动作/输出/验证如何保持。`literal_requirements` 登记必须逐字保留的关键数字、单位、逻辑限定及题定方法（不用于强制普通句式）。子项也有自己的 `original_id/source/coverage/literal_requirements`。不可通过漏登记原题子项来通过：`task_coverage` 的实际原件逐项审查负责确认库存完整。

`review` 包含 `reviewer/reviewed_at/bindings/findings`，以及八项 `{status,observation}`：`task_coverage`、`conditions_units_logic`、`source_attribution`、`method_assumption_result_separation`、`dependencies_outputs_validation`、`background_coherence`、`natural_expression`、`symbol_definitions`。初始 status=pending；只有实际审查后写 verified。`findings` 为 `{severity:hard|style,message,resolved}`，硬错未解决阻断，风格提示保留。禁止笼统“已审核”；观察应说明本题事实、修改和保留理由。

`first_chapters.source_bindings(manifest, paper_root, evidence)` 返回原件、全部正文和嵌套 TeX 的路径/哈希；仅在实际新审查时保存，不向旧 PASS 刷新哈希。任何源变化须重审，程序只能核对记录完整和当前性。

生成器 `build_latex.build_main → paper_contract.require_structure → audit_structure → first_chapters.audit_source` 强制调用；`audit_tex` 和 `audit_pdf_layout` 复用同一合同。Word 是可选派生物，同样先过源合同；不能拿 Word 的 PDF 替代正式 XeLaTeX PDF。没有新增无人调用的 skill，也没有假设存在文本生成服务。

## 三章独立编号与自然接排

固定 `1 问题重述（1.1问题背景、1.2问题重述）→2模型假设→3关键性符号说明`，独立源文件、目录和书签。第一章从目录后正文首页开始，第2、3章排在前章之后；空间不足自然跨页，标题须带合理正文或表题/表头/首行。第4章及后续一级章仍普通 clearpage，新章清浮动，不插奇数页空白。

类文件只对2、3章使用 FloatBarrier+Needspace；章节不得重复 newpage/clearpage/include。不把三章放入不可分页大盒，保留浮动控制以免路线图漂到假设章。生成器在每章输入之后插入 `GMCMChapterEnd`，清理浮动后记录实际 PDF 终点；目录标题不作起点。

`page_targets.json` 的 `first_three_chapters` 是整个章节组的推荐范围3～6页，超出产生内容与版面复查提示，不单独作为硬失败。第一章取消两页上限，扣除流程图、图题、标题和相关空白后的正文至少一页有效文字量。符号整章最多2页仍为硬限制，含章标题、表题、续表、所有行和最终注。实际 PDF 标题目的地及终点坐标界定内容，统计内容所在去重页集合并与连续范围核对；同页接排不得用“下章首页减一”计算，也不得简单相加三章页数。空白页、故意碎页不充数。

不足3页，检查真正遗漏的背景依据、必要机理、边界、子任务或实际假设的理由与范围；超过6页，检查重复铺垫及局部假设/符号是否应移回对应问题。合理内容超出推荐范围可保留，并在逐页观察说明。假设必须实际影响模型。不以空行/大间距/放大图表/无用条目补页，不缩字号/版心/字距或缩放表格挤页。实际缺失、注水或其他硬规则违反仍须 FAIL。

### 第一章净正文测量

仅计1.1和1.2的正文段落。`gmcm-layout.sty` 自动记录段落首尾PDF目的地和 `.gmcmprose` 的行距、版心及字号；非document环境、内盒段落登记为排除项。内盒还通过LaTeX的段落恢复钩子显式追踪，覆盖`parbox`、脚注和浮动体，不能仅依赖`\ifinner`判断；第一章的`center`/`tabular`边界在分组状态丢失前完成外层段落标记。`audit_pdf_layout` 调用 `restatement_prose.measure_prose`，从同一次最终PDF读取字形基线，排除非正文段落、标题、图题及页脚，并对同页同基线去重。不存在字形的空白、段距、浮动间距都不计。

标准版心高247mm、宽160mm，正文12pt、基线18pt。完整一页的基线容量为 `floor(textheight / baselineskip)`，当前为39行；正常段落末行按一行计，净文字等效页数为合格正文行数除以该容量，须≥1。不按字数、整章页数或含文字的页面数量替代。记录逐行页码、基线、包围框及段落ID，方便对照渲染图；正常上下标不另算一行。改变正文参数不能提高计数，参数不符须修复。

段落标记和机械计数不能证明内容充实。实际逐页审查必须检查拆碎短句凑行、重复题意、空泛背景、图内文字误入正文、漏计和字体异常；未知复杂TeX结构应查原件并修复追踪，不手填计数或PASS。新版测量保存在layout和待审记录的 `restatement_prose`，推荐页数提示保存在 `page_recommendations`；旧复核缺少这些字段时重新编译、渲染和审查，不刷新旧记录冒充有效。

## 关键性符号表

一个逻辑表，类别｜符号｜含义｜单位；本项目统一实现保留单位列，不适用写“—”，确实无量纲写“1”，未知单位待核查。按实际语义选择类别（索引与集合、参数、变量、评价指标等），不强凑类别、不增加未使用符号。类别重复填，不跨页合并，不按类别拆短表，不加分类线或底色。

每行一个独立对象；`i,j,k` 或 `alpha,beta,gamma` 不能一格合并、换行堆定义或并排双组。`x_{i,t}`、向量、矩阵、集合各是一个对象，真实同义索引族可用通式，角色不同不能伪装同族。含义可引用其他数学对象并自然换行，不展开长推导。上下标、正斜体、含义和单位与正文一致。

GB/T 7713.2—2022《学术论文编写规则》（[国家标准官方条目](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=0B963916637B8F34B295FCF4A51A1BE5)）第5.5节涉及表题、表头、续表等表达要求；以下精确参数是本项目要求，不能冒称该标准逐项规定这些数值：

- 每个可见片段三条实横线：顶/底1.5bp，表头分隔0.75bp，无竖线、斜线、表体横线或外框。`bp=1/72英寸`，TeX `pt=1/72.27英寸`，审计以 PDF bp 测量，线宽容差0.04bp。
- 所有单元格横向居中，长含义每行仍居中；按版心分配列宽，不缩字。几何审计记录字形中心偏差，数学字形边界容差不等同于排版命令的偏移许可，另需看局部图。
- 表题位于顶线上方居中，首表“表N 关键性符号说明”，与表头、首行同页。续页“表N（续）”同编号并重复表头，不递增计数。
- 表题和所有表内文字小四宋体12bp，数学主字号匹配且正常上下标；系统缺少 SimSun 报错。字体测量容差0.08bp，不以字体名替代实际字形查看。
- 最后底线下方边框外单独排“注：”，左对齐五号宋体10.5bp。不是表体数据行、caption或脚注；不用通用的“表注：”及小四字号。样式预留注的真实盒高，防止注单独溢出下一页。

实际模板调用 `GMCMSymbolTable` + `GMCMSymbolRow{类别}{单个符号}{含义}{单位}`，使用 longtable 真分页，每页重复三线和表头、行不可跨页、最终注只出现一次。局部环境设置字体，不改变通用图表说明。禁 resizebox/scalebox、table/minipage 包长表。

超过2页优先保留贯穿多问的公共索引/集合、核心参数、变量、目标和评价量；局部超参数/临时量移出，在正文首次使用处实际定义，不只写免责表注。`symbols` 每项含 `symbol/category/meaning/unit/scope/in_core_table/first_definition:{tex_path,quote}/uses:[{tex_path,quote}]`，在 `symbol_definitions` 逐公式复查库存完整、第一次使用已有解释、同符号无无说明换义。程序核对登记与真实表行、定义摘录和使用位置，不宣称能自动理解任意 TeX 宏的符号语义。

## 最终验收闭环

现有 `first_chapters_review_path` 同时承载“模型评价与展望”的全部页面、净正文测量与六项内容审阅；详细规则见[论文章节规范第7节](华为杯_论文章节规范.md)。本协议的前三章要求保持，采集器额外渲染评价章全部页面，最终审计要求两部分均完成实际复核。旧记录缺少评价字段时须重新采集与实际审查，不补写虚假通过。

生成/修订 → 通过源合同 → 现有 `collect_academic_paper_review.py` XeLaTeX 编译到 aux/toc/out 稳定（至少双遍，最多六遍后不稳则报错）→ PDF 坐标/去重页数/矢量线宽/文字字号与字体测量 → 渲染前三章每页和第4章首页、符号表局部 → 实际打开逐页与局部 → 修改后新编译、新渲染、新审查。

采集器按 manifest 的 `first_chapters_review_path` 自动生成待审记录。也可经 workshop 包装器调用 `audit_pdf_layout.py --pdf 论文/论文.pdf --source 论文/论文.tex --manifest 论文/论文输入.json --report 论文/验收输出/排版.json --prepare-first-three-review 论文/验收输出/前三章.v2.review.json`，它测量/渲染但不自动 PASS。

记录包含当前PDF路径/哈希、三章起止位置与去重页数、符号章全部占页、整页/局部PNG路径与哈希、参数及容差、逐页实际观察和 issues、复检状态。局部定义核验由同次源合同输出合并至 layout.source_structure，所有正文变动会使旧语义证据失效。

逐页查看接排/留白、孤立标题、遮挡裁切、断字缺字、上下标；局部查看三线、居中、分类、每行单对象、续表编号/表头、末注位置。填写每项 `reviewed/tool_ref/observation/issues`，实际全部解决后 `status=PASS,recheck=complete`。渲染/联系表/配置字段不证明已看图，不能只说“正常”；观察须具体。最终 `audit_paper` 重新核对当前PDF、坐标、测量、所有PNG与重渲染像素和逐页观察；缺失、过期或未解决直接失败。`workshop finish` 沿既有最终审计调用，不能绕过。

环境缺编译器/宋体/实际查看能力时分别报告静态、编译、测量、视觉未完成范围，不伪造 PASS。维护用例是明确标注的简化布局/语义材料，不是竞赛成果；测试不关闭生产门禁、不用正文注水通过正式论文验收。
