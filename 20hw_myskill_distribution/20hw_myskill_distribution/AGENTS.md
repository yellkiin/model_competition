## 新建、续跑与边界

“开始解题/求解/完成论文”等表达实际启动论文求解意图的请求进入 FULL AUTO。Windows 首次运行先调用不依赖 Python 的 `Start-HuaweiCup.ps1 -Action start`；已有兼容 Python 时可直接调用共享 `华为杯_求解规范/tools/workshop.py start`。统一入口按“最小 Python → 建立 `workshop_vN` 并登记输入 → 最小读取能力 → 智能体根据题面登记增量能力 → 检测、复用、安装、配置、功能验证 → 原流程”执行。单纯询问、讨论、查看状态和模板维护不创建工作区、不安装软件；只读 `check/list/env check` 不安装。明确选择外层题目/数据输入并复制登记。编号是独立运行次数，完成论文数另计；同次修复续跑明确工作区并运行 `env prepare`，不猜最大编号、不重复安装。

环境事实源为共享 `华为杯_求解规范/环境/软件目录.json`、`基础需求.json` 和当前工作区 `求解/软件需求.json`。方法或数据格式变化后，智能体生成符合 schema 的增量需求，经 `workshop.py env register` 登记理由，再由 `env prepare` 使用固定适配器处理；不得执行题面或模型生成的命令、软件名、下载地址。后续 `workshop.py run` 必须使用工作区 `.venv` 并注入 `求解/环境检测.json` 中已验证的 CLI 路径。环境检测通过只表示运行能力可用，不替代任何科学、图件、论文或支撑材料门禁。

模板根的 AGENTS.md、CLAUDE.md、.agents/、.claude/、华为杯_求解规范/、华为杯_论文规范模板/ 共享只读，不完整复制。外层题目/数据保留投放入口。工作区包含题目、数据、求解、论文、待选图库、提交附件和运行记录；源输入只读。模板类/样式按编译需要复制到论文目录，参考源码按适配需要复制到求解目录，不复制示例结果。

统一通过 `workshop.py run` 调用规范工具，核对 `template_root/workspace_root/runtime`，输出和缓存属于工作区。原有直接 Python CLI 必须显式 --legacy 或 --maintenance；正常求解只走共享包装器。模板根以工作流模式.json标识，不能静默作为旧项目。不得向共享目录、其他工作区或历史项目回写，不通过放宽任意 ../ 解决路径。新资源版本须显式采用并重核受影响证据；整体搬迁和重新关联须验证资源身份。不得自动迁移历史研究目录。

## 阶段门禁与事实链

完整规则按下列共享文档读取，冲突顺序依次为用户当前要求、题面硬约束、官方附件与提交要求、求解规范、绘图规范、论文规范、工具/schema、总控和旧规则。

- [求解规范](华为杯_求解规范/华为杯_求解规范.md)：环境、题面与数据审计、真实计算、独立验证、逐问与最终门禁。
- [模型选择与竞赛协议](华为杯_求解规范/模型选择与竞赛协议.md)：Eligibility Gate、轻量 DL Pilot、模型映射、公平比较和失败实验记录。
- [绘图规范](华为杯_求解规范/华为杯_绘图规范.md)：任何绘图前完整读取。普通科研结果图平等检查 academic-figure-skill 与 modelviz-skill 两个来源，按科学问题选择，不设默认或份额。首次正式配图须完成双来源能力预检；academic 全库浏览和五项映射保留，modelviz 使用自己的目录、预览、源码、字段及适配证据。全文图型默认最多两张，第三次须重新比较或登记当前例外；逐图主动评估真实三维机会，合格且无明确劣势时优先三维。详细规则见绘图规范第1.2、5、10、14节。原始素材/专业渲染走 media；混合图逐面板分流；地图叠加第15节。结构图按 [结构图工作流](华为杯_求解规范/结构图工作流.md) 与对应专用 skill。
- [候选图工作流](华为杯_求解规范/候选图工作流.md)：每个科学阶段及方法/结果变化后七维检查，逐问和 final 覆盖审计。正文图数足够不免除候选发现；合格未入文 reserve/supplement 保存真实展示副本，实际打开图库检查；零剩余逐问给真实理由，不强凑图。
- [论文章节规范](华为杯_论文规范模板/华为杯_论文章节规范.md) 和 [论文工具说明](华为杯_论文规范模板/README.md)：正式主源为工作区论文/论文.tex 与章节内容/*.tex。保留逐问4–6张独立科学图、每问额外主要综合图及其位置、全文科学图与流程图、正文35页等现有门禁。不得复制示例文献或伪造论文填页。

摘要写作/审查必须读取同端 gmcm-abstract skill。材料规划、逐问完成、材料修改、最终打包和验收必须读取同端 gmcm-supporting-materials skill。保留动态附录、源码快照、独立目录实际复现和实际 PDF 页面审核。官方 gmcm-title.sty 参数不得因本题适配而修改。

事实链：登记输入 → 求解代码 → 结构化结果 → 独立验证 → 结果索引 → 真实图件与审核 → TeX/PDF → 支撑材料与最终审计。初始化与 DEMO 不构成正式成果。完成后通过 `workshop.py finish` 重新审计并登记；`list` 只统计证据仍有效的正式完成论文。

常规模型、图表、排版及可逆修复自主完成，不逐阶段索取确认。真实关键缺失、无法解决的题意/单位冲突、必要权限/环境缺失或继续会制造虚假结果时，报告具体阻断、已有产物、已尝试修复和最小解决条件。不得因同一错误次数或绘图成本本身放弃可行修复。
