## 需要修正或限定

1. **优选预筛的适用范围（第107、114—118行）。** `worker.py` 对请求中 `published` 候选读取保存周期，以 `recorded > C_3(x)(1-\varepsilon)` 跳过，再对通过者做相同配置的完整 Q3 评价和审计；`recorded` 缺失时也直接确认。其生成分支 `generate(...)` 提出的新候选没有 `\widetilde C_3`，直接调用完整评价。故“只有已保存周期过门槛的候选进入完整确认”不能概括所有候选，算法第114行也不能无条件说当前运行重新生成了这些构造。若本节只陈述主结果的 `bank_only` 阶段，应明确限定为“已保存候选库”；若兼述在线生成，则把两条路径写开。建议用下段替换第107行相应句子：

   ```tex
   对已保存的候选库，记候选记录的周期为 $\widetilde C_3(y)$；
   仅当该记录缺失或 $\widetilde C_3(y)\le(1-\varepsilon)C_3(x)$ 时，
   才在相同配置下重评并核验。在线新生成的候选没有这一预筛记录，
   在预算允许时直接进入完整评价。确认可行后以 $(C_3,D_3)$
   字典序更新；阶段结束时仅在相对周期改善达到 $\varepsilon=10^{-3}$
   且方案确已改变时发布新方案，否则保留 $x^0$。
   ```

   若实际主结果仅走 `bank_only`，在线分支可不写入主算法，改为把“这些构造组成候选库，优选阶段读取候选库并去重”写清。`worker.py` 的结束判定还检查 `plan_key` 已改变；未变方案即使同周期额外 COPY 字节改善，也不会触发新方案发布。千分之一是候选库预筛和最终发布门槛，确认时的字典序比较仍可接受同周期较少额外 COPY 字节的暂存最优。

2. **“依赖图”和“原图弱连通分量”的节点范围（第80、95行）。** `band_candidates.py` 和 `cache_candidates.py` 都先排除 `COPY_IN/COPY_OUT`，再收缩这些排除节点产生的算子依赖；层带深度、同层带弱连通分量以及整图独立分量都是在这个计算算子投影图上求得。当前文字容易使读者按含 COPY 节点的原图直接求弱连通分量，所得划分未必相同。建议第80行首句写成：

   ```tex
   在排除显式 COPY 算子并收缩其依赖后所得的计算算子 DAG 上，
   定义 $d(v)$ 为从根算子到 $v$ 的最长依赖链长度，根节点取0。
   ```

   第95行的“原图的独立弱连通分量”相应改成“上述计算算子依赖图的独立弱连通分量”。

3. **通信代理的对象与 FIFO 前提（第91行）。** `_views` 把原始张量 ID 作为通信对象；若源文件中存在直接算子到算子的边，还按边索引建立独立虚拟张量，大小取该边的 `data_size`，不会把相同字节数的不同边误当同一张量。`_weighted_plan` 只对新出现的 `(对象ID, 来源核心, 消费核心)` 三元组计费；外部输入以 `None` 为来源，同组内部生产消费不计跨核传输。读入折中系数 `1/2` 仅在对象大小满足 `0<b_t\le B_{\rm L2}`、代理 FIFO 队列中仍有该对象、其首次入队层带严格早于当前层带时启用。模拟队列仅随新增通信关系插入；它不是正式执行轨迹中的填充队列，也不按同层带候选的读取时间推断命中。建议补一句：

   ```tex
   此处的“张量”还包括由直接算子边及其传输字节数构成的独立虚拟对象；
   代理驻留须满足 $0<b_t\le B_{\mathrm{L2}}$、仍在模拟队列且
   入队层带严格早于当前层带。该队列只在新增三元组计费后更新，
   不代表执行器实际填充时刻。
   ```

   第84—89行 `0.7/0.3` 映射公式、`\lambda\widehat T_{\rm comm}` 及并列规则与 `_weighted_plan` 一致；`A` 是当前层带流水线负载，`B` 是截至此时的累计流水线负载。通信代理对跨核对象在读入项外再计 `b_t/\beta_{\rm DDR}` 和固定交接延迟，正文无明显算式错误。

4. **多尺度集合与适用核数（第93行）。** 三份层带源码合起来确实是普通层带 `2,4,16,32,64`，通信权重 `0.25` 对应 `4,8,16,32,64`，另有 `(8,0.75)`；但 `band_candidates.py` 和 `refine_candidates.py` 在单核时立即返回，不生成层带候选。建议在参数句末补“层带候选仅在核数大于1时生成；单核保留基线或其他可行候选”。重复方案按算子所属核心及核内子图位置去重，候选数不是参数组合数。

## 已核实可保留的表达及边界

- `cache_candidates.py` 保留计算算子弱连通分量完整，按流水线、外部输入读入、输出写出估计资源负载，以 `max(load)+0.15 sum(load)` 选核心；对同核已用过的外部输入不重复计读入。曾在更早归核分量中用过且可容纳于 L2 的输入可用 L2 带宽作估计，这同样只是代理。输入并集容量控制的是相邻分量打包工作集。第95行的主要机制成立；若要更精确，可注明“已经见过且可容纳的输入按 L2 带宽近似估计”。
- `_frozen/.../candidates.py` 的 `weak` 单元化、就绪集拓扑排序、`(-h_{\mathcal U},a_{\mathcal U})`、再按优先级打破并列、低新读入工作集策略及全局顺序投影到各核，与第99—105行一致。这里 `I(\mathcal U)` 只对**原始保留张量身份**计数：所有生产者都在单元所属核心时排除，外部输入仍纳入；相同逻辑 ID 按最大张量大小归并。模拟 FIFO 按就绪单元被选出的顺序更新，已驻留对象不刷新位置；它只为排序提供代理，不承诺执行器的真实命中。源码还具备 `topo4` 细分和 `shared/stagger` 排序策略，但 `worker.py` 注释表示较差的 `topo4/shared/stagger` 未纳入其后续调度；不能仅因函数存在就要求正文逐项罗列。
- `worker.py` 的正式确认调用 `session.evaluate(p,3)` 或对保存响应作同计划、同配置审计；通过后以 `(makespan, added_copy_bytes)` 字典序暂存最优。最终若门槛未达则回退基线；选定方案再作同一计划的无 L2 评价，已有匹配的无 L2 响应可复用。第107行“完整确认”和第122行“同方案配对”的方向正确，但“完整确认”不必理解为每次必重新运行：基线与部分已保存响应可经严格审计复用。
- 第91行的折中命中代理、第95行的资源代理、第105行的 FIFO 代理，均不得写作最终周期或真实命中判定。最终性能应以完整官方 Q3 响应为准。
