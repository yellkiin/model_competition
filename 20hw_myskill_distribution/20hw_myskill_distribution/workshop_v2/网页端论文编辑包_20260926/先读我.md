# 网页端论文编辑包

本包以 `workshop_v1/` 为根，保留论文 `\input` 和图件的相对路径。打开 `workshop_v1/论文/论文.tex` 修改正文；`论文/论文.pdf` 是现有定稿页面的视觉参照。

## 推荐读取顺序

1. `论文/论文.tex`、`论文/摘要.tex`、`论文/章节内容/*.tex`、`论文/综合图片段/*.tex`、`论文/references.bib`；先看现有全文、章节及引用。
2. `求解/论文理论/bindings/20260925T204725662983Z/` 中的 `THEORY.md`、`ALGORITHM.md`、`TERMS.json`、`SOURCE_MAP.md`、`PAPER_ROUTE.md`、`references.bib`；再读 `求解/THEORY_ALIGNMENT.md`、`求解/METHOD_TO_CODE.csv`、`求解/TERM_SYMBOL_LEDGER.json`。理论包是原始输入，对齐文档记录最终版本。
3. `求解/规范化数据/combined/SUMMARY.json`、`main.csv`、`pairs.csv`、`anytime.csv`，以及 `求解/规范化数据/studies/cache_parameter_grid.csv`、`trace_fifo_events.csv`；改数字、图表或结论时逐例核对。
4. `提交附件/支撑材料文件/其他支撑材料/实际执行源码/` 与 `提交附件/支撑材料文件/其他数据/官方评价代码/`；只有改算法和执行语义时才深入核读，按 `METHOD_TO_CODE.csv` 定位，不重新设计求解器。
5. `正式图件/` 中有20张中文正式图、SVG/TikZ和绘图程序；正文实际引用的PDF路径位于 `求解/问题一|问题二|问题三|总体/图片/`。改图可使用 `求解/draw_*.py` 和 `求解/结构图源码/`。
6. `题目/` 是原题；`资料/文献卡/` 和 `资料/文献原文/` 支持定义、引用与原文页码核对。

## 数据范围

主表为100图、1400项配置；第三问为500组同一完整方案的无L2/有L2配对。每30秒结果取当时已获得的可用解。三项新增官方评价见 `资料/补算清单.json`，不写回原始搜索时间线。`资料/selected_index.csv` 是已选原方案/响应的索引；526MB原始逐例计划和响应未放在本编辑包，可从本项目GitHub私有Release的 `paper_final_data_and_recalculations_20260926.zip` 获取。

仓库：`yellkiin/model_competition`。数据Release：`https://github.com/yellkiin/model_competition/releases/tag/orion-local-data-complete-20260926`。项目内原始包仍在 `D:\数据`，网页端不能直接读取该路径。

请保留既有“联合决策—统一执行—多邻域迭代改进”方法，正文统一使用“总体任务执行时间（Makespan）”，不要把代码目录名或原搜索补算过程写成新算法。修改后重新编译、实际查看图件和PDF页面，并更新受影响的摘要、数据表、图件和结论。
