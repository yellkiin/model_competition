# 华为杯绘图规范

共享运行的命令变量 `$templateRoot`、`$workspaceRoot`、`$runtime`、`$python` 按模板 `华为杯_求解规范/工作区工作流.md` 的“命令变量”设置。工具从共享模板读取，子进程 cwd 为工作区；本题路径相对工作区，skill 内部引用相对本 SKILL.md。

本文件是本项目绘图与可视化规则的唯一详细事实来源。它适用于 Codex、Claude Code 以及任何为华为杯论文生成、修改、审查或解释 Figure 的自动化流程。项目总控文件只负责触发本文件和定义门禁；求解规范只保留 Figure Plan、结果追溯、计算/绘图分离和质量门禁；论文规范只处理 LaTeX 接入与版面可读性。`求解/求解计划.md` 保存人类可读的证据与图件叙事，`求解/视觉计划.json` 保存同一计划的机器可审计字段；两者的 ID、数据源、输出、标签和状态必须一致。

## 1. 适用范围与触发条件

在以下任一动作前，必须先完整读取本文件：

- 创建、选择、修改、审查或解释任何 Figure、Table、可视化或图形代码；
- 在 `求解/求解计划.md` 或 `求解/视觉计划.json` 中编写或更新 Figure Plan、Schematic Plan；
- 在 `求解/求解计划.md` 中编写或更新 Flowchart Plan；
- 生成 `求解/问题X/图片/` 中的正式图片；
- 将图片、TikZ 图或图表引用写入论文；
- 处理三维图、多面板图、渐变、透明度、柱状图、饼图、SCI 风格图或流程图。

触发后必须按以下顺序执行：

1. 阅读本规范和题面约束；
2. 在 Evidence Matrix、Figure Plan、Schematic Plan 或 Flowchart Plan 中定义科学问题、真实来源、视觉编码和输出；
3. 运行计算并把结构化结果落盘；
4. 绘图脚本只读取已经落盘的结果，不重新训练、优化或猜测数字；
5. 渲染、审查、记录质量状态；
6. 只有通过质量门禁的图才能进入论文。

### 1.1 中文显示、字体检测与反乱码门禁

普通科学结果图的可见标题、坐标轴、图例、Panel 描述、注释、图内统计
解释和图注默认使用中文；原始数据字段、源文件和计算代码不因显示适配而
改写。应先 Copy-First 复制生产脚本，再只在渲染层映射标签或数据路径，并
在 Figure Plan 记录映射。

- Python 图必须通过项目内 `academic-figure-skill/scripts/chinese_fonts.py`
  检测实际安装且覆盖所需字符的字体，必要位置使用 `FontProperties`，并
  设置 `axes.unicode_minus=False`；
- R 图必须用 `systemfonts` 或等价机制检测字体，并用 Cairo 设备渲染 PNG/PDF；
- 必须执行 `fig.canvas.draw()` 或等价渲染调用。字体烟雾测试覆盖中文、单位、
  RMSE、负值、希腊字母和上下标，并检查 PNG/PDF 的缺字、重叠、裁切、缩放
  和灰度可读性；
- 缺少字体、检测不到字符、渲染警告或视觉检查失败时，Figure 状态为“未完成”，
  不得进入正式图片目录或论文；
- 流程图、模型结构图和总体技术路线图遵守第 9 章的 Flowchart Plan 门禁与
  结构图工作流的分类skill与后端选择规则，不由普通结果
  图适配层替代。

### 1.2 双来源预检与平等选型

academic-figure-skill与modelviz-skill都是一级候选来源，不设默认、兜底顺序或各半份额，不引入第三套默认风格。科学正确性、真实数据语义和实际论文尺寸可读性是硬约束；随后落实第5节三维偏好及下述全文多样性，保留所选模板有意义的设计。相同变量/模型的颜色、单位和标记跨图稳定，不把modelviz全部强改成academic版式。

首次规划正式普通科研图之前，实际读取当前运行时两份SKILL.md、完整能力索引、适用数据结构和限制。Codex路径为`.agents/skills/academic-figure-skill/`和`.agents/skills/modelviz-skill-main/`；Claude只在`.claude/skills/`按front matter `name`发现对应身份。`drawing_sources.discover`要求唯一同端匹配并核对显式skill_root，禁止跨端、链接外跳、空壳或自动整包复制。版本内容摘要和能力概览写到本次工作区。

academic保留完整索引及实际浏览`assets/figure-atlas/`、`assets/figures/`全部图像/页/帧，以及候选族全部源码与示例精读。modelviz动态枚举完整`docs/template_catalog.yaml`，结合`template_index.csv`和`stage5_stage6_skill_workflow.md`理解用途，生成可读能力表及分页预览总览，实际查看可用预览；损坏/缺失资源明确记录原因，不能声称已看。首次不要求执行全部模板或读完全部源码，选中后精读真实源码、预览、依赖和限制。读取成功、哈希或脚本输出不证明已理解/已看图。

`tools/drawing_sources.py --runtime codex --output 求解/绘图能力预检.json`只初始化待审记录和modelviz总览，academic浏览继续用原索引工具；通过`workshop.py run`执行。预检记录对应`drawing_preflight.schema.json`，包含两端身份、真实路径、包摘要、能力/数据结构/限制观察、academic gallery_review路径及modelviz逐模板逐页实际观察。相同版本可以复用，资源变化须重新准备并审阅；不得只刷新摘要。上下文压缩、续跑或交接时重新读能力概览、当前计划和所选原图。该门只约束正式配图，不锁住探索、基线或正式数值求解。

选图先分析科学问题、真实结果字段/单位/形态及证据用途，再检查两来源候选，通常比较2–3个真正适用方案。无适配来源写具体限制，不硬凑；top-k仅用于召回，疑似遗漏时扩大查询/查看完整目录并据实更新候选，最终选择必须属于登记集合。不同库原始分数不可直接排序，关键词第一名不等于科学优选。

`rendering_route=academic`作为兼容的普通统计内容路由；`source_skill`显式区分两来源。academic面板保持.assets.json v2 atlas/生产源码/五项映射；modelviz面板用.modelviz.json的template_id、包目录、预览/源码哈希、代码位置、字段单位映射、设计继承与适配依据，不伪造academic资产。同一Figure可混合来源，各面板及整体真实执行/输出必须通过各自门禁。素材、地图和结构图按科学内容走专用路径，不能因出现在modelviz目录就改成统计图，也不能把统计图改称专业渲染逃门。

新计划v1.2增加`drawing_preflight_path`、面板`source_skill/chart_type/chart_families/chart_review/selected_candidate_id/comparison_group`及Figure的`selection`。原figure_family仍是科学任务类型，不能充当重复计数键。selection记录真实结果证据哈希、figure_sha256、两个source_checks、候选及取舍、three_d和重复例外。严格字段结构见视觉计划schema。旧v1.0/v1.1可读；共享新运行不得降版本逃门，缺新证据明确待补，迁移保留历史不转移PASS。

全文先规划实际图型分配，默认同一chart_family最多出现于两张独立正文Figure；第三次必须比较能保留结论的替代表达，确会损害科学含义、论文可读性或必要跨图可比性才允许例外。`chart_family_map.json`是可维护的语义归一化映射，热力/相关/聚类热力/换色热力均为heatmap，来源切换不重置；立体柱仍为bar，surface与contour可以区分。混合模板列全实际面板图型，禁止multipanel兜底；新增映射必须有源码/原图审阅依据，chart_review说明实际保留/移除元素。

同构对比面板同一家族按Figure一次计数，保留面板与comparison_group；不得拼接无关问题规避。重复引用、历史或失效图不计新图；结构/素材预览不套统计限额；综合图复用登记overview/detail联系，不冒充独立证据。reserve/supplement分开，不能因限额阻止有价值备选。

例外逐Figure登记`chart_family/figure_ids/scientific_purpose/alternatives/reason/evidence/portfolio_sha256`，明确比较过的其他图型与舍弃理由；“无替代”“好看”“保持一致”不合格。超出两张的每张均需例外，关联当前全文集合和结果证据；候选晋升、替换、面板或选择集合变化后全篇重核，不能机械先到先得。机器只检查记录/关联/当前性，不证明判断合理。

每图真实执行后保留矢量PDF/SVG、300dpi PNG、实际尺寸、中文与灰度检查，实际打开原图—成图对照、终PNG、矢量页面；分别填写科学有效性、参考保真、印刷可读性。计划、运行、技术、实际视觉和真实论文入文是不同状态。source/data/style/output变化使旧QA失效。DEMO不能通过正式paper门。


### 1.3 原始视觉素材、专业渲染与混合图

先按每个面板的实际科学内容分流，文件扩展名仅是读取线索，不能决定豁免。本文后续普通统计图执行双来源规则；矢量输出适用于两来源，五项映射专指academic来源面板；原始素材与专业渲染执行本节和第15节，结构图执行第9节。存在普通统计面板的项目仍完整执行双来源预检及academic全库门禁，不因混合图或附件类型而降低。

| rendering_route | 科学内容与边界 | 证据路径 |
|---|---|---|
| academic（旧计划缺字段时的默认值） | 方法比较、指标趋势、误差分布、相关矩阵、敏感性、稳健性及普通波形/频谱曲线等统计结果；输入可来自任意附件 | 按source_skill使用`.assets.json`或`.modelviz.json`，双来源预检/对应来源精读/真实运行/实际对照 |
| native_media | 原始图片、视频帧、真实格式重建图像及其裁剪、标注、拼接、局部放大和帧序列 | `.media.json`，原件—处理后对照及可复现处理 |
| domain_render | GIS、遥感、地形、具有真实坐标含义的科学场切片、点云、真实三维对象、语谱/MFCC和证据关系网络 | `.media.json`，专业元数据、计算参数、源切片—渲染对照；地理内容叠加第15节 |
| structure | 算法/物理机理/流程/综合结构面板 | 已有结构图专用skill与 `.diagrams.json`；混合图引用对应记录 |

native_media/domain_render不强制academic图库浏览、候选模板、生产源码继承或资产映射，可以借鉴排版但不强找无关模板。不能将任意矩阵改称空间场，不能把统计比较改名为地图、图像或专业渲染。根据科学问题选择必要表达，不按九类附件逐个机械出图；读取细则见求解规范“视觉附件读取与派生”。

逐面板登记 `rendering_route/content_kind/route_reason`，包含原始/专业/结构面板的Figure还须填写 `count_role=independent_science|illustration`。参数中记录科学变量、单位、坐标、切片、选帧和显示变换；metadata读取成功、人工分类审阅、科学解释各自独立。来源图片、题面示例和参考论文图均须注明性质，引用不能变成当前实验结果。

所有路径保留来源、许可、原始文件只读、真实计算、输入输出关联、可复现代码及实际视觉复核。专业处理先计算落盘，再渲染；禁止生成式增强创造细节、调整数据改善效果或挑选有利帧掩盖失败。坐标、标签、单位、透明度和跨图色义遵守科学语义；真彩色无需colorbar，连续数值须有变量与单位色标，分类须有分类图例。地图比例尺、方向、坐标网和图例逐项判定适用性，不能添加不正确或无意义的元素。

原生位图可作为正式输出。检查原始像素、显示变换和实际入文毫米尺寸，不以修改DPI、插值放大或PNG套PDF冒充高清/矢量。混合图尽量保留矢量标注与统计图元；包含academic或modelviz统计面板时仍要求正式PDF/SVG，不整体栅格化。灰度、缩放和局部检查保留，依赖色彩的专业内容登记限制和辅助编码，不强改科学语义。

## 2. BrightTech-Info 可选视觉偏好与语义 token

**BrightTech-Info** 是华为杯项目的可选视觉偏好和语义 token 参考，不是所有 Figure 的强制模板。普通科学结果图服从所选定 skill（`academic-figure-skill` 或 `modelviz-skill`，禁止绕过资产另造风格，见 8.1）对数据语义、实际论文尺寸、字体、色盲友好和灰度可读性的判断；只有在不冲突且确实有助于表达时，才采用 BrightTech-Info 的高亮度、多色、适度半透明或轻量科技感。这里的“色彩丰富”指同一论文在不同数据语义间形成稳定而有层次的蓝、青、紫、绿、橙等视觉词汇，以及连续量使用合适的顺序/发散色图；单个 Figure 的颜色数量服从真实类别和所选参考设计，不机械限制为 2--4 色。不得为了保持某种品牌外观而改变图型、增加装饰或牺牲可读性。

### 2.1 基础画布与几何

- 优先白色或极浅灰背景；不使用大面积深色背景，除非题面或 skill 的数据语义明确要求。
- 辅助网格使用浅灰、低对比度线；非必要外框弱化或删除。
- 线条、节点、点和标注保持清晰，不使用夸张发光、厚重阴影、纹理背景或装饰性 3D。
- 论文缩放后仍须能读取中文、负号、希腊字母、上下标、单位和图例。
- 总标题由 LaTeX `\caption{}` 承担；图内只保留必要的 Panel 编号、轴标题、单位和关键注释。

### 2.2 颜色、渐变和透明度

- 颜色必须服务于数据语义。Baseline、Main Model、Competitive Model、Best Solution、区域、类别和连续变量在全文中保持一致。
- 连续变量允许使用有明确数值顺序的多色渐变；优先感知均匀、色盲友好、灰度仍有层次的色图。禁止无语义地使用彩虹色制造伪层次。
- 分类变量使用稳定且可区分的离散色板；可优先从蓝、青、紫、绿、橙等颜色中选择，但具体色值由 skill 按数据语义、色盲友好和灰度可读性决定，类别顺序改变时不得重新随机分配颜色。
- 普通结果图的半透明用于置信区间、不确定性带、密度层、重叠区域或背景辅助层；结构图允许同一对象的薄片叠层和半透明表面。核心曲线、边界、文字、坐标轴和图例保持较高不透明度。
- 透明度不能遮蔽数值、改变面积/密度判断或造成重叠区域无法区分；同一语义层在不同 Panel 使用相同 alpha。
- 颜色不能成为唯一编码。关键比较还应使用线型、marker、位置、边界或文字，保证灰度打印可辨。

## 3. 视觉编码表与颜色语义

每个真实项目必须在 `求解/视觉编码表.md` 固化实际采用的语义 token、色值、线型和 marker。下表只规定抽象语义，不强制固定 HEX；具体色值由本图选定的 skill（`academic-figure-skill` 或 `modelviz-skill`）根据当前 Figure 的数据结构和输出尺寸决定，并在项目表中固定复用。

| Token | 抽象语义 | 推荐线型/marker |
|---|---|---|
| Baseline | 基线、原始方案或对照 | `--`, `o` |
| Main Model | 主模型、最终采用方法 | `-`, `o` |
| Competitive Model | 竞争方法或替代模型 | `-.`, `s` |
| Best Solution | 最优解、关键方案或被强调结果 | `-`, `*` |
| Continuous Gradient | 连续量、响应面、密度或热力层 | colorbar |
| Uncertainty Band | 置信区间、预测区间或不确定性 | alpha 由数据可读性决定 |
| Highlight | 阈值、峰值、交叉点或关键事件 | `:`, `D` |
| Neutral Auxiliary | 辅助线、背景参考、不可比较的注释 | `:`, `x` |

需要额外类别色时，可登记抽象的 `Category Green`（具体色值由 skill 选择并写入项目视觉编码表），并在全文固定复用；不得临时改色。

要求：

- `Baseline`、`Main Model`、`Competitive Model` 和 `Best Solution` 在所有 Figure 中复用同一语义；
- colorbar 必须写明变量、单位和方向，且共享量纲的 Panel 共享范围；
- 灰度备份至少给出线型/marker/明度对应关系；
- 不为了“颜色丰富”给无数据含义的元素换色；
- 颜色选择与题面官方色彩要求冲突时，题面优先，并在编码表记录例外。

## 4. 图型选择矩阵

图型由科学问题、数据结构和可读性决定，不存在默认图型。Figure Plan 必须写明为什么选择该图型以及为什么没有选择更简单的替代图。

### 4.1 趋势与变化

- 适用：时间序列、迭代过程、参数扫描、预测轨迹和变化率。
- 推荐：折线图、时间序列图、变化率图、预测曲线、置信带。
- 数据：有序连续轴和同一指标的多组观测/预测。
- 布局：共享 x 轴的 1×2 或 1×3；主曲线与残差/区间可组合。
- 不适用：类别没有自然顺序或每组只有一个独立数值。
- 单独出现：当趋势本身就是结论时可以；否则与误差或分布 Panel 组合。

### 4.2 方法比较与排序

- 适用：Baseline、Main Model、Competitive Model 的指标或排名比较。
- 推荐：排序点图、误差线图、箱线图、小提琴图、水平条形图；柱状图仅在类别少且长度比较确实必要时使用。
- 数据：模型×指标、重复实验或交叉验证结果。
- 布局：按指标分面或 1×2（性能/误差），共享零线和尺度。
- 不适用：类别很多、尺度差异大或需要展示完整分布时的单色柱图。
- 单独出现：精确比较可单独出现，但优先配合不确定性或排序信息。

### 4.3 预测与回归验证

- 适用：预测可靠性、残差结构和校准。
- 推荐：实际值–预测值散点、残差图、残差分布、预测区间、校准曲线、Q-Q 图。
- 数据：观测值、预测值、残差、分组或时间索引。
- 布局：2×2（预测对比、残差、分布、校准）或 1×2（主对比/残差）。
- 不适用：只展示单一相关系数而不展示误差结构。
- 单独出现：实际–预测图可作为主证据；其它诊断通常与它组成 Panel。

### 4.4 分类与聚类

- 适用：类别判别、阈值选择、嵌入结构和聚类质量。
- 推荐：混淆矩阵、ROC、PR、PCA/UMAP 散点、聚类分布、Silhouette 图。
- 数据：标签、概率、嵌入坐标、距离或聚类编号。
- 布局：2×2 或 1×3，类别颜色与全篇编码表一致。
- 不适用：类别极不平衡时只给 accuracy 柱图。
- 单独出现：混淆矩阵或 ROC 可单独出现，但应在正文解释基准率和阈值。

### 4.5 优化与决策

- 适用：收敛、权衡、敏感性、资源分配和调度。
- 推荐：目标函数收敛曲线、Pareto 前沿、参数敏感性热力图、资源分配图、Gantt 图、优化前后对比。
- 数据：迭代历史、可行解、目标向量、参数扰动、任务时段和资源量。
- 布局：收敛/可行性 1×2；Pareto/敏感性可 1×2 或 2×2。
- 不适用：用装饰性曲线代替约束可行性或目标定义。
- 单独出现：Pareto 或收敛图可作为核心图；资源图需在题面确有调度/分配含义时使用。

### 4.6 分布、不确定性与稳健性

- 适用：误差、重复试验、bootstrap、扰动和鲁棒区间。
- 推荐：箱线图、小提琴图、KDE、ECDF、bootstrap 分布、灵敏度图、鲁棒区间图。
- 数据：重复样本、模拟结果、扰动场景和分位数。
- 布局：同一指标按方案分面，共享 y 轴；不确定性带与主趋势共享色义。
- 不适用：只用均值柱图隐藏分布和异常值。
- 单独出现：分布图可单独出现；KDE 需在样本量足够且带宽合理时使用。

### 4.7 关系与相关性

- 适用：变量关系、回归结构、相关性和密度。
- 推荐：散点图、回归关系图、hexbin、相关矩阵、散点矩阵。
- 数据：成对观测、分组、密度或相关系数。
- 布局：散点+边际分布或相关矩阵；第三变量最多再加入一种视觉通道。
- 不适用：同时用颜色、大小、形状、透明度和分面编码过多维度。
- 单独出现：关键关系可单独出现；相关矩阵需配合显著性或变量筛选解释。

### 4.8 空间、结构与流程

- 适用：空间分布、等值线、网络、数据流和图像叠加。
- 推荐：空间分布图、等高线、网络拓扑、Sankey、流程图、图像分割叠加、结构图。
- 数据：坐标、几何对象、边/节点、流量或真实图像。
- 布局：主空间图配局部放大、剖面或误差 Panel；流程图保持真实数据流方向。
- 不适用：没有空间或拓扑含义的装饰性地图/网络。
- 单独出现：流程图可单独出现但必须支撑模型结构；Sankey 必须有守恒或流量语义。

## 5. 主动评估三维机会与有条件优先

每个普通科研Figure的selection.three_d必须判断真实三维机会。第三轴可为真实空间、参数、响应量、有解释意义的分组层或时间切片，来自题意和已验证结果；禁止虚轴、补数和无意义高度。适用时比较实际三维候选与二维替代，三维科学正确且论文表达合格、无明确劣势时优先选用；回到二维必须记录具体数据/遮挡/尺度/阅读原因，不能只写“二维简单”或“习惯”。不设最低三维数量，不为立体效果增加实验。

主动考察响应面、曲面+等高线、三维散点、轨迹、多目标前沿；modelviz的cmp_3d_ribbon_chart、cmp_3d_waterfall_distribution、cmp_3d_stacked_surface、mpn_3d_surface_scatter_report是候选而非必选。逐图核对实际含义及印刷尺寸。轴记录field/unit/meaning/result_file/range并绑定真实字段与证据，记录视角、遮挡处理、色标与定量依据、二维投影/等高线/辅助视图；辅助视图可在同一Figure，不另造图凑数。

禁止装饰性3D柱、3D饼、无数据坐标、过度透视或透明。缺真实关系则采用优质二维并记录不适用原因，不能制造数据。三维也参与全文图型限额；优先找另一种适用三维表达，否则允许有证据的二维或重复例外。必要补算由求解代码真实完成、独立验证并落盘，再绘制。


## 6. 柱状图、饼图及相关限制

柱状图不是默认图型。只有类别少、数值长度比较是核心问题，且排序点图、误差线图、箱线图或热力图不能同等清楚表达时才使用。类别较多时优先水平条形图；必须说明颜色的类别语义；不得使用装饰性三维柱状图或大量无意义单色柱图。

饼图不是默认图型，也不能单独作为核心证据。仅在少量（原则上不超过 4–5 个）互斥类别的整体构成是科学问题时使用，并优先作为多面板 Figure 的一个 Panel，与趋势、排序、堆叠图、热力图、流程图或其它诊断组合。能用排序点图、堆叠图或面积图清楚表达时放弃饼图。禁止三维饼图、爆炸效果、厚重阴影和装饰性渐变。

## 7. 多面板 Figure 与布局

- 一个 Figure 围绕一个科学问题；不同科学问题不得为了凑图数硬拼。
- `quantitative_grid` 只在 Panel 科学权重相当时使用对称布局；`schematic_led`、`image_plate_quant` 和 `asymmetric_mixed` 应按证据主次与所选参考决定是否指定 hero panel 及其面积比例，不能强制 1.2--1.5 倍。
- 1×2 适合二元比较或主结果/残差；1×3 适合三个互补维度；2×2 适合四种诊断；2×3 适合六个同构对象。非规则布局、局部放大和 inset 只能由真实信息结构驱动。
- Panel 之间保持与科学问题相符的语义一致性（单位、共享轴/色标和必要的视觉 token）；字体、字号、线宽、marker、alpha、布局细节和图例摆放由本图选定的 skill（`academic-figure-skill` 或 `modelviz-skill`）按目标尺寸决定，除非题面另有硬约束。
- 子图编号统一为 `(a)`、`(b)`、`(c)`，放在不遮挡数据的位置；总标题由 `\caption{}` 给出。
- 共享 legend、colorbar 和轴标签优先；重复图例和重复刻度应合并或删减。
- 先增大 Figure、调整布局、减少标注、调整图例和稀疏刻度，再考虑小幅缩小字号；最终字号、线宽和尺寸遵循所选定 skill（`academic-figure-skill` 或 `modelviz-skill`）的实际论文尺寸与可读性 QA，项目不设跨 Figure 的固定字号或线宽。
- 不用大量逐点标注、拥挤文本或空白分页来制造页数。

### 7.1 视觉证据覆盖与组合门禁

Figure Plan 在探索小实验与基线确定结果结构后形成，于正式绘图前完成并审计。正式数值求解不受绘图规划阻断；补充扫描、重复试验和统计量由求解代码真实计算落盘，再更新计划，不得在绘图脚本中制造数字。

每个问题的 Evidence Matrix 至少审查以下四类视觉证据，并为每一行填写 `figure / schematic / table / text / N/A`：

1. 机理、几何、坐标、数据流或算法结构；
2. 主结果和题目要求的关键输出；
3. 独立验证、误差、守恒量、约束或理论边界；
4. 敏感性、鲁棒性、场景、收敛或反事实。

#### 独立科学图与额外综合图

- 每问必须有4–6张独立科学图，用于不同且必要的科学论证，可为普通结果图、算法/物理机理图或其他有独立科学用途的结构图。
- 每问额外强制有1张主要图文综合流程图，位于首节“问题的描述与分析”内，必要描述分析之后、第二个二级标题之前。它有独立编号、短caption、label和正文引用，但不抵扣4–6张额度；每问通常合计5–7张。内部Panel不单独计数。
- 排除各问主要综合图后，全文仍须至少16张合格正文图；总体技术路线图可计全文，不归入逐问额度。正文至少2张有真实流程语义的图另行检查，合格主要综合图和总体路线均可满足。
- 综合图默认优先直接复用合适原图做总览，允许缩略细节不可读并关联正文详细图；详细独立图必须增加结构解释、定量细节或验证证据。不得直接拆出综合图面板、重复排版或对同一证据仅换图型凑数。Panel、重复引用、图库参考、附录与补充图均不抵扣正文额度。
- `视觉计划.diagrams.json` 的 `figure_accounting` 按 `图数口径.schema.json` 列全图ID、用途、所属问题、逐问/全文/流程资格和科学贡献；资格由 `figure_accounting.py` 根据实际计划与overview映射重新推导，不接受手工改布尔值绕过。规划、逐问完成、render、tex/paper及final链都要查账；结果索引、论文图表清单和审计报告保留同一口径。声明不证明科学价值，必须继续通过来源、真实运行、资产参考、实际看图及独立证据审查。

**账表发布与一致性门禁。** 用 `tools/build_figure_accounting.py --project-root . --plan 求解/视觉计划.json --stage plan --runtime codex` 从同一计划生成 `论文/图表清单.json` 和 `求解/结果索引.md` 中由 `GMCM-FIGURE-ACCOUNTING` 标记围住的账表；Claude显式换运行时。用户撰写的索引正文保留，标记块及JSON不手改。命令只返回 `GENERATED_NOT_QA`，不自动填写贡献、看图结论或科学质量通过。计划、归属、资格、图题、标签、输出字节或质量记录变化后重建；缺文件、漏行、改额度和两处不一致都使结构图/视觉计划门禁失败。

规划审计前用 `--stage plan`；某问图形完成后用 `--stage question --question-id <ID>`；全部渲染完成及TeX审计前用 `--stage render`。逐问账表仍列出其他问题的计划状态，不能把计划图数当成其已完成证据。计数来自原计划，不由生成表的行数倒推。`论文/图表清单.json` 是内部入文清单，不额外创建正文一级章或把内部额度表塞进正式论文。

编译采集实际图形、实际打开论文页面并完成原有视觉审阅后，用 `--stage paper` 重建账表，再运行paper门禁。此时每图实际出现页码、bbox及probe_id来自当前 `paper_review_path`，复用编译闭包和PDF测量验证；不能手填页码，也不能用计划阶段账表替代实际出现记录。审阅记录变化后同步重建，使其哈希与当前版本一致。账表发布仍不替代逐图资产/结构真实性、PDF位置、尺寸、科学信息独立性及人工实际查看门禁。

证据不足时补充真实适用实验，仍无法满足则报告真实阻断，不伪造或自动豁免。独立验证可使用图、表、解析证明或可复核重算；无法获得真值时登记限制与替代证据，不把辅助证据冒充准确率验证。

四问型赛题通常由每问至少4张独立科学图满足全文16张下限，四张主要综合图另计；每问独立科学图上限为6张。其它题数也必须同时核对逐问范围与全文下限，不能重复挂载同一图抵数。布局与图型多样性只根据数据语义选择。

### 7.2 正文证据密度与补页图门禁

视觉计划除检查图数，还要检查图在正文中的分布。模型/机理、主结果、验证、误差、敏感性与边界图应尽量靠近对应问题，不能把图全部集中在前半段，再以全量折表、文件审计或交付说明撑后半段。论文初稿生成后制作逐页联系表；若正文后 1/3 连续出现低信息密度页，优先把真实的设备/场景差异、逐折不确定性、参数可辨识性、残差分层、模型胜负、特征响应或边界证据前移并图形化。

页数不足时，允许新增“解释性证据图”，但必须同时满足：

1. 回答正文尚未可视化的具体科学问题；
2. 只读取已落盘的真实结果，或由新增计算脚本真实生成并登记结果；
3. 与已有 Figure 不同证据、不仅是同一数据换图型；
4. 具有可复核的统计/边界/分组/不确定性含义；
5. 通过 Figure Contract、统计报告、字体和渲染 QA。

适合的补充族包括：参数目标面与 bootstrap 联图、折级森林图/胜负热图、设备×验证口径误差谱、残差随状态/时间分层、特征局部响应、阈值/可行域、模型失效地图和带置信区间的敏感性图。装饰性流程图、无数据三维图、同一数字的饼图/柱图重复、虚构示例曲线以及仅为占版面的“好看图”一律不合格。若题目证据不足以支持更多图，应承认不适用并调整章节，而不是制造视觉填充。

### 7.3 Schematic Plan：机理/几何示意图

Schematic Plan 专门管理不表达计算顺序的数据机理与几何示意，例如轨道/空间几何、坐标旋转、传播路径、相对论几何、采样、分箱、折叠原理和物理作用关系。它与 Flowchart Plan 的边界如下：

- 主要回答“对象、几何或机理如何构成”，没有算法顺序、决策分支或数据流的，使用 Schematic Plan；
- 主要回答“输入如何经过步骤/模型到达输出”，或包含迭代、反馈、验证门、分支的，使用 Flowchart Plan；
- 同一 Figure 同时含机理示意和定量 Panel 时，可使用 `schematic_led` archetype，但示意 Panel 仍必须先通过Schematic Plan及对应算法/物理skill，定量 Panel 仍通过所选定的 `academic-figure-skill` 或 `modelviz-skill`；不得用 skill 自动生成的装饰性 schematic 绕过真实性审查。

每个 Schematic Plan 至少记录：Schematic ID、科学问题、类型、题面/公式/代码/结果来源、真实元素及其关系、可删除元素、可复现可编辑源及后端理由、PDF/PNG、图题、label、正文引用、字体/灰度/版心/裁切状态。示意图按 `结构图工作流.md` 选择Python+draw.io、PlotNeuralNet/TikZ或其他可复现矢量输出；任何元素或关系无法追溯时状态为“未完成”。

## 9. 流程图与模型结构图规范

流程图、总体技术路线图、模型结构图、算法流程图和数据流/模块关系图都属于结构性 Figure。它们不是装饰图，也不是用于增加论文页数的版面填充。只有当图能够增强以下至少一项的表达时才生成：全文技术路线、多问题依赖、输入—模型—输出—验证关系、多层模型结构、算法步骤与迭代、优化/预测/验证反馈闭环、数据/结果/决策流，或系统架构与模块关系。

每问首节“问题的描述与分析”内强制放置1张额外主要综合图，实际PDF不得越过第二个二级标题。图须优先复用本问已有合适结果并落实适用机制，以紧凑对齐矩形形成总览，按结构图工作流内容v2完成审查；允许直接缩小结果图并关联正文详细图，细节不要求逐项可读，自绘导航仍清晰；它不抵扣4–6张科学图或全文16张门槛，但合格流程语义可计入全文至少2张流程图。总体路线另放1.2问题重述。来源、引用、当前结果和实际视觉复核仍须通过。

结构图按 `华为杯_求解规范/结构图工作流.md` 路由：算法内部用 algorithm-mechanism-diagram，物理/科学机理用 engineering-physics-mechanism-diagram，逐问图文综合图用 comprehensive-graphic-text-flowchart；普通流程与总体路线参考 scibox-diagram。后端按科学表达、编辑、公式和实际渲染选择；仅普通流程/总体路线保持draw.io优先。

### 9.1 结构类型选择

结构类型只能由真实题面、数据流和模型结构决定，不得固定套用某一模板，也不得把历史 A/B/C 代码块当成生产模板。可选类型如下：

1. **总体技术路线图**：展示全篇或多个问题的输入、处理、核心模型/算法、输出、独立验证和总体结论；存在多问依赖时按真实问题分行或分组，列数、行数和节点数随题目调整。
2. **分层系统架构图**：仅在数据、特征/状态、模型/算法、约束/校验、结果/决策确有层级或耦合关系时使用；右侧全局验证区只有在存在真实全局校验时才保留。
3. **纵向算法流程图**：用于有真实初始化、计算/更新、收敛或停止判断、输出的顺序算法；循环或反馈箭头必须对应代码、公式或明确停止条件。
4. **双阶段或多阶段协同流程图**：用于粗解—精解、Baseline—改进、预测—优化、候选生成—筛选—Pareto 权衡或多阶段场景；必须标出阶段之间传递的真实变量、目标向量、可行域或风险指标。
5. **输入—模型—输出—验证图**：用于多个数据源进入不同模型、各模型有独立输出和验证指标、最后再汇总的结构；行列按实际问题和功能调整。
6. **数据流或模块关系图**：用于复杂数据处理、网络/图结构或具有真实依赖的系统组件；每个分组框、模块框和验证节点都必须能追溯到题面、代码、公式或结果。

### 9.2 节点、箭头和真实性

- 在绘图前先回答：图要解释的科学问题、图型、输入、中间模型/计算、输出、验证条件、循环/分支、每个节点来源、每条箭头传递的信息、可删除节点以及是否应拆图。
- 每个节点必须对应真实存在的题面数据、处理步骤、特征/变量、数学模型、算法、参数、约束、中间结果、输出结果、验证指标、决策或场景。节点文字使用具体名称，优先写“清洗后的时序数据”“特征矩阵”“参数估计值”“候选解集合”“可行解”“预测结果”“残差指标”“Pareto 解集”“独立验证结果”等；避免“信息输入”“数据处理”“模型计算”“结果输出”“信息传递”等空泛标签。
- 每条箭头必须对应真实的数据/变量传递、模型依赖、计算顺序、约束关系、反馈关系或验证关系；箭头方向与实际数据流和求解顺序一致，箭头文字写明传递的变量或关系。
- 禁止凭空增加不存在的模型、数据、验证条件、优化阶段、反馈循环、“智能决策层”或“系统平台层”，也禁止为了美观保留不影响逻辑的重复节点。反馈箭头只有在真实迭代、修正或回传存在时才使用，并采用虚线或其它明确线型标识含义。
- 节点过多时，优先按层级、问题、输入/模型/输出/验证分组，或拆成总体路线图与局部算法图、多面板 Figure；不得通过缩小字体、堆叠节点或增加装饰性框体掩盖结构复杂性。

### 9.3 BrightTech-Info 在流程图中的语义

- 画布使用白色或极浅灰背景；数据、模型、约束、验证、输出等语义层可使用可区分的离散色，并在 `求解/视觉编码表.md` 固化实际取值。BrightTech-Info 仅在不牺牲可读性时提供可选色义。
- 同一语义层或同类节点复用同一颜色；验证门可使用统一强调色；关键节点可用 `Highlight`，但颜色不得成为唯一层级编码，必要时同时使用边框、虚线分组、节点形状、线型、位置和文字标签。
- 节点可适度透明，但文字和边框必须清晰；箭头使用深色或中高对比度颜色，不使用大面积渐变、发光、厚重阴影、纹理、立体按钮或装饰性 3D。渐变只在表达连续状态、连续阶段或连续数值时使用。
- 灰度打印和论文缩放后仍应识别主要层级、箭头方向和验证门；流程图应轻量、清晰、适合版心，不能做成商业海报。

### 9.4 结构实现与质量门禁

完整协议唯一见 [结构图工作流](结构图工作流.md)，对应三份skill管理参考选择、科学语义、布局和后端；scibox-diagram提供普通流程模板及通用配色、字宽和预检。综合图的科学关系/论文可读性、本图库布局、scibox风格、固定模板依次优先，固定三栏五带不能约束新图文布局。

每张结构图均须真实来源及连接解释、参考候选实际查看、可复现源、矢量PDF、PNG、整体/局部/等尺寸PDF/灰度实际查看。draw.io使用严格预检，允许精确登记的同对象无字表面叠层和真实位图，不能关闭全局检查；文字碰撞、关键结构遮挡和越界仍须修复。脚本执行成功或自动待审记录不能替代看图，只有人工填写实际复核及当前输入哈希才能标记qa_pass。

规划时初始化逐问主要综合图；计算与验证完成后生成正式结果并合成，优先在各问问题描述与分析之后、详细建模之前展示。模型或结果变化后重绘受影响图并重新看图；逐问与final审计核查来源、归属、引用、当前结果一致性及视觉记录。任一失败不得进入论文。

## 13. 与 LaTeX 论文流程的衔接

论文规范只负责图像路径、宽度、图题、标签、正文引用、PDF 缩放可读性和裁切检查。图像视觉风格、图型选择、颜色、透明度、三维/柱状/饼图限制和 Figure Plan 均以本文件为准。

正式链路为：

```text
真实结果/已审计机理与模型结构 → Figure/Schematic/Flowchart Plan
→ 普通科学结果图：双来源预检与选型 → academic或modelviz对应证据（实际渲染、对照/统计/QA）
→ 原始素材/专业渲染：media证据（元数据/真实处理/来源对照/实际复核；地理内容叠加地图合规）
→ 算法/物理/综合结构图：专用skill + 结构图工作流（可编辑源/矢量PDF/实际复核）
→ 普通流程/总体路线：Flowchart Plan + scibox-diagram，draw.io优先
→ 渲染/质量检查
→ 求解/问题X/图片/ → LaTeX \includegraphics
→ XeLaTeX PDF → 论文视觉与页数验收
```

在普通图全部渲染后运行 `--stage render`；在论文 TeX 组合并通过 audit_tex 后，运行 collect_academic_paper_review.py 双遍编译并采集实际入文路径/宽度/页码，打开页面填写待审记录后再运行 `--stage paper --main-tex 论文/论文.tex`，核对计划 label、正式图、正文引用及编译证据。任一阶段失败都返回上游修复，不能以正文达到 35 页代替视觉门禁。

不得在论文阶段重新生成与求解结果不一致的图片，不得修改官方 `gmcmthesis.cls`、`gmcm-title.sty`、`gmcm.bst` 或 `figures/` 资源来迁就绘图。

## 14. 持续候选发现、七维门禁与待选图库

在求解过程中持续发现候选，不等最后集中想图。每完成具有科学意义的数据处理、特征构建、模型训练、优化求解或验证阶段，以及关键方法/结果变化后，逐项检查：

|角度|要回答的问题|
|---|---|
|数据结构|数据如何分布，是否存在分组、相关、异常或时空规律？|
|处理效果|处理前后改变了什么，是否丢失重要信息？|
|中间机制|特征、状态、参数或中间解揭示了什么？|
|求解过程|是否收敛，路径如何变化，约束何时起作用？|
|最终结果|效果、分布、结构和实际意义是什么？|
|比较验证|相比基线改善在哪里，独立验证是否支持？|
|误差边界|哪里失败，对哪些条件敏感，是否出现反例？|

检查对象是阶段成果，不是每行代码。题型风险检查与阶段七维检查叠加，允许混合/新增题型，具体风险与命令接口见[候选图工作流](候选图工作流.md)。阶段清单从实际算法/代码制定，不能从已画图倒推。每阶段同时检查两个skill是否支持有价值的新表达，不因正文图数已够省略。每项关联阶段ID、科学问题、当前证据及哈希、判断、理由、候选ID和后续动作；区分已有图覆盖、需要新增图、需要先补分析、表格/文字更合适、不适用、真实阻断。N/A须有具体依据。不能用批量默认答案、图数足够或页面已满省略有价值的候选。

适用且有信息价值的视角先生成候选再决定入文；已有结果直接读取落盘数据，缺分析则先真实计算。多个表达确有不同分析价值时可生成备选，不穷举、不重复换皮；同一图可覆盖多个角度，不要求每阶段七图。输入/方法/结果变化后旧证据失效，原样证据可带理由引用有效检查。尚无结果则登记后续节点，不虚构结论，不使用测试集或漂亮投影反复调参；保留负结果、混杂与失败。

无依赖的数值探索和正式计算可继续，检查不成为全局计算锁；每问标记完成前须完成七维检查并落实承诺图，关键阻断不能靠填理由消除。逐问完成和最终交付重新对照题面、实际源码、中间结果及论文主张，查找缺分析和缺图，不能只看候选清单。自动审计验证记录覆盖/文件关系，不能证明科学分析绝无遗漏或模型真正看懂图。

**同等质量硬要求**：待选图库所有普通科研图完整执行双来源预检及所选来源门禁；academic保留全图库实际浏览、候选原图/生产源码精读、五项映射，modelviz保留完整目录预览及选中模板源码/适配、真实运行、参考适配、矢量PDF和300dpi PNG、参考—成图对照、PNG/PDF页面/灰度实际查看和三项结论、plan/render门禁。不得降级为草图；无同型模板使用有依据的cross_type_inherit，不受现有图族名称限制。流程图与机理示意图保持第9章及Schematic专门后端，不强行改为普通图路径。候选按预计论文物理尺寸复核，真正入文后再检查TeX引用/尺寸/页码，不转移旧PASS。

清单采用独立schema，视觉计划v1.2兼容旧v1.0/v1.1读取，academic资产保持v2。质量状态（待生成/待复核/合格/失败/过期）与使用去向（正文/补充/待选/淘汰）独立。候选保持稳定ID及唯一权威数据、源码和成品；正文选择生成派生计划。workshop内 `待选图库/图片/逐问目录/` 保存真实PNG及适用原始导出的可重建展示副本，`展示副本.json`记录来源和哈希，不维护可独立修改的事实副本。源图更新刷新副本，过期或淘汰图移出当前合格展示。`index.html` 默认显示全部合格reserve和supplement，正文图单独查看，提供缩略图、大图、结论限制、统计单位、推荐章节、未入文理由及源图/证据链接；其他质量状态只显示中文状态。零剩余时显示数量、逐问取舍和复查结论，新工作区完成审计要求completion_review.zero_remaining_reason及当前复查证据，不能用空白页面或统一套话代替。

候选与补充图不计每问4–6张科学图、额外主要综合图、全文至少16张合格图或至少2张流程图；35页门禁不变。待选图库面向用户，不整库进入提交包；补充图按gmcm-supporting-materials明确选择与追溯。没有赛题仅在隔离DEMO验证，不创建虚假正式证据。新项目自动启用；旧项目兼容不等于完成新门禁，迁移时保留历史审计并如实说明未记录的历史范围。

原始素材与专业渲染候选执行第1.3–1.4节同等质量检查，替换的仅是academic资产继承要求；七维发现、科学来源、真实处理、实际查看、失效更新和选入审计保持。计数和补充材料资格不由扩展名决定。

## 15. 地理图件与中国版图合规

适用于原始图片、视频截图、专业地图、栅格、结构图或混合面板中实际出现的地理内容；不能通过声明native_media或只画局部绕过。科学真实性、适用法律及版图准确性优先于美观。本节为项目规则，法定适用性须按实际用途、范围、比例尺、数据类型和当时有效官方文件核验。

### 15.1 官方依据与适用范围

2026-09-09实际核读的基线：自然资规〔2023〕2号《公开地图内容表示规范》（自然资源部2023-02-06发布，[官方全文](https://www.fmprc.gov.cn/web/wjb_673085/zzjg_673183/bjhysws_674671/bhflfg/dtdmxgfl/202303/P020230313585504979937.pdf)），第2条为公开地图/附着地图图形产品的适用范围，第3–9条为边界及重点地区，第19–22条为精度和内容要求。[国家标准平台](https://std.samr.gov.cn/gb/search/gbDetailed?id=71F772D8237CD3A7E05397BE0A0AB82A)列GB/T 35764-2017为现行，并列修订计划；未发布的计划不能当成已生效标准。[新疆自然资源厅登载使用指南](https://zrzyt.xinjiang.gov.cn/xjgtzy/tzgg/202011/c0e1f60f85774e1c80f6ba9306ef678f.shtml)说明内部用图核查、公开使用审核与标准地图改动的区别。不同年代地方指南的缩放表述不得外推成全国通用豁免。

每个实际项目重新核对官方现行性，在map_review.official_sources记录URL、标题、版本、checked_date、具体条款、适用性、实际阅读观察；本段基线不是未来项目自动通过证据。旧转载页面的失效标签、修订草案和现行正文可能不同，遇冲突查主管部门原件并记录。法规要求与项目更严格规则分开登记，不用自检替代主管部门审核。

### 15.2 底图、边界与专题表达

- 优先使用自然资源主管部门标准地图服务提供、保留真实审图号的标准图。其他矢量边界须有可靠出处、版本和对照核验材料。禁止直接将未经核验的Natural Earth、国外在线地图等作为中国国界来源；GeoPandas/matplotlib是工具，其名称不证明数据合规。
- 完整继承核验底图的国界、南海断续线及东海有关线段，不凭固定段数自行补画，不擅改地理含义。正确投影转换可改变图面坐标，但不得移动地理位置或手工按外方主张线重绘。专题层不得遮盖关键边界、岛屿、必要地名和审图号；绘制顺序与避让须实际检查。
- 中国全图的主图与附图共同核验四至和完整性，南至曾母暗沙以南；核验南海诸岛、台湾及钓鱼岛/赤尾屿、藏南/阿克赛钦等关键部位。南海附图、海南省图、台湾省图及局部图的要求依据适用条款和图名判断，不能把台湾岛图与台湾省全图混用。项目默认完整保留所选合规全国底图的重要要素，较法规例外更严格的选择记入project_stricter_rules。
- 台湾按适用规范的省级单位和省级行政中心口径表达；专题数据与大陆使用相同变量、分级规则和图例，按真实值着色，禁止为同色修改值。缺失用明确缺失编码并注明“台湾省资料暂缺”，不能填零或推测。港澳适用条款一并核查。
- 局部省市/流域图按研究所需范围表达，不为装饰加全国图；裁切不得引入错误边界或伪装完整全国轮廓。局部图不因缺全国轮廓自动免审。

### 15.3 配准、精度与公开状态

显式声明源/目标CRS、投影、转换和单位，从可信元数据核对而非只填EPSG。JPG/EPS标准地图不默认携带地理参考；须有可靠配准、控制点或投影依据及误差证据，不能拉伸到大致重合，不能擅自标CGCS2000。核对轴序、经纬度/米、NoData及分类/连续量重采样。

2023规范第19条的原文限定为平面精度不优于10米（不含）、高程精度不优于15米（不含）、等高距不小于20米（不含）；依法公布的高程点有单独规定。第22条对境内公开遥感影像规定地面分辨率不得优于0.5米，并限制涉密敏感信息和固定设施伪装处理。应用时保留“不含”等边界并核对现行条款，不把位置精度、像元大小、输出DPI混为一谈。不得因此自动降低合法原始科研数据或内部计算精度；降低分辨率不等于其他要求全部满足。第20–21条禁止/限制内容及其例外需按具体图件检查，不能复制泛化口号代替核验。

分别记录内部科学核验、实际人工/模型看图核验、法定审核状态。legal_review.status为required_pending/approved/not_required，附依据；approved须有最终成果审批证据和审图号。原标准底图审图号仅证明原底图，不能代表裁切/叠加后的成果已经获审。实际拟公开使用且需审核未完成时，public_ready不得为true，不得作为可公开最终版；内部图可继续研究但保留待审核状态。竞赛提交是否属于需审用途依据实际提交/公开规则判断，不自动假定。无需审核也须明确依据，不能用人工通过替代法定结论。

### 15.4 逐图检查

map_review记录scope、intended_use、是否表示中国国界、底图、official_sources、evidence、registration、legal_review、public_ready及checks。固定检查项见工具MAP_CHECKS，覆盖来源、边界、南海、台湾、钓鱼岛/赤尾屿、西部国界、四至、遮挡、CRS、来源审图号、精度、敏感内容、比例尺、方向、坐标网和图例。每项使用pass/fail/not_applicable/pending（通过/失败/不适用/待核验），附具体理由及当前证据路径；不适用不能省略原因。图件不适用全国要素时据范围登记，而非机械判缺失。

检查真实来源、底图—成图对照、当前哈希与坐标依据；实际打开全图、关键局部、灰度、拟入文页面。不自动填勾、不自动填审阅观察。失败或待核验项阻断相应图件完成；必要法定审核仅阻断相应公开用途，不阻止无依赖内部数值计算。

受控 chart_family_map 按实际参考图编码维护，而非由模板名称猜测；同构曲线上的标记不额外算散点。复合模板保留的所有编码均登记 chart_families；明确去掉某类子图时，逐项填写 omitted_chart_families 的当前科学/版面原因，由实际图像复核确认，不能静默漏计。
