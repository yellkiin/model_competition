# 模型选择与竞赛协议

本文件是数据驱动问题的模型选择唯一详细规则，供 `华为杯_求解规范.md`、Codex/Claude 总控和 `求解/求解计划.md` 引用。它不替代题面约束、数据审计、验证规范和论文规范；冲突时按项目既有优先级处理。

## 1. 四级模型竞赛

每个适用的数据驱动子问题按实际可行性组织候选：

1. 经典/统计或机理 Baseline；
2. 一至两个有意义的传统机器学习候选；
3. 通过深度学习适用性门控后的轻量 DL Pilot；
4. 只有前述结果显示存在明确收益时才进入 Improved Model。

必须先完成低复杂度基线和公平比较，再决定是否升级主模型。DL 获得参赛资格不等于必须成为 Main Model。

## 2. Deep Learning Eligibility Gate

在最终确定候选模型前，为每个可能使用数据驱动方法的问题填写以下判断：任务类型、数据模态、样本规模、特征维度、标签充分性、数据质量、非线性程度、时间/空间/局部/高维结构、合理网络架构、相对传统方法的理论潜在优势、可用计算资源和赛题时间预算。

判定为：

- **A 适合**：必须真实训练并验证至少一个轻量 DL 候选；
- **B 可尝试但优势不确定**：与A类一样必须真实执行低成本 Pilot，不是可静默跳过的建议；
- **C 明显不适合**：允许不训练，但必须记录样本/结构/标签/机理/成本等具体理由，不能只写“传统模型更好”。

GTX 1650 性能不足、没有 CUDA 或已有传统模型表现较好，单独不能构成 A/B 问题跳过 Pilot 的理由。应先降低模型规模、输入尺寸、Batch、Epoch 或搜索范围，必要时使用冻结迁移学习或 CPU fallback。

## 3. 轻量模型族映射

不得指定万能网络，按数据模态选择最小合理模型：

| 数据模态/任务 | 传统候选 | 轻量 DL 候选 |
|---|---|---|
| 普通表格 | 线性/Ridge/Lasso、RF、SVM、Boosting | 小型 MLP |
| 时间序列 | ARIMA/SARIMA/ETS、滞后特征+Boosting | TCN、GRU；必要时 LSTM/1D-CNN |
| 一维信号 | FFT/小波、时频特征、SVM/RF/Boosting | 1D-CNN、TCN |
| 图像分类 | 传统图像特征与简单分类器 | MobileNetV3、ResNet18、EfficientNet 小型号，优先迁移学习 |
| 图像分割 | 传统分割基线 | 轻量 U-Net |
| 目标检测 | 传统检测基线 | Nano/Tiny 级检测器 |
| 图结构 | 结构统计、传统图算法/ML | 2–3 层 GCN 或小型 GraphSAGE |
| 异常检测/降维 | PCA、Isolation Forest、One-Class SVM | 小型 AutoEncoder |
| 机理/ODE/PDE | 解析、数值、参数辨识、优化 | 残差修正、参数拟合、代理模型或小型 PINN（仅有依据时） |

Transformer、大型 CNN/GNN、强化学习、视频模型、大规模 Neural ODE/PINN 和大范围超参搜索不得作为 GTX 1650 下的默认候选。确需使用时必须记录运行可行性、必要性和轻量替代方案评估。

## 4. Pilot 与硬件约束

Pilot 采用小模型、合理默认参数、少量 Epoch、Early Stopping、小范围调参和固定随机种子；记录设备、显存、参数量、输入尺寸、Batch、训练时间、最优 Epoch、指标和日志。CUDA 不可用时可在 CPU 完成轻量 Pilot，但不得更换数据或评价口径。

默认规划上限为GTX 1650常见4GB显存（4096MB），不因检测到更强设备自动扩大模型。显存包括输入、中间激活、梯度、优化器状态，参数量不能替代实测峰值。先用少量batch计时/测内存估算总成本，再选择epoch、batch、hidden dimension及搜索次数；最大试验次数与秒数先登记，超过预算必须有实测依据并更新理由。没有CUDA保留CPU fallback事实；不要把CPU显存0写成进程内存0。

A/B不能仅以“硬件弱”改判C。若真实尝试仍因OOM、异常或不可接受成本终止，保留失败收据、轻量化重试、CPU成本评估和最终决定，报告为“未取得有效DL验证”，不能写DL性能较差或Pilot成功。题面禁止学习方法时直接按硬约束登记C，不运行违规候选。几十/几百条数据不是自动C阈值，需结合独立样本数、维度、噪声与可用先验判断。

Pilot 结果只回答“是否值得继续竞争”：明显落后可停止复杂训练；接近或超过传统 ML 才进入有限调优；明显胜出才可升级 Main Model。

## 5. 公平比较与选择

候选模型尽可能使用同一训练/验证/测试划分、同一评价指标和同一泄漏约束。时间序列使用 chronological/rolling split，分组数据使用 Group Split，空间数据使用 spatial block；预处理和调参只能在训练折拟合。

选择同时考虑预测/分类性能、稳定性、鲁棒性、训练与推理成本、参数规模、可解释性和建模合理性。性能差异很小时优先稳定、简洁、可解释的方案。DL 没有获胜也必须保留为有效竞争实验。

选模只能用验证集或内层交叉验证；封存测试集在方案锁定后仅做最终评价，不用测试榜反复挑冠军。统一split文件列样本ID，分组/空间任务登记group/block，时序登记时间戳；切窗先按原始设备/序列分组。小成本pilot允许训练子集，但与使用更多训练数据的正式模型不能直接排名，须在统一数据预算重跑或明确分开报告。模型参数/标准化/特征选择仅在训练折拟合；预训练来源、冻结范围、数据增强与外部数据另行披露。

预先登记主指标方向、实际有意义差异和重复试验策略。接近时考虑波动而不是按0.1%提升追逐复杂度。选择理由必须解释精度、稳定性、鲁棒性、推理成本和可解释性；未执行的分析写明限制。DL明显胜出可成为Main，之后按问题需要做消融、敏感性、鲁棒性和可解释性。改进模型须绑定已比较的基模型及不足，不允许先改进后补写基线。

## 6. 机理残差路线

存在明确机理时，可比较 `机理模型`、`ML/DL`、`机理+ML残差` 和 `机理+DL残差`。组合模型必须有真实结果和独立验证，不得为了制造创新点强行组合。

残差目标为训练范围内的y−f_mechanism(x)。若机理参数也从数据估计，比较与验证必须封存对应验证/测试标签，必要时用训练折外预测构造残差，避免用全样本拟合机理后泄漏到验证。图网络只用于有科学依据的真实关系，禁止任意连边包装GNN；PINN必须有可验证物理约束，不强行使用。

## 7. 统一记录

每问在现有`求解/支撑材料清单.json`的question条目增加`model_selection`，指向`求解/问题X/结果/model_selection_report.json`（[Schema](模型选择报告.schema.json)）。这是每问模型选择的唯一结构化记录，不另建全局模型注册表；计划写动机，结果索引由工具生成链接，论文读取派生TeX。纯理论/优化题也登记applicable=false、C及题面证据，不强制训练ML/DL。

报告记录门控12项、理由、候选家族、配置/收据引用、选用运行、失败原因→轻量化重试→决定、预算、主指标、Main/Improved及取舍。所有运行采用新的run_id，`求解/实验运行/问题ID/运行ID/receipt.json`不可覆盖；源码、配置、数据、split和所有输出绑定当前哈希。未登记的成功或失败运行也会使审计失败，防止只保留冠军。报告的review文字须实际审阅后填写，机器不能证明科学判断真实。

## 8. 执行、生成与门禁接口

以下参数均以workspace_root为基准，通过既有共享包装器执行：

```powershell
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --tool 华为杯_求解规范/tools/model_selection.py -- run --config 求解/问题一/实验配置.json --timeout 600
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --tool 华为杯_求解规范/tools/model_selection.py -- audit --stage question --question-id q1
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --tool 华为杯_求解规范/tools/model_selection.py -- publish
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --tool 华为杯_求解规范/tools/model_selection.py -- audit --stage paper
```

配置字段：run_id/question_id/candidate_id、inputs、sources、split、selection_partition=validation、commands（train随后validate，各自argv数组，以`{python}`开始）、outputs、metrics；DL另含training_record、checkpoint。argv的脚本必须在sources内。数据与代码不允许来自既有提交副本；所有预期输出本次运行前不存在。配置可包含题目特定参数，训练和验证脚本必须实际消费同一split。验证指标JSON含metrics字典、evaluated_ids、split_sha256、independence、leakage_review；独立验证器重新读取原始真值和预测结果计算指标，不能抄训练日志。

DL training_record包含seed、parameters、input_shape、batch_size、epochs、best_epoch、early_stopping、device、peak_memory_mb（GPU分配显存）、elapsed_seconds，并保存训练history及最佳checkpoint。完整实验参数和框架版本随配置/环境说明保存。其他任务的独立验证器根据真实指标实现，不强制套DEMO回归公式。

`audit --stage plan`核查待执行门控及证据；`question`核查已运行候选、同源数据划分、指标、失败记录与主模型；`publish`仅在数值证据通过后生成`求解/模型比较/q1.csv`、`论文/章节内容/q1_模型比较.generated.tex`与结果索引标记块；`paper/final`重查当前源并拒绝漏引、过期或手改的比较片段。所有问题必须在支撑材料清单登记。初始化清单只填报告路径，不伪造通过状态。

论文问题章在合适位置恰好包含一次`\input{章节内容/q1_模型比较.generated.tex}`。片段包含候选动机、统一条件、指标、成本、复杂度与选择理由，失败无有效指标时不填数。两项主指标进精简表，其余指标同源输出；完整CSV保留所有指标。正文仍须解释变量、假设、机理、方法和结果，不让自动比较代替问题分析。

支撑材料构建与逐问/final审计调用同一门禁；build_latex自动刷新片段，paper_contract供生成器与TeX审计共同检查。保留全部候选训练/验证源码及必要配置、依赖和模型产物，完整CSV登记本问补充表。内部报告和日志留在验收目录，不复制到公开包；公开包的独立复现必须重现所有已用于比较的候选结果。原有图数、摘要、引用、附录、页面和正式finish门禁不豁免。

## 9. DEMO边界

需要自动选择时，使用`model_selection.py select --config 求解/问题一/结果/model_selection_report.json`：按metrics第一项方向排序，selection_tolerance内优先较简单家族。该规则只生成有依据的默认选择；若成本、稳健性或解释性支持非最低误差模型，必须填写selection_override_reason。该动作也重新执行证据审计，不读取封存测试集；之后再次publish。Improved候选填写base_candidate及improvement_reason，时间顺序必须在基模型完成验证之后。

`run_model_selection_demo.py`只接受purpose=demo的共享工作区，真实训练Ridge、Random Forest和小型PyTorch MLP并由独立脚本复算RMSE/MAE。负例夹具与真实运行结果明确区分，不预设DL胜负；DEMO可验证接口、拒绝条件、TeX和公开包复现，不证明赛题适用性或GTX 1650速度，也不授予整篇论文通过。
