# 工作流部署

新运行默认共享模板，详细目录与路径合同见[工作区工作流](工作区工作流.md)。deploy_candidate_workflow.py 与 sync_supporting_skill.py 共用模式明确的部署接口。

## shared：新建与续跑

```powershell
python -B 华为杯_求解规范/tools/deploy_candidate_workflow.py --root . --mode shared --runtime codex --input 题目/本次题目.pdf --input 数据/本次附件.zip
python -B 华为杯_求解规范/tools/deploy_candidate_workflow.py --root . --mode shared --runtime codex --project workshop_v1
```

输入须真实存在且由本次任务明确选定。未传 --project 时分配下一 workshop_vN；传入时仅恢复该工作区并核对模板/运行时关联，不猜最大编号、不复制共享目录、不更新原始输入。日志与科学产物位于工作区，不写回外层 output。共享资源漂移报告失败，不刷新哈希掩盖失效验收。

sync_supporting_skill.py --template-root . --mode shared --runtime codex 同样创建共享工作区；--project-root 指定已有工作区时仅检查关联。共享模式不接受 mirrors-only。

## maintenance：模板自身两端同步

```powershell
python -B 华为杯_求解规范/tools/deploy_candidate_workflow.py --root . --mode maintenance --mirrors-only
```

仅在用户要求维护模板时执行，按部署工具的既有镜像清单同步并保留维护备份。modelviz 不在跨端镜像清单：分别从 `.agents/skills/` 与 `.claude/skills/` 递归解析 front matter 的 `name: modelviz-skill`，保留两端各自的真实目录，本模板当前均为 `modelviz-skill-main`。缺失、歧义、跨端链接必须报错，不能用 Codex 副本覆盖或补造 Claude 副本。不得在论文运行中使用此模式，不自动同步历史活动项目。镜像维护不允许解题时跨端回退。

双来源预检、modelviz 执行和 QA 的资源依赖包含同端 skill 版本及共享桥接/schema。明确采用新资源后必须重新检查受影响的选择、运行和视觉证据；采用资源不自动刷新这些证据。完整 legacy 部署分别复制每端实际发现的 modelviz 目录，`mirrors-only` 仅验证其存在和身份。

## legacy：旧独立项目维护

```powershell
python -B 华为杯_求解规范/tools/deploy_candidate_workflow.py --root . --mode legacy --project <用户明确指定的旧独立项目>
```

只有用户明确要求更新旧独立项目时才完整复制维护工具、规范和两端 skill，前后核对科学数据与论文不变。禁止对 workshop_vN 或存在工作区清单的目标执行完整复制；不导入模板历史成果，不补造旧项目阶段和审核记录。

legacy 和 maintenance 是模板维护任务，保留原维护备份链，不适用于新论文运行。部署通过仅证明安装或关联，不代替求解、独立复现、图件和实际 PDF 验收。
