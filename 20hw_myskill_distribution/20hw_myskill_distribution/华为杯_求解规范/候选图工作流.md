# 持续候选发现工作流

共享运行的命令变量 `$templateRoot`、`$workspaceRoot`、`$runtime`、`$python` 按模板 `华为杯_求解规范/工作区工作流.md` 的“命令变量”设置。工具从共享模板读取，子进程 cwd 为工作区；本题路径相对工作区，skill 内部引用相对本 SKILL.md。

共享运行按[工作区工作流](工作区工作流.md)先初始化 workshop；本文命令的工具从 template_root 读取，科学输入与输出相对 workspace_root，使用 workshop.py run 调用。直接命令仅作为 legacy 模式或子工具参数参考。

候选按绘图规范第1.3–1.4节逐面板分流。普通统计图按来源要求完整academic资产或modelviz模板证据；原始素材/专业渲染使用同stem的media证据，候选figure/registry/gallery/select-paper及补充打包统一调用分类门禁。混合图同时通过各面板路径，不因输入扩展名放宽。原生位图以outputs.primary登记；illustration不抵扣科学图数量。候选质量、使用去向与是否可公开发布分别核验，地图适用性见绘图规范第15节。

本文件是候选清单的操作接口；科学取舍与质量规则由《华为杯_绘图规范》第14节维护。新项目启用，旧项目缺少清单时不得虚构历史阶段事件。升级已有项目须从当前工作节点真实登记，并在最终复查中说明此前未记录的范围。

## 生命周期

计算计划先登记每问 `problem_types`（可多选并可自定义）、`type_reason`、逐题型 `type_reviews` 与 `expected_stages`。阶段清单依据实际代码/算法阶段制定，变更时追加；不能仅凭候选图列表倒推阶段。

```powershell
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --tool 华为杯_求解规范/tools/candidate_figures.py -- init --question-id q1 --question-id q2
# 填写求解/候选图清单.json的问题类型、题型风险和预期阶段后：

& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --tool 华为杯_求解规范/tools/candidate_figures.py -- start --question-id q1 --stage-id q1_data --kind data_processing --evidence 求解/问题一/问题一.py
# 真正运行计算，再登记输出。命令仅记录，不替代计算。
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --tool 华为杯_求解规范/tools/candidate_figures.py -- complete --stage-id q1_data --evidence 求解/问题一/结果/统计.json
# 根据实际观察填写本阶段七维checks后：
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --tool 华为杯_求解规范/tools/candidate_figures.py -- review --stage-id q1_data
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --tool 华为杯_求解规范/tools/candidate_figures.py -- audit --runtime $runtime --stage progress --report 求解/验收输出/候选.progress.json
```

检查表的 `evidence` 是项目相对路径到当前SHA-256的映射，不允许空证据，N/A也应关联阶段方法/输入/结果以说明限制。`reuse` 可引用已有阶段的dimension与checks_digest，仍须写本次判断并验证原记录及证据有效。方法或结果变化创建新stage_id、kind=method_result_change；旧事件保留，不改写历史为已执行。

候选条目用 `candidate_figures.py register --record <手工填写的候选条目.json>` 登记，工具追加真实发现事件，并只初始化为planned/reserve，不自动批准。完成复查的scopes应覆盖实际科学源码和结果目录，files为重新枚举后的哈希库存；新增文件也需要复查。用 `candidate_figures.inventory(root, scopes)` 计算库存，不由脚本生成观察结论。

修订阶段使用 `start --kind method_result_change --supersedes <旧stage_id>`，旧事件与检查保留为历史，受影响候选自动过期；新阶段必须重新完成七维复核。同一科学问题的候选使用 `revise-candidate --figure-id <原ID> --stage-id <新stage_id>` 沿用ID并回到待复核状态，不转移旧PASS；改变科学问题应登记新ID。正文仍选用已过期图时审计会失败。

`new_analysis` 不能仅把resolved改为true就通过完成门禁；真正补算后更新为covered/new_figure/text_table等已落实判断，关联实际新证据并重新登记review事件。blocked同样不能靠状态标记消除。

`progress` 报告未落实事项但不阻止独立数值任务。`question` 要求本问所有expected_stages完成并审阅，承诺的图通过渲染复核，无关键阻断；完成复查须对照实际代码/结果清单，不能只数记录。`final` 还要求全文主张/代码/结果复查与正文选图精确匹配。JSON、哈希及事件链可被编辑，无法证明认知、时间真实性或绝无科学遗漏；它们只检查一致性和当前性。

## 图形计划和质量

视觉计划使用v1.1并兼容v1.0，其同名.assets.json继续使用academic v2。候选可以独立plan/render审计，不要求其他候选已准备好，也不套正文图数下限；完整正文审计仍执行原门禁。科学数据、图片、脚本保持唯一权威源；图库在图片/逐问目录保存可重建展示副本，展示副本.json记录来源及哈希，不允许独立修改副本。

```powershell
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --tool 华为杯_求解规范/tools/candidate_figures.py -- figure --runtime $runtime --plan 求解/候选计划.json --figure-id q1_F01 --stage plan --report 求解/验收输出/q1_F01.plan.json
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --tool 华为杯_求解规范/tools/run_academic_figure.py -- --runtime $runtime --plan 求解/候选计划.json --figure-id q1_F01 -- 绘图参数
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --tool 华为杯_求解规范/tools/prepare_academic_figure_qa.py -- --runtime $runtime --plan 求解/候选计划.json --figure-id q1_F01
# 实际打开参考对照、PNG、PDF页面、灰度并填写三项结论后：
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --tool 华为杯_求解规范/tools/candidate_figures.py -- figure --runtime $runtime --plan 求解/候选计划.json --figure-id q1_F01 --stage render --report 求解/验收输出/q1_F01.render.json
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --tool 华为杯_求解规范/tools/candidate_figures.py -- gallery --runtime $runtime
```

清单quality与destination分开。只有实际通过render的图可标qualified；编译/实验成功不自动授予质量状态。合格reserve和supplement进入默认缩略图总览，正文图单独折叠展示；未生成、失败、过期和淘汰项只显示中文状态。学术意义、统计单位、结论限制、推荐章节和未入文理由应完整，图数足够不是拒绝生成理由。新增候选先登记再生成，不回填不存在的运行或查看。零剩余时逐问填写completion_review.zero_remaining_reason和实际复查证据，不设剩余图配额。

## 正文与材料

入文选图从规范候选计划生成正文计划；沿用ID和文件路径，引用同一数据和源码，正文修改后重建派生计划。候选资格只证明plan/render；实际TeX路径、尺寸、caption/label/ref和页面须另过paper门禁。预计版心取真实模板尺寸；改变尺寸、输入、源码或样式使对应证据过期。

待选图库供用户审阅，不进入竞赛提交包。只有清单中选为supplement的合格图才可登记支撑材料；按gmcm-supporting-materials取舍。论文正文数量、流程图、页数要求不变，候选图及补充材料不得冲抵正文数量。

新清单项目的支撑构建与审计显式传入 --runtime codex（Claude对应claude），保留材料取舍和七维覆盖门禁。无候选清单的旧项目兼容不表示完成新机制。新建workshop只注册共享关联，不自动更新历史活动项目；用户明确要求维护旧独立项目时才使用 --mode legacy，不补造历史记录。

## 题型复查提示

以下是可扩展的检查角度，不是强制图型。一个问题可同时触发多行；无法适用须关联真实依据，不能统一填写N/A。

|题型|最容易遗漏的证据|
|---|---|
|分类与识别|特征结构、类别混杂、阈值/校准、少数类、错误样本、学习过程|
|回归与拟合|预测—真实关系、残差、异方差、分组偏差、区间覆盖、外推|
|时间序列|趋势/周期、残差自相关、滚动验证、步长误差、突变、不确定性|
|聚类/降维/异常|变换前后、簇内差异、参数/种子稳定、异常阈值、投影失真|
|评价/排序/决策|指标贡献、权重扰动、排名逆转、权衡、冗余、情景稳定|
|连续/组合/多目标优化|收敛、可行性、约束松弛、Pareto、初值/种子、资源边界、解结构|
|调度/路径/选址/网络|时空安排、资源冲突、瓶颈、覆盖、公平、负载、重规划|
|机理/动力/控制|状态/相空间、平衡/稳定区、参数响应、控制量、守恒误差、边界|
|估计/反问题/辨识|可辨识性、目标函数形态、参数耦合、不确定性、重建误差、噪声|
|仿真/随机/排队/可靠性|分布尾部、等待/拥堵、失效、仿真收敛、重复区间、极端情景|
|空间/时空/几何/场|采样覆盖、空间残差、局部误差、剖面、边界、时空演变|
|信号/图像/检测|原始—处理对照、频谱/时频、失真、局部细节、尺度/噪声|
|推断/实验设计/因果|效应区间、异质性、假设诊断、设计覆盖、混杂与识别边界|
|迁移/跨域/漂移|条件类别结构、负迁移、工况、目标支持范围、无标签验证边界|
|理论/解析|参数区域、几何、极限、数值核验；图不替代证明|

预测解释不能冒充因果证据；无标签嵌入和距离下降不能冒充准确率；参考与DEMO数据不能成为赛题结果。


## 双绘图来源接入

普通科研结果图平等检查 academic-figure-skill 与 modelviz-skill 两个来源，按科学问题选择，不设默认或份额。首次正式配图须完成双来源能力预检；academic 全库浏览和五项映射保留，modelviz 使用自己的目录、预览、源码、字段及适配证据。全文图型默认最多两张，第三次须重新比较或登记当前例外；逐图主动评估真实三维机会，合格且无明确劣势时优先三维。详细规则见绘图规范第1.2、5、10、14节。

新建计划由init_visual_plan生成v1.2和drawing_preflight_path。首次正式选图调用drawing_sources.py生成待审能力记录，实际阅读/浏览后填入；modelviz通过modelviz_bridge.py按每图job_dir运行，使用.modelviz.json；academic保留.assets.json。candidate figure/gallery/select-paper、图数账表、真实入文采集、支撑材料与finish复用来源审计；正文晋升全篇重核，旧资源/结果/源码/样式/输出变化须重新验证。
