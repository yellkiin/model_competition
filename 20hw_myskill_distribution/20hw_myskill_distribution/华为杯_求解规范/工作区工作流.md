# 共享模板与独立论文工作区

本文件规定共享模板和工作区职责；科学、绘图、论文及提交门禁继续由各自规范负责。与旧文档中“在项目根求解”“新项目复制完整工具和 skill”等行为冲突时，新建运行按本文件执行。维护模板与使用模板必须区分。

## 目录与生命周期

模板根保留 AGENTS.md、CLAUDE.md、.agents/、.claude/、华为杯_求解规范/、华为杯_论文规范模板/ 六项共享资源，并保留题目/、数据/作为输入入口。解题时共享资源只读，不向 workshop 完整复制。当前模板维护任务可以修改这些资源，不改变历史研究成果。

workshop_vN/ 内存放工作区清单.json、题目/、数据/原始/、数据/中间/、数据/自主/、求解/、论文/、待选图库/、提交附件/。题目相关的其他产物同样在本次工作区。编译必需的类/样式/附录排版文件可以复制到论文/；选定参考源码复制到求解/适配，保留来源，不复制整套规范、skill 或示例结果。

开始自动求解先创建工作区，再读取输入副本和开展处理，不等待问题数量或视觉计划。N 是独立运行编号，原子 mkdir 分配现有最大编号加一；失败目录保留，不填补空号。完成状态与 completed_at 单独记录，初始化不能授予完成状态。演练标记 purpose=demo，不算真实完成论文。

同一次运行修复、续写和补实验继续使用原工作区；新题或明确独立重跑创建下一个编号。有多个候选续跑对象时不猜最大编号。不能自动迁移或更新 2025E_研究、2025E_研究v2 等历史项目。

## 路径合同

- template_root 用于共享规则、参考资产、schema、工具及模板读取。
- workspace_root 用于本题输入、计划、代码、结果、图件、论文与记录。
- 清单 template.relative_path 相对工作区根，支持整体搬迁；其他科学记录中的相对路径基准是 workspace_root。
- skill 内部 references/、assets/、scripts/ 链接相对该 skill；共享文档内部链接相对文档。不能把这些链接相对当前 shell cwd 拼接。
- `WorkspaceContext.read_resource` 只读共享白名单，并按 runtime 限定 .agents 或 .claude；`reference_path` 仅用于读取参考，不可作输出解析器。
- `WorkspaceContext.write_path` 限制当前工作区内可写产物，拒绝原始输入、共享目录名、其他 workshop、符号链接和 junction。原有 safe 的科学文件边界不扩展成任意 ../。

新运行保留共享文件哈希和版本摘要。`check` 报告共享资源或输入漂移；发现变化不能直接沿用 PASS，也不能只刷新摘要掩盖失效审阅。`adopt-resources --reason` 显式采用新版本，保存旧清单、变化文件与受影响证据；`relink-template` 只允许重新关联到字节一致的原资源。两者都不授予科学审核通过。academic、media、结构图、论文页面与支撑材料复现证据绑定对应资源依赖，新版本下受影响的旧记录须重跑重审。新增维护测试不会使生产图件审核过期；新增生产辅助代码或相关参考资产会。

## 会话启动与工具执行

本项目不是 Git 仓库。Codex 与 Claude 会话统一从模板根打开，使根总控和对应 .agents/skills 或 .claude/skills 可被发现；会话明确当前 workspace_root。工具可以从模板根、工作区或其子目录启动，统一入口解析清单后把子进程 cwd 固定到工作区。shell 的 cd 不等于重新加载智能体规则，不能以复制一套共享文件应急。

Windows 10/11 x64 正式入口为模板根 `Start-HuaweiCup.ps1`。`-Action start` 在没有 Python 时先以固定版本、固定 HTTPS 源和发布方 SHA-256 安装用户级 CPython，再调用 `workshop.py start` 创建工作区和准备基础环境；已有兼容解释器则复用。`-Action check` 及 `workshop.py check/list/env check` 严禁安装。普通讨论、状态查询、模板维护不调用 start。其他平台尚未实现自动安装，必须如实报告，不声称兼容。

每个新工作区有独立 `.venv`。`求解/软件需求.json` 是能力需求事实源，`求解/环境检测.json` 是本机实测事实，根 `requirements.txt` 是直接 Python 依赖，`requirements.lock.txt` 是实际解析版本，`求解/环境与依赖.md` 和 `论文/requirements.tex` 从机器清单生成。计划条目不能直接标记成功；方法变化用 `env register` 增量登记来源和理由，再运行 `env prepare`。环境工具只使用共享目录中的固定适配器和参数，不执行题面、模型文本或外部需求中的 shell 字符串与下载地址。

环境安装可写的项目外范围仅为当前用户环境变量和 `%LOCALAPPDATA%/HuaweiCupWorkflow/` 下项目专属下载/轮子缓存及软件目录；通用 `WorkspaceContext.write_path` 不扩权。用户 PATH 保留原值、大小写无关去重；工作区 `.venv/Scripts` 只注入当前子进程，永不持久写入 PATH。工作区 `env prepare` 生成的环境记录由 `workshop.py run` 读取，后续子进程使用该 `.venv` 和已验证的 XeLaTeX/draw.io 路径；记录过期、目录搬迁或路径失效时重新探测。

本会话 Codex 提供的 skill 清单已经列出模板 .agents 下各 skill，可作为此会话发现事实；这不是对任意未来启动位置或 Claude 安装状态的证明。每次启动检查当前运行时技能清单与真实路径，缺少时显式读取同端共享 SKILL.md 并记录路径，不静默跨端回退。

官方依据（2026-09-10 查阅）：[Codex AGENTS.md 发现规则](https://learn.chatgpt.com/docs/agent-configuration/agents-md)说明无项目根时仅检查当前目录；[Codex skills](https://learn.chatgpt.com/docs/build-skills)说明仓库祖先扫描范围。[Claude skills](https://code.claude.com/docs/en/skills)说明启动目录、仓库祖先和额外目录的发现方式；[Claude memory](https://code.claude.com/docs/en/memory)说明 CLAUDE.md 的加载。工具文件可读不代表规则已自动加载。

在模板根使用已验证解释器运行（`python` 代表该解释器，不要求系统别名可用）：

```powershell
python -B 华为杯_求解规范/tools/workshop.py create --template-root . --runtime codex --input 题目/题目.pdf --input 数据/附件.zip
python -B 华为杯_求解规范/tools/workshop.py start --template-root . --runtime codex --input 题目/题目.pdf --input 数据/附件.zip
python -B 华为杯_求解规范/tools/workshop.py check --workspace-root workshop_v1 --runtime codex
python -B 华为杯_求解规范/tools/workshop.py env prepare --workspace-root workshop_v1 --runtime codex
python -B 华为杯_求解规范/tools/workshop.py run --workspace-root workshop_v1 --runtime codex --tool 华为杯_求解规范/tools/build_academic_figure_asset_index.py -- --runtime codex --output 求解/academic_figure_asset_index.json
```

上面的输入名是接口示例，执行前必须明确选择真实文件。`--input` 可重复，不自动扫描导入所有历史材料。复制登记入口相对路径、工作区路径、大小、哈希、时间；入口变化不传播到旧运行。数据/原始输入布局不会再嵌套一层原始/。新增输入应使用登记接口，不直接覆盖副本。

从子目录启动时，使用已经定位的共享 workshop.py 完整路径，省略 --workspace-root 可从 cwd 向上找清单；从模板根必须明确指定工作区。所有传给子工具的数据相对路径仍相对 workspace_root。子工具若有 --project-root，使用 `.`；--template-dir 则传 template_root 下论文模板的实际路径。运行时参数必须与清单一致。

`run` 记录真实命令、退出码、stdout/stderr、共享前后差异和输入核验，日志存求解/验收输出/工作区运行/。Python 常见文件写操作受运行时审计钩子约束；临时目录、字体和渲染缓存指向求解/缓存/，禁止生成共享 __pycache__。外部程序和原生扩展不构成 OS 级沙箱，仍须核对各工具的输出参数和前后文件状态。项目外独立复现必须使用明确的新隔离目录和专门复现入口，不能把任意项目外写入作为默认许可。

## 命令变量

其他规范和 skill 中的 PowerShell 命令使用以下显式变量。先从模板根启动会话，选定当前工作区和本机已经验证的 Python 解释器，再执行命令；不要原样运行尖括号占位值。从子目录启动工具时继续使用已解析的完整路径，不重新以 cwd 猜模板根。

```powershell
$templateRoot = (Resolve-Path '<本次模板根目录>').Path
$workspaceRoot = (Resolve-Path '<明确选定的 workshop 完整路径>').Path
$python = (Resolve-Path '<本机已验证的 Python 解释器完整路径>').Path
$runtime = (Get-Content -LiteralPath (Join-Path $workspaceRoot '工作区清单.json') -Raw | ConvertFrom-Json).runtime
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" check --template-root $templateRoot --workspace-root $workspaceRoot --runtime $runtime
```

新建时尚无清单，create 的 runtime 必须按当前实际运行时明确选择。上面的 check 将清单和两根路径相互核对。工作区子工具的 `--project-root .` 表示包装器固定的工作区；`--template-dir`、`--targets` 等共享读取参数使用 `$templateRoot` 完整路径。规则读取、skill 发现和工具执行是三项不同检查，路径校验通过不替代前两项。

结构图手工 QA 记录使用同一资源依赖函数 `workspace_resources.dependencies(workspace_root, runtime, 'structure')` 的返回值作为 `resource_dependencies`，只记录本次实际使用版本；其 reviewed/status/observation 仍在实际渲染和查看后填写。版本变化后生成新的复核记录，不向旧 PASS 补写新哈希。普通图、media、论文编译与支撑复现的准备/运行工具会自动保存各自依赖，均不自动填写视觉通过。

## 补充输入、采用版本与完成统计

下列命令从模板根展示。`python` 必须是已经验证的解释器；实际工作区由本次任务确定，不把示例编号当作自动续跑选择。

```powershell
python -B 华为杯_求解规范/tools/workshop.py add-input --workspace-root workshop_v1 --runtime codex --input 数据/本次新增附件.zip --reason "登记本次用户补充的附件，后续重新核查受影响的分析"
python -B 华为杯_求解规范/tools/workshop.py adopt-resources --workspace-root workshop_v1 --runtime codex --reason "采用已维护的新模板版本，重新运行并复核受影响的图件与论文"
python -B 华为杯_求解规范/tools/workshop.py relink-template --workspace-root <工作区完整路径> --template-root <搬迁后模板完整路径> --runtime codex
python -B 华为杯_求解规范/tools/workshop.py finish --workspace-root workshop_v1 --runtime codex
python -B 华为杯_求解规范/tools/workshop.py list --template-root .
```

`add-input` 拒绝覆盖已登记副本，复制期间来源变化或并发操作则失败并保留记录。`finish` 必须有真实登记题目和全部正式产物，重新执行支撑材料、附录、TeX、实际PDF最终审计；失败不能登记完成，DEMO始终拒绝。审计通过后保存成果与证据哈希，不自动生成缺失的论文或审核记录。`list` 分别报告运行和当前有效完成论文数；成果、输入、审核或共享版本变化的旧完成记录不计入当前有效数量，历史仍保留。文本可编辑的哈希记录不等于不可伪造的审核证明。

## 待选图库

候选发现与科学质量按绘图规范第14节。合格且未入文的 reserve、supplement 均在默认页展示，正文图在折叠区域单独查看。图在求解目录维护唯一权威源；待选图库/图片/问题标识/ 保存可重建 PNG 和适用的原始导出展示副本，展示副本.json 保存来源与哈希。不得单独修改副本。

重新构建刷新副本，移除已失效、淘汰或不再选用的受管展示文件；被外部修改的旧副本不静默删除。HTML 提供缩略图、打开 PNG/原图副本/权威源图及计划、源码、复核证据链接。科学问题、结论、限制、选用理由和建议位置必须来自实际候选记录。

零剩余时，各问 completion_review.zero_remaining_reason 记录真实取舍原因，observation/scopes/files 保留当前复查证据。缺失或过期时页面明确标注，不能宣称已经排除所有候选；新工作区逐问/final 门禁要求具体零剩余原因。机器检查不证明科学判断完整。图库不整库提交，补充图按支撑材料规则选择，不冲抵正文图数。

图库复查文件哈希未变，不等于共享版本变化后的图件审核仍有效。只要本问存在已过期图件，零剩余区域必须显示“关联图件或共享资源已过期，须重新复核”，原观察标记为当前不可沿用的历史结论；不能继续显示当前复查通过。

## 直接 CLI 与可选 Word 路径

现代模板根保存 `工作流模式.json`（mode=template）。旧独立项目无此标记；旧项目即便位于模板目录内，也按它自己的完整规则目录识别，不因此迁移。正常共享工具必须经 `workshop.py run`；直接 Python CLI 未声明模式时，在创建输出前拒绝并显示正确入口。只读 `--help` 可直接运行。

维护模板使用直接 CLI 的 `--maintenance`；明确维护旧独立项目使用 `--legacy`，并从该旧项目根启动或传入其实际 `--project-root`。模式由子进程继承，但工作区包装器会清除继承的维护/legacy模式并绑定本次清单。共享工作区禁止降级为这两种模式；兼容 API 不等于对新版工作区免门禁。

外层可选 `第二十三届研赛论文Word标准模板.docx` 是明确白名单的只读文件，若存在则纳入共享哈希；构建 DOCX 时传它的完整路径。它不属于本题输入，也不完整复制到工作区。Word 派生文件只写工作区；VBS 通过共享 `tools/run_word_render.py` 包装器调用，明确校验 DOCX/PDF/JSON 路径，在工作区缓存创建本次临时输出后再发布，防止旧 PDF 冒充本次结果。VBS 自身与 Python 文件存在均不证明已安装 Microsoft Word；渲染后仍须实际看页并执行对应审计。

## 已准备证据的附录链路演练

`run_appendix_smoke.py` 从清单确认共享工作区的 `purpose=demo`，不要求 workshop 名含 demo，也不允许在正式运行中执行演练。它通过相同共享执行器依次调用摘要、图数、材料构建、独立复现、逐问/final材料、LaTeX、附录、TeX和编译采集，日志位于本次 `求解/验收输出/附录演练/`。模板路径使用 template_root，科学路径使用 workspace_root。只有明确 legacy 独立项目才从该项目自己的规范树调用工具。

此入口要求已有真实、完整的演练证据；不制造摘要、参考文献、正文或人工审核，不因为演练而豁免任何科学门禁。材料不足应在相应门禁失败，机器阶段全部通过后仍需实际看图和PDF。完整命令（`$reproductionRoot` 为明确的新项目外隔离目录）：

```powershell
& $python -B "$templateRoot/华为杯_求解规范/tools/workshop.py" run --workspace-root $workspaceRoot --runtime $runtime --timeout 7200 --tool 华为杯_论文规范模板/tools/run_appendix_smoke.py -- --project-root . --runtime $runtime --work-root $reproductionRoot
```


## 双绘图来源接入

普通科研结果图平等检查 academic-figure-skill 与 modelviz-skill 两个来源，按科学问题选择，不设默认或份额。首次正式配图须完成双来源能力预检；academic 全库浏览和五项映射保留，modelviz 使用自己的目录、预览、源码、字段及适配证据。全文图型默认最多两张，第三次须重新比较或登记当前例外；逐图主动评估真实三维机会，合格且无明确劣势时优先三维。详细规则见绘图规范第1.2、5、10、14节。

新建计划由init_visual_plan生成v1.2和drawing_preflight_path。首次正式选图调用drawing_sources.py生成待审能力记录，实际阅读/浏览后填入；modelviz通过modelviz_bridge.py按每图job_dir运行，使用.modelviz.json；academic保留.assets.json。candidate figure/gallery/select-paper、图数账表、真实入文采集、支撑材料与finish复用来源审计；正文晋升全篇重核，旧资源/结果/源码/样式/输出变化须重新验证。
