# Q3/L2 代码核对与限时小批次结论

结论：当前 Unified/Trident 已有真实的 F 缓存优化，并非 L2 未生效。新实验进一步改善了部分 Q3 方案，但仍没有证据证明显著扩大了 L2 的边际收益。保留下面完整固定版本成绩，不逐图拼接最好值。

**本批成绩最好的是 L2_window_v1（第一版）**：六图平均周期下降 0.093064%，3图改善/3图持平，无退步；030/033/083 的周期为 558512/350553/177259。后两版并未超过它。最后执行的 v3 不等于最好版本，不替换 v1 记录。这里只按本次六图平均相对周期下降选择一个完整固定策略，不能证明泛化最优。

## 全量既有记录核对

已解析三个分机原始 500 项及授权 049/n1 接续的 1000 份已存在 gzip 响应。原始配对 498/500；按原选择回执纳入接续后 499/500，仅 014/n5 缺同方案 no-L2。保存响应的状态、audit、问题号、配置、周期、时间线终点及 plan 对象对应未发现其他冲突。没有重新调用评估器补齐旧数据。

五核 99 个有效配对的 no-L2/Q3 算术均值 **1.056110957**、中位数 **1.007469632**；76 例变快、23 例相同。已有 F 共 7669 次评价、535 次接受、517 次严格周期下降事件；不是 517 张图，也不等于独立 F 消融胜率。附件是更早 workshop_v1 版本，不能与这组数据混称同轮。

四核仍保留 case_079 的反向差异：有L2比无L2多69周期（7614798 vs 7614729），没有删去。原评估在 COPY_IN 发起时判命中、完成时更新 FIFO；同时在途 miss 不合并，hit 不刷新 FIFO，命中仍受通信依赖约束。代码与文献对应见 [RESEARCH_NOTES.md](RESEARCH_NOTES.md)。

## 实际执行与范围

Python 3.12.8 x64，CPU i7-13650HX（14 核/20逻辑处理器），Windows 11，CPU-only。每臂 120 秒/64 次官方调用，含新起点 Q3/Q2 回放、候选生成、评价、保存和最终精确配对；搜索预留 24 秒收尾。最多 2 workers，未重算 Q1/Q2 单核分母，未恢复已停止的整轮。

六图在首次评价前固定为 001/026/030/033/080/083，五核 Q3。每个版本均从相同旧 Trident 强方案重新开始；基线 F 为局部 F 搜索，并非完整 SMFB。第二批重复 F 的正式周期与第一批一致。第三批只跑新臂，与前两批已保存 F 作参考；不把不同批次秒数当严格性能基准。

共 30/30 项完成，30 个最终同方案配对；partial=0、failed=0、整项超时退出=0、not_started=0。合计 831 次原官方调用。
各批墙钟：round1=156.872s, round2_local_v2=139.583s, round3_hybrid_v3=160.799s。各项候选耗尽、调用上限与搜索窗口退出见 coverage.json；搜索窗口结束并完成配对不等于整项失败。

## 调试后保留与未解决问题

- 保留合法旧 incumbent、精确同plan回放与实际周期/COPY词典序。新增候选仅供独立Q3研究入口调用，尚未接入正式Unified入口；Q1/Q2入口和旧结果不受影响。
- v1 揭示弱连通解包有用，广域 topo4/shared/stagger 常严重增加 Spill。v2 保留分组作局部窗口调序，效果较弱；局部移动仍可能增加 Spill，不能保证免疫。
- 最后 v3 对全部六图统一运行 weak FIFO/low_footprint → 真实观察窗口 → 局部候选，不使用案例名策略。不包含 topo4/shared/stagger；weak 排序仍可能是全局重排，并非全程局部。
- 弱单元复用代理仍可能多计同一核心内部消费者；它没有用于正式评分或宣称缓存精确模型。后续应改成官方真实读取身份与事件窗口，并把通信释放/驻留压力联合纳入候选准入。
- 未找到001/026/080相对强起点的进一步改善。没有证明全局最优，没有新100图、没有与旧论文整体超越的证据。此次六图已用于设计调参，后续泛化评估需要另行冻结版本及未参与设计的案例。
- 本次到此停止，没有再扩展实验。建议保留本次全部版本及失败方向，下一阶段先验证真正限制最终COPY终点的窗口，再考虑扩样。
