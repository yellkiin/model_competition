# 通用问题三改进器

> 发布说明：本报告属于早期 workshop_v1 实验，不能与仓库已有 Unified/Trident 强基线混比。源码与原始数值保持不变；此副本调整了阅读链接。复现前请阅读 [发布入口](./README.md) 和 [数据位置索引](./DATA_INDEX.md)。

`solve_q3_optimized.py` 接受任意符合本题格式的计算图 JSON、1–5 个核和一个已有可行方案。它先用未修改的官方问题三评估器重放基线，再评价有限数量的通用候选。输出按照 `(总周期数, 新增搬运字节数)` 择优，完全相同时保留已有方案。

## 调用

在工作区根目录使用当前 `.venv` 的 Python：

```powershell
.\.venv\Scripts\python.exe -X utf8 -B .\求解\q3_l2_optimization_20260926\solve_q3_optimized.py `
  .\数据\原始\A题官方附件\data\case_044.json -n 5 `
  --baseline-plan .\求解\正式实验\候选评估\case_044\n5\components\plan.json `
  -o .\求解\q3_l2_optimization_20260926\my_run\plan.json
```

所有路径均可替换为其他计算图、基线和输出的绝对路径；程序不要求输入名为 `case_XXX`。脚本依赖当前工作区的官方代码、固定 `config.txt`、原有求解器以及同目录的三类候选模块，使用 Python 标准库。

## 预算与结果

- `--budget-seconds 300`：基线验证完成后的搜索墙钟预算，包含候选生成与评价；最后的结果写盘和子进程清理可能有少量额外时间。
- `--timeout-seconds 30`：每个候选评价、每个候选族生成的最大时间，且受剩余总预算约束。
- `--baseline-timeout-seconds 120`：建立已验证基线的独立时间上限，不计入搜索预算。
- `--max-candidates 24`：除基线外最多评价的不同方案数；设为 `0` 只验证并导出基线。
- `--families original,band,cache,refine`：搜索族及顺序；可选子集。`original` 包含原连通块、8 段和适用时的 800 节点分批；其余模块提供不同分段尺度、通信/管线代价、共享输入与缓存分组候选。
- `--receipt`：汇总记录路径；默认为输出计划同目录、同主文件名的 `.receipt.json`。
- `--work-dir`：详细运行目录的父目录；默认建立 `<输出主文件名>_runs/`，每次运行建立唯一子目录，保留候选方案、失败/超时记录，以及基线和可能入选方案的官方时间线。

成功返回 `0`，打印基线与最终周期数，并输出计划与记录。候选生成失败、执行失败或超时均保留当前已验证最优方案；预算耗尽后正常导出已有方案。基线本身无法通过官方执行与独立时间线检查时，返回 `2`、记录 `BASELINE_UNVERIFIED`，不发布未经验证的计划，也不声称已建立不退步保证。

## 保证范围

最终周期数不高于**本次输入基线在官方问题三配置下的周期数**；这不是全局最优保证。搜索预算较小、候选超时或图结构不适合候选族时，结果可以与基线相同。启发式模型中的缓存代价仅用于产生候选，正式分数全部来自官方评估器。

该程序只生成问题三的新计划，不修改问题一、问题二的代码、计划或结果。若将新问题三计划拿去替换问题一/二方案，不能保证这两个场景也更好；保持原问题一/二方案即可保留它们原有成绩。程序不修改 L2 容量、带宽、DDR 带宽、私有内存容量或跨核延迟。

输出路径必须与输入图及基线路径不同。运行时会检查输入、选中计划是否变化，发现变化则不发布新计划。请保留详细运行目录，以便按汇总记录复核官方时间线。
