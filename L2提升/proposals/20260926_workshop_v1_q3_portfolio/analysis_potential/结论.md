# 问题三 L2 收益的理论边界与现有方案诊断

核查对象：官方固定参数、100 个图、现有五核问题三最优方案及完整官方时间线。没有修改输入、官方评估器或原始结果。本报告中的“旧方案”专指优化前的正式实验方案。

## 1. 先回答：按本题是否应该普遍有很大的 L2 提升？

**不应该预设所有图都大幅提速；但也不能用当前平均收益小来证明算法已经充分利用 L2。** 题目要求适配新增的共享缓存，这表示应把缓存容量、共享数据和访问顺序纳入切图与调度决策，并不表示硬件模型保证大加速。

题给 DDR 总带宽为 60 B/cycle，L2 容量为 1 MiB、读带宽为 250 B/cycle。250/60≈4.17 是带宽比，不是整图加速比。命中读取不再占 DDR，并使用独立的 L2 带宽池，因此收益包括读取本身变快及减少其他读写的争用；计算周期、首次读取、写回和 500 周期跨核同步仍然存在。

这个评估器中的只读缓存还具有几个关键性质：

- 只有 `COPY_IN` 查询缓存；首次未命中读取完成后才插入。
- 多核在首个读取完成前同时发起同一张量读取，会分别未命中，不会合并缺失请求。
- FIFO 命中不刷新淘汰顺序，因此相同张量“曾经读过”不等于再次访问必定命中。
- 核内 L1/UB 已经保留的数据，不必再读取 L2。成功减少 DDR 换入次数的算法，甚至可能同时降低 L2 命中率和总执行时间。

因此，大收益需要同时满足三个条件：有足够重复读取、这些重复读取能在缓存驻留期间发生、这些读取或其 DDR 竞争确实限制全局完工时间。只满足其中一个条件不够。

## 2. 不依赖缓存假设的计算下界

每个核心同一条 Pipe 同时只能执行一个操作。令普通计算操作周期为 d(v)，核数 n=5，可得到任意合法方案均满足的下界：

\[
L_{global}=\max\left\{\max_p\frac{\sum_{v:\,pipe(v)=p}d(v)}{5},\ \max_{P\in DAG}\sum_{v\in P,\ v\text{非COPY}}d(v)\right\}.
\]

第二项把所有搬运耗时都置为零，保留原图计算依赖得到关键路径长度。若保持旧方案中每个操作的核心归属，则还有更强的固定分配下界：

\[
L_{fixed}=\max_{c,p}\sum_{v:\,core(v)=c,\,pipe(v)=p}d(v).
\]

设旧 L2 完工时间为 T，则 `1−L_global/T` 是任意切分重分配所能达到的**最大时间降幅的乐观上限**，`1−L_fixed/T` 是固定核归属时的对应上限。下界忽略搬运、同步、私有缓存约束和很多排队关系；**它不是可实现的目标值，也不是保证能获得的收益。** 当前时间远高于下界，只能说明尚不能排除改进空间。

100 图五核的精确统计：

| 允许改变的内容 | 剩余时间降幅上限 ≤10% 的图数 | ≤5% 的图数 | ≤2% 的图数 | ≤1% 的图数 |
|---|---:|---:|---:|---:|
| 任意切分与核心重分配，受全局计算下界限制 | 28 | 22 | 9 | 3 |
| 保持旧核心归属，受固定分配计算下界限制 | 44 | 35 | 22 | 11 |

这里的比例是 `下界/当前T`，而非 `当前T/下界`。例如 `下界/当前T≥95%`，表示从当前成绩继续减少时间最多 5%。

**这已经足以否定“100 个图引入 L2 后都应该明显变快”的预期。** 对其中 22 个图，即使同时改变切图和核心分配，并理想化消除所有搬运等待，也无法在旧 L2 成绩基础上再降时超过 5%。

为直接对应“从无 L2 引入 L2 应该多大收益”，也可用旧同方案无 L2 时间 T0 作分母：`1−L/T0`。此时，**18 个图即使同时改分核并理想化消除全部搬运，也不可能比旧无 L2 成绩降时超过 5%；保持原核心归属时，此类图有 31 个。** 10% 阈值对应图数分别为 28 与 44。这里仍是理想上限，并不承诺其余图能达到该幅度。

最直观的是 case_001：T=47502，纯计算全局下界=46560，进一步降时上限仅 1.983%。旧方案读取总量 824960 B，其中除首次外的重复量仅 4608 B（0.559%），且均在首读完成前并发未命中。这个图 L2 不明显是合理的，不应为拉开两条曲线而制造额外搬运。

## 3. 现有算法为什么收益不明显

现有候选主要为完整连通块平衡、固定八层带切分和 800 操作分批。候选生成主要围绕计算工作量与图结构，最终用问题三评估器重新选优。它没有系统搜索 L2 参数相关的共享输入分组、分片粒度、数据复用次序或跨核首读错峰。

这造成两类完全不同的低收益：

1. **已经接近计算瓶颈**：即使命中增加，也很难传递到整图完工时间。此时 L2 低收益主要是实例性质，不是必然的算法缺陷。
2. **方案本身有调度或访存不足**：不平衡的核负载、过多同步、粗粒度切分、过大的活跃数据集合及重复换入，可能让现有候选远离更好的成绩。此时简单开启 L2 不能修复原有切图与次序问题。

现有方案的读取重复潜力也没有普遍用尽：把同一逻辑张量除第一次以外的所有读取视为理想可复用读取，逐图“可复用字节/总读取字节”的均值为 **41.67%**，实际字节命中率均值为 **21.29%**。前者是假设无限有效驻留和理想时序的读量上限，不能换算成可达命中率或可达时间收益。

- 16 个图的理想重复读取比例不足 1%，21 个图不足 5%，25 个图不足 10%。这部分图本身就缺少大量 L2 复用机会。
- 按所有图的访问字节加总，首读完成前的重复并发未命中约 **112.32 MB**；曾经插入过但后来再次未命中约 **993.05 MB**。后者主要集中在少数大图，表明仍存在容量或访问顺序导致的重复未命中。
- 后一项不能理解为可直接回收的时间，或者把所有图平均都描述成严重缓存失效。它是按字节加总的诊断量，受大图权重影响。

值得针对性检查的图：

## 4. 不要把流水线忙时当作总时间的可相加组成

MTE2、MTE3、M、V 在各核上可以重叠执行；DDR 请求还可能共享带宽。因而不能写成 `T=计算忙时+读搬运忙时+写搬运忙时`，也不能把 `MTE2忙时/T` 直接当成 Amdahl 定律中可单独缩短的串行比例。

例如旧 case_056 中，最晚完成核心的读搬运累计忙时从 3409 降到 3182 周期，减少 227；全图却只提前 18 周期。这说明一部分搬运收益被重叠和依赖关系吸收。case_083 的读搬运缩短则大幅传递到全图，说明两图的瓶颈结构不同。

判断方向时，应优先看实际全局 Makespan、每核每条计算 Pipe 的负载下界、关键依赖等待、读写字节及完整时间线；流水线忙时只作为辅助诊断。

## 5. 算法可以怎样改，怎样正确展示改进

应在问题三单独增加候选与择优逻辑，保留旧问题一、问题二方案和成绩。以旧问题三方案作为默认候选，只在官方固定参数评估得到更低 Makespan 时替换；时间相同时才比较新增搬运量。这样可以实现逐例不退化。

适合继续搜索的方向是：更细或自适应深度切分、按不同 Pipe 平衡负载、兼顾依赖边代价的分核、减少私有缓存压力的组件分批、共享输入感知的分组和执行次序。切分更细并不必然更好，因为可能增加跨核同步与 DDR 搬运，必须由未修改的官方评估器比较。

**新方案成绩变好，不等于全部改善来自 L2。** 必须同时保留两个比较：

\[
G_{alg}=T_{old,L2}/T_{new,L2},\qquad G_{cache,new}=T_{new,noL2}/T_{new,L2}.
\]

第一个衡量算法改进，第二个固定新方案衡量新增 L2 的实际作用。不能用旧方案无 L2 与新方案有 L2 的比值冒充纯缓存加速比。

如果新算法消除了一批本来会被 L2 命中的 SPILL 换入，则命中率甚至缓存加速比可能下降，而有 L2 的总时间明显改善。这个结果符合优化目标：少读一次通常比先产生多余读取再命中更好。题目最终最小化的是 Makespan，并非最大化命中率或人为拉开曲线。

## 6. 数据与复现

- `five_core_potential.csv`：100 图逐例诊断，包括固定与全局计算下界、字节复用、并发冷启动与重复未命中。
- `summary.json`：汇总统计。
- `analyze.py`：从旧正式结果和图文件只读提取，使用 Python 标准库及官方图解析函数，不调用新求解，不更改原结果。
- 运行：bundled Python 加 `-X utf8 -B analyze.py`。

补充限制：CSV 中的带宽松弛下界及计算下界都用于筛选方向，不能直接拿作论文中已达成的性能结果；最终新算法是否有效，必须以官方固定配置的逐例重评估、同方案无 L2 对照和完整验证为准。
