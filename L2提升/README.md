本目录集中保存问题三的 L2 研究、实现、可复现实验和交接说明。当前结果 PR：https://github.com/yellkiin/model_competition/pull/54。

后续 AI 可以提出不同的方法、证伪现有解释或重新设计 Q3 候选生成；本目录不是要求延续某一种既定算法的清单。正式周期始终来自原官方评估器，Q1/Q2 原有入口、原图、题定配置和既有实验记录保持不变。

建议每个 proposal 至少包含：说明问题与假设的 `README.md`、实现代码、实验协议、实际命令及环境回执、逐例结果、简要结论和数据位置索引。大体积原始响应与运行目录放在执行机器上，仓库提交可供审阅的报告、小表、必要方案和来源索引；不要默认上传多 GB 原始包。

## 当前证据

本次只进行了六个固定案例的五核 Q3 局部改进实验：001、026、030、033、080、083。三个批次合计 **30 个作业、831 次官方调用**，全部作业完成，全部有最终同方案无 L2 配对。两次 `existing_F` 对照都计入 831 次调用；版本比较表只展示一次该对照。

四个策略中，**v1 是本次六图上最好的完整固定版本**：相对同一批旧强起点，逐例周期降幅的算术平均为 **0.093064%**，3/6 图改善。v3 对应为 **0.090809%**。不能将各版本逐图最好值拼成一个策略成绩，也不能把这个幅度写成相对原图单核的加速比。

此前三分机 Trident 的已有 Q3 记录包含 500 个主键：原始完整同方案配对 498 个，纳入已有授权的 049/n1 故障接续后为 **499/500**，014/n5 仍缺配对。五核 99 个有效配对的无 L2 / 有 L2 均值为 **1.056111**，中位数 **1.007470**。这是已有数据核查，没有重新启动 100 图实验。

已有 F 确实执行缓存时序相关优化，产生过真实接受和周期下降。本次新候选的少量改善主要也出现在无 L2 回放中；当前证据不足以声称显著扩大了缓存本身的边际收益。附件早期 `workshop_v1` 的实现和统计不能与新版 Trident/Unified 混称同轮。

详细结论、限制和逐例证据请从 `orion_20260926/reports/` 的 `FINAL_REPORT.md`、`RESEARCH_NOTES.md`、覆盖记录及版本比较表开始阅读；各批次报告也保存在 `reports/` 下。保留 v1 作为下一步实测参照，不代表它已达到全局最优或可以直接用于 100 图总体结论。

## 数据与环境的可迁移性

官方 A 题输入应从仓库 `题目/` 下的 A 题同名附件或已恢复目录取得。传给 `--official` 的目录应包含 `code/` 和 `data/`；保持题定 `config.txt`、原图和官方代码原样。若为 Git LFS 占位或压缩包，只恢复启动本次真实案例所需的 A 题材料。

`orion_20260926/seeds/jobs/case_XXX_q3_n5/` 保存六个真实强方案 `plan.json` 及精简历史分数来源 `summary.json`，运行入口的 `--seed-root` 指向 `orion_20260926/seeds/`。历史 summary 是来源证据，不替代目标机器本次的官方回放；同一 plan 仍须在目标 Q3/n5 重新验证，并进行该 plan 的 Q2/no-L2 配对。

运行入口为 `python -m L2提升.orion_20260926.experiment`，在仓库根目录执行。该入口自动加载同目录 `_frozen/` 中保存的必要 Unified 依赖与本次研究运行代码，无需安装额外 Python 包，也不依赖另一份活动工作区。父实现锚点是 `217444aba097259feb09cac8544279533f670986`；新研究代码、批次快照和父提交分别记录，不能只用父提交冒充新代码的已测版本。具体命令以子目录说明为准。

Windows 优先复用已有 Python，Linux/容器使用实际可用的 Python 3.10+；本实现为 CPU/标准库方案。不要为复现盲目安装 CUDA、PyTorch、Conda 或求解器。六个方案是可迁移的小型输入；完整旧原始响应仍在原执行机，本地绝对路径不是另一台机器可直接使用的公共数据地址。
