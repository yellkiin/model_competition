# 三问统一理论：同一决策变量，不同 Task 构造与数据通路

2026-09-23。本文件与 `model.py / solver.py / evaluator.py` 一一对应。以下明确区分**源码计数恒等式、数学下界、候选排序代理、待检验假设**。分析对象是仓库当前 A 附件三个原评估器；不改图、不改硬件参数、不改评分程序。

## 1. 统一问题与三个不同的评价函数

设计算操作集合为 V，张量集合为 T；排除原始 COPY_IN/COPY_OUT 后的操作仍保留通过 COPY 路径连接的先后依赖。操作 v 具有 Pipe 类型 p(v) 与时间 c_v=max(1,cycles_v)，张量 t 大小为 s_t。

所有问题共同的决策是 P=(π,a,σ)：π 将计算操作划为子图，a 将子图分配到 n 个核心，σ 给每个核心的子图顺序。提交文件只有 `node_to_subgraph` 和 `core_schedules`；没有直接控制 Step3 逐 Pipe 时间线或插入任意延迟指令的权限。

统一写为

$$\min_{P\in\mathcal F_q} F_q(P),\qquad q=1,2,3,$$

其中 Fq 是**原评估器**完成任务构造、Step1、Spill、Step3 和全局模拟后的 makespan。Fq 不是本项目代理分数；可执行集合 Fq 也随模型改变。

|问题|操作的 Task 标签 κq(v)|额外执行规则|本程序的针对性|
|---|---|---|---|
|1|π(v)，即子图|Task 之间必须经 DDR；同核也不跨 Task 驻留；Task 等待为同核100/跨核1000周期|切分粒度、Task 关键路、等待与通信权衡|
|2|a(π(v))，即核心|同核子图合并；跨核 COPY 等待500周期；驻留跨子图持续|核心亲和、生命周期、负载/Spill 权衡|
|3|与问题2相同|增加所有适格 COPY_IN 的只读 FIFO Cache；DDR与Cache独立共享带宽池|完成时插入、复用时序、命中与端到端时间权衡|

固定值来自附件 `data/config.txt`：L1=524288 B、UB=131072 B、DDR=60 B/cycle、Cache=1048576 B、Cache带宽=250 B/cycle。代码读取文件，不把它们作为寻优参数。三个问题不能只换一个“缓存开关”：**问题1与问题2的边界 COPY 生成次数本身就不同**。

## 2. 从源码推导统一通信计数

### 2.1 符号与口径

对每个张量 t，记 P_t、C_t 为非 COPY 的生产/消费操作集合；z_t=1 表示原图中该张量有 COPY_OUT 消费者。给定 Task 标签 κ，定义 A_t={κ(v):v∈P_t}，B_t={κ(v):v∈C_t}。以下集合计数是按 **Task/核心去重**，不是按消费者操作数收费。

Dpre 只统计任务构造阶段生成的 COPY 字节，未包含 Step2 后续 Spill。张量大小即使为0，COPY 仍可能消耗至少一个周期，所以字节数不是全部时延。

### 2.2 问题1：每个输出 Task 至多一次写回

逐个 Task 查看 `_build_scene_a_tasks`：有本地消费者但没有本地生产者时读入；有本地生产者且需要向外/最终输出时写出。因此

$$R_1(t)=|B_t\setminus A_t|,$$

$$W_1(t)=\sum_{a\in A_t}\mathbf1\{z_t=1\ \lor\ B_t=\varnothing\ \lor\ B_t\setminus\{a\}\ne\varnothing\}.$$

$$D_1^{pre}(P)=\sum_t s_t[R_1(t)+W_1(t)].$$

同一输出被三个远端 Task 消费，且单生产者、不是额外最终输出时，计费是一次写＋三次读，即4s；三个消费者在同一个远端 Task 时为2s。将这些 Task 分到同一核心也不会消除其 COPY。

**直接 op→op 边的区别：** 当前问题1源码只在同一 Task 内保留这种边；跨 Task 的控制由 Task 依赖实现，没有额外按 `data_size` 生成 COPY。不能凭一般硬件直觉为第一问增加不存在的复制字节。

### 2.3 问题2/3：每对不同核心分别生成一写一读

源码对每个 (源核,目标核) 连接生成独立 DDR 张量和 COPY 对。令

$$E_t=|\{(a,b)\in A_t\times B_t:a\ne b\}|.$$

则

$$R_{23}(t)=\mathbf1[A_t=\varnothing]|B_t|+E_t,$$

$$W_{23}(t)=\mathbf1[z_t=1\lor B_t=\varnothing]|A_t|+E_t.$$

额外的直接跨核 op→op 边贡献

$$D^{direct}_{23}=2\sum_{(u,v)\in E_{direct},\ \kappa(u)\ne\kappa(v)}\max(0,\operatorname{int}(data\_size_{uv})).$$

从而

$$D^{pre}_{23}(P)=\sum_t s_t[R_{23}(t)+W_{23}(t)]+D^{direct}_{23}.$$

**反例：** 1024 B 张量从一个生产核到三个不同消费核，问题2/3为6144 B，不是4096 B。三个消费者同在一个远端核则为2048 B。代码 `copy_accounting()` 对一般多生产者、原输入、最终输出和直接边也按上述集合计数实现，不假设所有张量只有一个生产者。

这说明“超图去重”要尊重具体实现：去重消费者操作是对的，但不能进一步合并原评估器实际上创建的多份源端写回。SIAM 的无环超图划分工作支持张量集合建模视角，不提供本题这一 COPY 计数规则。[1]

### 2.4 从前置字节到实际执行字节

对当前构图规则，原结果应满足

$$D^{scheduled}=D^{pre}+D^{spill},$$

$$D^{partition\ added}=D^{pre}-D^{original}.$$

后者可以为负，例如任务合并去掉了原图冗余复制；不能强制截断为0。`proxy_calibration.csv` 保存 `pre_spill_formula_error`，其理论值为0。非零说明版本、输入语义或本计数实现需复核，不能靠拟合权重掩盖。

当前三个评估器构造的边界/Spill复制经DDR；第三问的命中读不经过DDR。因此在这个前提下

$$D^{DDR}_3=D^{scheduled}_3-H_3,$$

其中 H3 是原评估器 `cache_stats.hit_bytes`。程序标注 `scheduled_copy_bytes_minus_cache_hit_bytes` 为**推导口径**，不是声称读取了不存在的 `physical_ddr_bytes` 字段。若未来允许非DDR内部复制进入同一统计，必须改为按每个COPY实际路径计数，此恒等式不可无条件继承。

## 3. 第三问：Cache 是时间状态，不是静态“共享输入减分”

### 3.1 与原代码一致的事件规则

缓存键是 COPY_IN 的首个非DDR输出张量的 `logical_tid`，不存在时取该张量ID；包括原输入、跨核中间结果、Spill换入。正字节读在**发射时**查找：命中走CACHE_READ，未命中走DDR。在**该读完成时**尝试入队；超过容量的条目不缓存，已有条目不刷新顺序，空间不足从FIFO队首驱逐。COPY_OUT不查询/填充缓存。

一个容易遗漏的边界：命中的读完成时同样尝试插入。若其条目在读期间被别的完成事件驱逐，完成后可以重新插入。`fifo_requests()` 与测试包含这个行为。

设某键首次冷读在t=0发射、t=d完成；同键另一读在0≤t<d发射，也会未命中。因此**把消费者同时启动不必提高命中率**。通过重排独立工作，使复用落在首次填充后且驱逐前，才可能命中。代码只能改变合法子图顺序/归属，不能伪造延迟指令。

### 3.2 两个不能假设的单调性

FIFO请求序列 `1,2,3,4,1,2,5,1,2,3,4,5` 在所有读取先完成再发下一条、等大条目时，容量3出现9次未命中，容量4出现10次未命中。这个构造说明FIFO容量单调性不能当定理。正式实验仍固定官方容量，不用改容量“提高成绩”。

命中字节多也不必降低总时间。DDR减少后，计算关键路、跨核等待或Cache共享读池可能成为瓶颈；时序变化也可能让更多关键读等待。因此比较结果必须同时看命中、DDR、Cache服务量和makespan。

### 3.3 本项目代理与真实模拟之间的边界

代理先用串行参考计算顺序估计请求时刻，再按FIFO完成时插入规则估计命中字节。它**不复刻共享带宽争用、Step3重排或生成的Spill请求**，也不对直接边新生成的缓存键模拟复用。所以 `cache_hit_bytes_proxy` 只用于候选排序，不等于实际H3。

代码已将预测Cache读服务量 Hhat/250 与预测DDR服务量 (Dpre−Hhat)/60 同时放入最大值，避免只奖励命中而忽略Cache瓶颈。代理不准时有 `no_cache` 消融与 `unranked` 修正，最终仍靠原评估器保留最好方案。

## 4. 计算下界与为何不能强求 n 倍加速

令 Wp=Σ_{v:p(v)=p} c_v。每个核心该Pipe同一时刻只能执行一个操作，故

$$T_q(P)\ge W_p/n\quad\forall p.$$

另外，取任务构造明确保留的计算依赖图的一条路径，操作必须串行，最长计算路径长度为L，则

$$LB_n=\max\{L,\max_p W_p/n\}\le T_q(P).$$

代码对下界只使用非COPY直接边和同张量的计算生产/消费边；对用于排序的任意COPY收缩路径不额外假设其执行保留方式。忽略COPY、等待、Spill使下界偏松，但不凭错误的执行假设将其做强。

不能使用 ΣpWp/n 作为一般下界，因为不同Pipe可重叠。也不能把固定方案的DDR流量当作所有方案不变的全局下界。若已执行方案的实际字节口径可靠，则 DDDR/60、H/250 是**该方案的服务时间下界**，适合解释瓶颈，不是未搜索方案的最优性证明。COPY取整带来额外开销，字节/带宽下界通常不是精确COPY耗时。

相对固定官方单核分母Tsingle，有 S≤Tsingle/LBn。若T/LB很接近1，继续搜索的改善空间有限；若比值很大，只能说明这个界解释不了全部开销，不能直接断定某一种故障。允许n个虚拟核中部分空置是候选策略，`--cores`与实际使用核数分别记录。

## 5. 驻留峰值、面积与两种相反的粒度效果

对一个参考Task内访问序列，将张量从首次触及保持到最后一次触及；在同一操作上，输出与最后使用的输入同时计入。记参考驻留曲线Mr(j)，定义

$$P_r=\max_j M_r(j),\qquad A_r=\sum_j M_r(j)c_j.$$

P−容量的正部分反映超限倾向，A/容量有周期单位，反映长期占用。代码使用

$$\lambda_m\left[\frac{\sum_r(P_r-C_r)_+}{B_{DDR}}+0.1\sum_r A_r/C_r\right]$$

作为代理惩罚，而非真实Spill字节或物理峰值的定理。参考序列不包含COPY和Step3乱序重叠，必须通过实际 `spill_added_copy_bytes`、`memory_peak_by_core` 和 `memory_dependency_count` 检验。

**第一问**切小可能降低单Task驻留，却增加跨Task复制及100/1000周期等待；切大相反。**第二/三问**同核分成多个子图不会重置驻留，单纯“切小就释放缓存”是错误解释。它们的细分收益只能通过改变优先顺序、迁移/重新分核和实际Step2/3行为产生。`spill` 修正同时倾向最后使用者、加强驻留惩罚并允许迁移；不是只修改块数。

## 6. 统一候选排序与原评估器驱动的搜索

统一代理可写成

$$\widehat F_q(P)=\max\{\widehat L_{core,pipe},L,\widehat D_{DDR}/B_{DDR},\widehat H/B_C,\widehat L_{Task}\}
+\lambda_d\widehat D_{DDR}/B_{DDR}+\lambda_m\widehat M.$$

Q1启用Task屏障路径项，Q2/3不启用；Q3启用FIFO预测，Q1/2命中为0。Task路径项以每块最大Pipe工作量和前驱/同核等待递推，忽略真实搬运和重叠，因此只作代理；不与严格LBn混用。

采用最大值而非简单把计算+通信全相加，是因为Pipe/DDR/Cache可能重叠；额外通信与驻留项用于对同等瓶颈的候选作正则排序。权重是算法超参数，不是物理常数。不同资源下界的最大值也可解释为在单纯形权重上最大化加权下界，但**这不意味着当前含启发项的目标是官方优化问题的精确对偶**。

候选来自工作量等分的连续拓扑块、关键路/最后使用/共享张量/随机拓扑序、负载与亲和分核；局部动作是相邻合并、拆分、迁移、边界移动和商图拓扑重排。`portfolio`不作局部动作；`unranked`随机选择候选而不按代理分数筛选。其余配置和调用预算记录于 `search.json`。

每次候选都交原CLI评分。官方结果的字典序 `(makespan, DDR字节口径)` 决定胜者。失败也消耗调用预算，不能把容易失败的方法按“成功次数相同”隐性给予更多计算。

固定随机种子时，前k次调用不依赖最终预算B；因此可以从一次32次实验截取4/8/16/32次前缀，不必每个预算重跑。已观察到的最好makespan随调用次数不增加：这是维护最小值的程序不变量，**不是对全局最优收敛速度的定理**。追加修正重评父方案，若原环境/评估确定且重评成功，则至少保留父方案；改善是在额外预算下取得，不能混入原定预算的主表。

## 7. 保序搜索空间与小图枚举范围

若全局计算拓扑序切为连续区间，则跨区间依赖只能从早区间指向晚区间；每核心也按全局区间序取子序列，加入核内子图顺序后仍无子图级回边。相邻合并/拆分/边界移动保持性质。商图拓扑重排后，块内原序列加新的块顺序仍是全局拓扑序。

这个证明**不覆盖**Q2/3在Step3之后新增的逐PipeFIFO、内存复用和跨核COPY组合图。代码没有承诺所有候选最终可执行；原评估器是最终判定。

对m个操作的**固定**拓扑序，每个相邻间隙可选择是否切开。若切为k块，有C(m−1,k−1)种切法、n^k种核心分配；核内顺序固定为块顺序，因此候选总数

$$N(m,n)=\sum_{k=1}^{m}{m-1\choose k-1}n^k=n(1+n)^{m-1}.$$

m=4,n=2时为54。`oracle`实际枚举这些候选并逐个原评估；不枚举其他拓扑序、非连续划分或任意核内顺序。全部候选已调用也不代表所有失败都已证明数学不可行：超时/内部异常仍未知。因此输出称“限制族中已观察到的最好值”，保留逐例失败供复核。它可以揭示局部搜索遗漏，不冒充大图全局最优证书。

## 8. 三场景同方案回放与收益归因恒等式

对分别在Q2/Q3优化得到的P2、P3，记a=T2(P2)、b=T3(P2)、c=T2(P3)、d=T3(P3)。报告

$$G_{cache|P2}=a/b,\quad G_{cache|P3}=c/d,\quad G_{retune}=b/d,\quad G_{joint}=a/d,$$

并逐图验证

$$G_{joint}=G_{cache|P2}\,G_{retune}.$$

“缓存作用”与“重新优化作用”由同方案对照分开。平均值的乘积一般不等于乘积的平均，不能用三列平均值重新声称该恒等式成立。完整3×3矩阵还包含Q1来源方案；Q1/Q2比较同时改变Task同步、驻留和COPY构图规则，不能把该比值只归因于驻留。

## 9. 论文主线与证据等级

建议论文依次写：统一决策模型 → 场景化通信恒等式 → 计算下界和驻留/FIFO代理 → 保序组合与局部搜索 → 三问独立主结果 → 消融和3×3归因 → 差例修正及限制。

正式表中必须有100图各n=1…5三问分数、统一单核分母、实际调用数、完整性、失败和搜索开销。开发20图用于选统一权重/配置，余80图另报；种子先在同图内平均，不能将3个种子当3倍独立图样本。图集重采样区间只作结果敏感性，不把固定100图假设为某人群随机样本。

本环境只有数学/统计单元验证，未运行正式100图或完整原评估器。提交的实验设计和代码足以逐问生成求解方案及论文证据，但**真正的三问数值答案，要由本地跑出的官方结果填写**。
