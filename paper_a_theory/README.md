# ORION论文理论输入包

本包把PR #38实际实现整理为可供全文写作采用的统一模型、术语、方法路线和证据接口。它是论文的理论输入，不是新的求解器，也不是另一套通用写作Agent。

**统一主线：子图划分、核心映射和核内顺序的联合决策，在同一执行模型下由多类邻域共同改进。三问通过Task组织、跨核交接和FIFO状态的不同规定加以特化。**

## 阅读与文件分工

| 文件 | 用途 | 面向 |
|---|---|---|
| `THEORY.md` | 统一方案、三问语义、资源/缓存执行、目标、下界与性质、指标 | 模型与正文写作 |
| `ALGORITHM.md` | 真实的共同方案更新、多邻域、成本选择与停止流程 | 算法章节与流程图 |
| `TERMS.json` | 全篇术语、符号、定义、内部实现词到学术表述的映射 | 所有写作/数据/绘图角色 |
| `SOURCE_MAP.md` | 原题章节、代码调用链、已读原文段落、迁移边界 | 内部核对与增量更新 |
| `references.bib` | 与文献库编号对应的书目 | 参考文献管理 |
| `PAPER_ROUTE.md` | 章节主线、必需图表、证据集合、未来变化处理 | 论文主Agent及更新角色 |
| `APPEND_PROMPT.md` | 可直接追加在PR42提示词后的完整补充 | 零上下文本地Codex |
| `BINDING.template.json` | 可更换实际源码、Agent工作区和结果目录 | 输入适配 |
| `bind_theory.py` | 新建独立理论输入目录和绑定记录；原目录不写入 | 本地安装 |
| `check_binding.py` | 人工构造工作区上的接入边界检查，不运行研究算法 | 本包工程验证 |
| `MANIFEST.json` | 文件清单、阅读次序、版本锚点与数据要求 | 机器读取 |

顺序：README → THEORY → ALGORITHM → TERMS → SOURCE_MAP → PAPER_ROUTE → references。内部SOURCE_MAP、绑定与检查文件不直接进入论文正文；正文沿已定义的数学和学术术语写作。

## 本地接入

由原启动提示词建立新的论文工作区，保留`workshop_v1`。从理论分支读取本目录并固定取得的commit。复制BINDING模板为本次新配置，填入真实路径；路径可为绝对路径，或相对于配置说明的仓库根目录。

```text
python <理论包目录>/bind_theory.py --spec <已填好的配置JSON> --package-commit <取得本包的40位commit>
```

输出位置：

```text
<本次论文工作区>/theory_input/orion-pr38-theory-v1/<binding_id>/
    THEORY_HANDOFF.md
    THEORY_BINDING.json
    BINDING_INPUT.json
    package/...
```

每次接入使用新的binding_id；已有目录不会被覆盖。脚本不修改AGENTS.md，不运行求解器，不修改模板，不读取Git凭据，不联网或切换实验分支。Git模式只比较明确列出的入口文本与所声明commit；这不是全依赖语义验证。归档源码模式要求真实执行清单，并将后续语义核对保留为待完成。

## 数据未到齐时

先写模型、性质、算法与方法性摘要草案，并建立数据和图表脚本。最终实验集合、实际算法版本、原plan与原response绑定之后，再填写定量结论。理论包不包含编造的成绩、实验曲线或已完成实验数量。

更新仅结果时不必重写数学框架；更新算法策略时修改伪代码与相应实验定义；改变决策权限或执行语义时重新审查受影响的定义和证明。

## 数学解释的几个边界

商图无环不是完整执行可行性的全部条件；计费按张量与Task/核语义而非简单割边数；F候选只改核内顺序，S/M不一定只改变一个变量；当前解单调保持相对于给定可行起点成立；停滞和下界精度停止分别解释。

第三问的额外COPY字节、DDR实际服务量和命中率是不同指标。时间—质量曲线按结果实际可用时刻记录。具体阈值、源码变量和跨版本历史留在内部绑定中，不充当论文主线。
