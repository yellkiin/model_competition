# 共享带宽与层级存储约束下的多核计算图调度

## 1. 研究对象与统一决策

计算图的多核执行需要同时确定算子分组、分组到处理器的映射以及每个处理器上的执行顺序。分组决定任务边界，映射决定跨核数据交换，顺序决定数据的驻留区间和资源竞争时刻。这三类决策共同影响计算、搬运与等待的重叠关系，因此以完整执行过程的最大完成时间为优化目标。[题目；A49]

设原始计算图为有向无环图 \(G=(V\cup\mathcal T,E)\)。其中，\(V\) 为需要分配的非边界搬运算子集合，\(\mathcal T\) 为张量集合；算子 \(v\) 的固定计算周期为 \(p_v\)，所属计算流水线为 \(\rho(v)\)，张量 \(t\) 的大小为 \(b_t\) 字节。边界搬入和搬出操作按照执行规则重新构造。张量的生产者集合和消费者集合分别记为 \(P_t\) 与 \(C_t\)，数据依赖方向为生产者到消费者。共享张量可以用有向超边 \((P_t,C_t)\) 表示，从而保留一次生产关联多个消费者的集合结构。[题目；A39]

设可用核心集合为 \(K=\{1,\ldots,n\}\)。一个完整方案表示为

\[
x=(\mathcal P,a,\boldsymbol\pi),\qquad
\mathcal P=(V_1,\ldots,V_m),\quad
 a:\{1,\ldots,m\}\to K,\quad
\boldsymbol\pi=(\pi_1,\ldots,\pi_n).
\tag{1}
\]

\(\mathcal P\) 为非空算子子集构成的划分，满足 \(\bigcup_iV_i=V\) 且 \(V_i\cap V_j=\varnothing\;(i\ne j)\)。\(a(i)\) 为子图 \(V_i\) 的核心归属，\(\pi_k\) 恰好包含分配给核心 \(k\) 的所有子图各一次。允许 \(\pi_k\) 为空。以 \(g(v)\) 表示算子所属子图，则其核心归属为 \(a(g(v))\)。

将每个子图收缩为一个顶点，得到子图依赖图；再加入各 \(\pi_k\) 中相邻子图的顺序边。该图无环是所选顺序与数据依赖相容的必要条件。[A02] 运行过程中还应满足流水线次序、存储容量和任务间释放条件。最终可行集合 \(\mathcal F_q(G,n,\theta)\) 由问题 \(q\in\{1,2,3\}\) 的完整执行规则确定，\(\theta\) 为容量、带宽、等待周期等固定参数。

划分和核心映射是决策，算子的实际启动时间、Spill 位置和缓存命中则由执行规则产生。这个区分使优化变量与题目允许提交的方案一致。[题目]

## 2. 三个问题的统一执行语义

定义任务归属函数

\[
\chi_q(v)=
\begin{cases}
g(v),&q=1,\\
a(g(v)),&q=2\text{ 或 }3.
\end{cases}
\tag{2}
\]

第一问中，每个子图单独形成一个 Task；第二、三问中，同一核心上的子图按照给定顺序组成一个 Task。Task 在本文中专指这一执行组织单元，与算子和子图区分使用。

| 执行条件 | 第一问 | 第二问 | 第三问 |
|---|---|---|---|
| Task 组织 | 一个子图一个 Task | 一个核心一个 Task | 一个核心一个 Task |
| 同核相邻子图的数据 | 跨 Task，经 DDR 交接 | 可按容量和调度规则在片上保留 | 同第二问 |
| 任务或通信等待 | 同核 Task 等待 100 周期；跨核依赖 Task 等待 1000 周期 | 跨核 COPY_OUT 完成后等待 500 周期释放相应 COPY_IN | 同第二问 |
| L1 / UB | 每核分别受容量约束；Task 切换清空 | 每核分别受容量约束 | 同第二问 |
| 共享只读 L2 | 无 | 无 | FIFO 替换，发射时查找、完成时填充 |

上表参数对应官方默认配置：每核 L1 为 524288 字节、UB 为 131072 字节，共享 DDR 带宽为 60 字节/周期；第三问只读 L2 容量为 1048576 字节、带宽为 250 字节/周期。[题目及官方配置] 参数研究采用单独标明的 \(\theta\)，与默认配置分别统计。

对第一问，Task 的最早激活时刻由同核前序 Task 的完成时刻和跨核依赖 Task 的完成时刻共同确定，并分别计入规定的等待。对第二、三问，跨核数据到达条件作用在相关搬出与搬入操作之间，而非在每一对相邻子图之间统一插入整段等待。不同流水线在数据依赖允许时可以重叠执行。

## 3. 从候选方案到执行时间线

把固定执行规则记为映射

\[
\mathcal E_q(G,x;\theta)
   =\bigl(\text{可行性},\;\mathcal R_q(x),\;C_q(x),\;D_q(x)\bigr).
\tag{3}
\]

\(\mathcal R_q(x)\) 是包含算子、搬运、内存分配与释放、缓存事件的执行记录；\(C_q(x)\) 是最大完成时间；\(D_q(x)\) 是官方口径的额外 COPY 字节量。该映射依次完成 Task 构造、固定拓扑调度、容量约束下的 Spill 处理、流水线排程和全局离散事件推进。其内部排序与内存置换由题目规定。[题目]

### 3.1 数据依赖与流水线约束

执行展开后产生操作集合 \(\widetilde V_q(x)\)。记操作 \(j\) 的发射时刻和完成时刻为 \(s_j\) 与 \(f_j\)。所有依赖边必须满足规定的数据完成与释放时刻；同一核心同一 Pipe 上的两个操作按固定队列先后执行，不能同时占用该 Pipe。不同核心及不同 Pipe 可以在满足其他条件时并行。

计算操作的服务周期取题目给定值；COPY 的完成时刻还取决于与其重叠的共享带宽请求。因此，依赖图中的通信不能统一替换为与其他操作无关的常数边权。

### 3.2 片上驻留与 Spill

令 \(\mathcal B_{k,r}(t)\) 为时刻 \(t\) 核心 \(k\) 在存储区 \(r\in\{L1,UB\}\) 中实际分配且尚未释放的缓冲实例集合。对每个时刻应有

\[
M_{k,r}(t)=\sum_{b\in\mathcal B_{k,r}(t)}\operatorname{size}(b)
\le \operatorname{Cap}_{r}.
\tag{4}
\]

这里统计缓冲实例而非简单累加所有逻辑张量；复制、搬运与释放可以改变实例的生存区间。超过当前片上可用容量时，固定内存处理步骤根据后续使用位置选择置换对象，必要时向 DDR 备份，并在再次使用前取回。驻留、换出和取回的状态分析可用于解释分组与顺序引起的额外数据搬运。[A16]

优化通过改变 \(x\) 间接改变上述状态。它不增加自由地址分配、任意重算或自主选择置换对象等决策。用于生成候选的驻留峰值估计与式(4)中的实际占用应分别标注。

### 3.3 共享带宽

令 \(A_r(t)\) 为资源池 \(r\in\{\mathrm{DDR},\mathrm{L2}\}\) 上正在服务的搬运集合。官方模拟将每项搬运的剩余独占服务工作量记账，并在活动请求之间均分相应资源池的服务能力。若一个事件间隔长度为 \(\Delta\)，期间活动数固定为 \(m_r>0\)，则采用归一化工作量表示时有

\[
w_j(t+\Delta)=\max\{0,w_j(t)-\Delta/m_r\},\quad j\in A_r(t).
\tag{5}
\]

初始工作量和事件完成取整遵循官方搬运时长函数，不能以连续近似替换其最小周期与取整约定。新请求发射、已有请求完成等事件会改变活动集合，并相应改变后续服务速率。DDR 与 L2 分别维护资源池。

### 3.4 FIFO 复用时序

以 \(Q_e\) 表示某一具体事件处理前的只读 L2 队列，队列元素为已完成填充的逻辑张量标识及其大小。COPY_IN 的命中变量为

\[
h_j=\mathbf 1\{\operatorname{logical}(j)\in Q_{e_j}\},
\tag{6}
\]

其中 \(e_j\) 是该次发射查找事件。相同时刻已先处理的完成与填充事件包含在 \(Q_{e_j}\) 中。命中选择 L2 服务，未命中选择 DDR 服务。读取完成后尝试填充；仍在队列中的条目保持原插入位置，命中也不更新 FIFO 次序。空间不足时按插入先后驱逐；大于总缓存容量的张量不驻留。[题目及第三问官方事件处理]

因此，两个相同张量的读若都早于第一次填充完成而发射，均可能未命中。合法的核内重排可改变消费者相对于填充、驱逐事件的位置，进而改变复用机会。这种调整通过执行已有子图实现，不增加暂停或延时指令。

## 4. 统一目标与耦合关系

在各问题的可行集合内求解

\[
\min_{x\in\mathcal F_q(G,n,\theta)}^{\mathrm{lex}}
J_q(x),\qquad J_q(x)=(C_q(x),D_q(x)),\qquad
C_q(x)=\max_{j\in\widetilde V_q(x)} f_j.
\tag{7}
\]

先比较完成周期，周期相同再以更少的额外 COPY 字节决胜。实现中的第二项是并列处理准则，不改变以最大完成时间为主目标的建模。

划分、映射与顺序通过式(2)—(6)耦合：更细划分可能增加可调度性，也可能增加第一问的 Task 边界；更均衡的计算分配可能增加跨核数据交换；更长的驻留可能减少重复读取，也可能增加容量压力；更高的字节命中率可能只加速并未决定最终完成时刻的读。因而，候选排序可使用启发式特征，接受候选则依据式(7)的完整执行结果。

第三问中，官方额外 COPY 字节由生成的 COPY 操作及 Spill 统计得到，缓存命中的 COPY 仍可能计入这一操作字节口径。它与实际由 DDR 资源池服务的字节量是不同指标。报告物理片外流量时，应从服务资源和实际事件另行计算并说明口径。

## 5. 下界与解质量

令 \(G_c\) 为固定执行规则保留的计算依赖图。忽略通信、等待和资源争用，计算最长路径给出

\[
L_{\mathrm{path}}=\max_{P\text{ 为 }G_c\text{ 中的路径}}\sum_{v\in P}p_v.
\tag{8}
\]

对每种计算 Pipe \(r\)，令 \(W_r=\sum_{v:\rho(v)=r}p_v\)。每核的该 Pipe 同时至多服务一个操作，故

\[
L_{\mathrm{load}}=\max_r W_r/n.
\tag{9}
\]

不同计算 Pipe 可重叠，故式(9)分别取负载再取最大值。令 \(B_{\mathrm{DDR}}^{\mathrm{mandatory}}\) 为经过证明、对所有候选都必须由 DDR 服务的字节量，则

\[
L_{\mathrm{io}}=B_{\mathrm{DDR}}^{\mathrm{mandatory}}/\beta_{\mathrm{DDR}},\qquad
L=\max\{L_{\mathrm{path}},L_{\mathrm{load}},L_{\mathrm{io}}\}.
\tag{10}
\]

在初始缓存为空、输入逻辑标识独立且终端写出确属必需的普通算例中，必要读写提供上述字节下界。存在逻辑别名等情形时，应重新论证必要读取部分，或仅采用仍有效的写出下界。三个下界分别来自依赖、独占计算资源与共享服务量的松弛，取最大值避免把可重叠开销相加。

**性质1（全局下界）。** 在式(8)—(10)的依赖和必要流量假设成立时，对任意可行方案 \(x\)，有 \(L\le C_q(x)\)。证明分别由依赖链必须顺序完成、每种 Pipe 的 \(n\) 核总服务上限、以及 DDR 的总服务能力得到。

给定一个已经通过完整执行验证的方案，令 \(U=C_q(x)\)，最优完成周期为 \(C_q^*\)。当 \(0<L\le C_q^*\le U\) 时：

\[
\frac{U-C_q^*}{U}\le 1-\frac{L}{U},\qquad
\frac{U}{C_q^*}-1\le\frac{U}{L}-1.
\tag{11}
\]

第一式是相对于当前周期的最大可能减少比例上界；第二式是相对于最优周期的相对误差上界。二者分母不同，应分别定义。以第一式的右侧不超过阈值作为停止条件，属于给定松弛下的精度控制。

还可固定当前候选的核心归属、通信边界等构造候选专属下界 \(L(x)\)。若 \(L(x)>U\)，该候选无法改善当前完成周期，可以省去完整评价。这一结论作用于该候选；全局停止使用对整个可行集合成立的 \(L\)。

## 6. 多邻域迭代改进的基本性质

以 \(x^{(0)}\) 为初始可行方案。结构调整、驻留相关重组和缓存时序重排生成完整候选 \(y\)。只有 \(y\in\mathcal F_q\) 且 \(J_q(y)<_{\mathrm{lex}}J_q(x^{(k)})\) 时，令 \(x^{(k+1)}=y\)；否则保留 \(x^{(k)}\)。

**性质2（可行性与单调保持）。** 若初始方案可行、每次替换前完成相同规则的可行性评价，则所有保留方案均可行，且 \(J_q(x^{(k+1)})\le_{\mathrm{lex}}J_q(x^{(k)})\)。证明直接由接受规则归纳得到。该性质以给定的合法初始方案为起点。

**性质3（纯顺序邻域的不变量）。** 仅改变各核心内子图排列、保持划分和核心归属时，算子集合、张量依赖与跨核生产者—消费者归属保持不变。实际驻留、Spill、流水线队列及缓存事件仍可改变。最终可行性继续按完整执行规则验证。

搜索预算、调用次数或有限候选流给出停止条件。上述性质说明了保留解的质量与安全性；不同邻域的贡献和给定时间预算下的效果由匹配实验衡量。

## 7. 与题目要求一致的评价量

对图 \(i\)，令 \(T_i^{(0)}\) 为题目规定的原图无 L2 单核基准，\(C_{i,q,n}\) 为所选方案的完成周期。逐图加速比及均值为

\[
S_{i,q,n}=T_i^{(0)}/C_{i,q,n},\qquad
\bar S_{q,n}=\frac1M\sum_{i=1}^{M}S_{i,q,n}.
\tag{12}
\]

这里先逐图求比，再取算术平均。原图单核基准是固定执行方案，划分后额外搬运和 Spill 可随方案变化，因此与理想固定工作量线性加速模型分别解释。

对第三问选中方案 \(x_{i,3,n}\)，以同一个方案分别运行有 L2 与无 L2 语义，得到

\[
R_{i,n}=\frac{C_2(x_{i,3,n})}{C_3(x_{i,3,n})},\qquad
S^{\mathrm{noL2}\mid x_3}_{i,n}=\frac{T_i^{(0)}}{C_2(x_{i,3,n})}.
\tag{13}
\]

其无 L2 对照仍固定第三问的方案。字节命中率单独定义为命中字节与总读取字节之比。

以 \(\tau\) 表示主机搜索墙钟秒数，与设备执行周期 \(s_j,f_j\) 区分。时间—质量曲线使用在截止 \(\tau\) 前已经完成验证并保存的可用方案：

\[
U(\tau)=\min\{C_q(x):x\text{ 在 }\tau\text{ 前已验证且可用}\}.
\tag{14}
\]

暖启动分别记录历史方案取得成本、本次验证和追加搜索成本。完整历史缺失时，总端到端时间保留为未知；已知追加时间仍可独立报告。设备周期的改进与主机求解速度的改进分别评价。
