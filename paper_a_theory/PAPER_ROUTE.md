# 全文路线与数据接入要求

本文件供论文主Agent、数据Agent、绘图Agent和增量修订Agent共同读取。正文母本为`THEORY.md`与`ALGORITHM.md`；术语统一采用`TERMS.json`。这里的路径、版本号、内部检查项留在工作记录，不直接复制进学术正文。

## 1. 论文中心句

> 将多核计算图调度表示为子图划分、核心映射与核内顺序的联合决策，在统一的容量、流水线和共享带宽执行约束下，以最大完成时间为主要目标，采用多类候选共同更新当前最好可行方案，并依据实际评价收益分配有限搜索时间。

建议论文题目为“基于无环划分与多邻域迭代改进的多核计算图调度”。标题和摘要最终按实测范围调整。ORION Trident可以作为实现名称出现一次，不把项目代号或自拟缩写当作理论贡献。

## 2. 推荐章节与逻辑

| 章节 | 必须回答的科学问题 | 使用内容 | 成稿要求 |
|---|---|---|---|
| 摘要 | 问题、统一模型、核心方法、实测主要发现 | 最终方法与结果绑定 | 数据未齐时先完成方法性摘要草案，定量结论待绑定数据生成 |
| 1 问题分析 | 为什么分组、映射和顺序需要联合考虑 | THEORY §1及题目§1.3 | 用题目约束解释耦合；不写历次PR或失败版本回顾 |
| 2 假设、符号与执行模型 | 决策权限是什么，硬件资源怎样计费 | THEORY §1–4、TERMS | 输入既定条件与为了推导使用的附加假设分开 |
| 3 无环划分与多邻域搜索 | 如何获得和改进完整合法方案 | ALGORITHM §1–6 | 先完整总流程，再解释候选类别及选择；一套符号贯穿 |
| 4 第一问 | 子图级Task如何影响并行、边界搬运和等待 | 统一模型的q=1特化 | 依赖图、Task等待、周期及额外COPY；保持统一算法 |
| 5 第二问 | 核心级Task怎样改变驻留与跨核交接 | q=2特化、驻留相关候选 | 与第一問的执行语义区别；结果来自q2实际记录 |
| 6 第三问 | FIFO事件与顺序怎样共同影响完成时间 | q=3特化、缓存时序邻域 | 固定同一方案的有/无L2对照；命中与关键等待分别分析 |
| 7 搜索效率与方法分析 | 有限时间花在哪里，哪些机制有效 | 下界、真实前缀、匹配消融 | 设备周期与主机秒数分开；来源接受计数与因果效果分开 |
| 8 结论 | 模型和实验支持哪些结论 | 真实结果与数学性质 | 陈述适用场景和观察事实，不用防御性口号或未验证的最优性宣传 |
| 附录与支撑材料 | 如何复核逐例结果、符号和实现 | 完整逐图指标、方案索引、参考文献 | 代码变量、目录和复现实验操作放支撑材料，而非模型推导 |

第二至三问重复使用前面定义的方案与执行模型，仅说明新的约束或状态；不要为每一问另起一套互不相干的算法名称。

## 3. 理论、实现与实验的主张分层

- 理论层：可行性与单调保持、有效下界及差距关系。使用THEORY中的前提和证明。
- 实现层：实际启用的候选、来源选择、停止规则。逐项对应绑定源码；未执行的实验分支不能进入算法主流程。
- 实验层：完成周期、加速比、生成开销、机制贡献、参数作用。对应原方案、原响应和真实时间，不能由设计意图推导数值。

写作可以凝练，但不能删除决定正确性的前提。所谓“理论统一”是同一决策空间与执行语义下的联合搜索，不是把已有启发式重新命名成未实现的数学规划算法。

## 4. 必需数据与图表

每条记录最少带有：图标识、问题、核数、算法版本、硬件配置、运行标识、冷/暖模式、预算、种子来源、选中plan、官方response、可用时间。下表文件名是PR38导出器的已核对名字；目录改变时由绑定适配，不要求其他Agent把结果搬回旧目录。

| 图表/用途 | 已有导出来源 | 核对条件 |
|---|---|---|
| 三问1–5核平均加速比 | `paper_data/mean_speedup_1_to_5_cores.csv`、`per_case_all_metrics.csv` | 每点固定同一图集合、逐图比再平均；显示count，不能用成功子集替代全体 |
| 第三问同方案无/有L2曲线 | `q3_same_plan_cache_pairs.csv` | 两种场景使用同一个第三问plan，均有合法response；分母同一原始单核基准 |
| 周期、额外COPY、Spill、字节命中率附表 | `appendix_q1.csv`、`appendix_q2.csv`、`appendix_q3.csv` | 字节字段口径不混用；空值不是0；不把不同策略的各例最低值拼入主表 |
| 真实时间—质量阶梯曲线 | `anytime_30_seconds.csv`与原improvement/progress记录 | 只纳入截止前已保存可用的结果，明确停止后持有；不同路径独立成曲线 |
| 候选成本与收益 | `candidate_attempts.csv`、`source_yield_and_cost.csv`、`optimization_phase_seconds.csv` | 构造是生成子集；原评估/审查/IO字段的包含关系写清楚 |
| 机制解释 | 原per_core_timeline、cache_events、COPY issue/complete及`per_core_pipe_utilization.csv` | 容量、Pipeline占用与缓存事件对齐；忙周期比例不是可加的Makespan归因 |
| 图结构与表现关系 | `graph_features.csv`及原始图 | 配置相关下界带q/n，不把首次遇到配置的bound当该图所有配置通用特征 |
| 条件消融 | 独立diagnostics记录 | 同起点、同机同预算，记录保留的基础候选；不能把诊断优胜解偷偷替换固定主策略 |

第一、二问的n=1点按PR38导出约定为原图单核基准，值为1；第三问n=1是实际有L2方案与原图无L2基准之比。正文或图注正面说明这一实验定义。

按PR38正式方案，一百图需要每图1个原始单核基准、第一问4个核数、第二问4个核数、第三问5个核数，共1400条主记录，另500条第三问同方案无L2记录。这是完整性要求，不是本包确认已经完成的实验数量。

## 5. 主结果集合的冻结

不要采用“从所有旧PR里给每张图取最低周期”作为某一新算法的正式结果。可以维护两种清楚分开的集合：

1. 固定算法、版本与预算协议实际跑出的主实验集合。
2. 有明确原plan和原response支撑的累计最好方案集合。

累计最好集合有实际应用价值，但它的取得成本和组成方法可能不同。主文选择其一时应明确研究对象；另一集合放独立表，不能用同一图例暗示一次统一运行。

本轮结果尚未到齐时，继续完成模型、证明、算法解释、术语和图表脚本。生成待补证任务清单；终稿摘要和结果结论在数据完整性与版本语义核对后定稿。旧报告中的数值不自动成为占位值。

## 6. 学术表达约束

正文用客观叙述，例如：“在给定时间预算内维护当前最好可行方案；每项候选均按同一执行规则评价。”避免写成“我们不声称全局最优”等反复防御性句式。若需说明适用条件，直接给出模型假设、预算与算例范围。

先定义后使用，同一对象始终使用相同名称和符号。可以定义本研究的新数学符号，但不能把新命名包装成已有学界理论。保留必要的学术引用、前提、负结果与实验限制；去模板化润色不得改掉事实、偷换结论或隐藏与主张直接相关的证据。

示例方法段（按最终绑定源码复核后使用）：

> 针对任务边界、片上驻留与共享带宽之间的耦合关系，本文在统一方案空间中组织多邻域迭代改进。结构邻域调整子图粒度和核心映射，驻留相关邻域控制数据的同时存活范围，缓存时序邻域通过合法核内重排改变读取相对于填充与驱逐事件的位置。候选均由同一离散事件执行模型评价；只有目标改善且可行的方案才更新当前解。来源选择依据实际评价收益与生成、评价成本，并保留基础候选的搜索机会。

## 7. 增量修订Agent的触发规则

每次被要求更新论文时，先读取旧绑定和新的运行/源码清单，按以下变化类别处理，不后台自动改稿：

| 变化 | 必需动作 |
|---|---|
| 仅代码/结果目录迁移 | 更新路径与读取适配；核对语义一致，保持理论定义 |
| 新结果到达，执行版本不变 | 核对原plan/response、覆盖数与预算；重算图表及结论，保留旧稿 |
| 候选顺序、停滞阈值或时间预算改变 | 新运行单列；同步更新算法伪代码、参数与搜索效率实验，不混合轨迹 |
| 来源算法、变量范围或Task/FIFO/Spill语义改变 | 重新核对THEORY相关定义、证明前提及源码映射，先产出差异说明 |
| 只有报告分数，没有原方案/响应 | 登记待取证，不把数字合入正式表 |
| 发现理论包与真实题目/执行版本矛盾 | 以题目及真实版本事实为准，修订绑定和相关理论；不能为服从旧文字而篡改结果 |

变更记录写在内部`THEORY_CHANGELOG.md`；文稿只体现修订后的定义、方法和事实。
