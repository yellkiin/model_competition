# memory-coherent-4.4：结构感知修复实测

## 结论

本轮是在已合并的 memory-frozen-3.0 基础上继续优化，父方案直接采用已经保存并通过官方评估的可行解，不重复旧成绩评估。新增候选全部由未修改官方评估器验收。

主五核样本为 036/048/068/084/085/086/097 × 三问，共 21 个配置：16 个 Makespan 严格下降，5 个保留父方案，0 个最终选中退步。

## 084：从失败机制到结构规则

084 有大量彼此独立的小计算组件，且几乎没有跨组件共享外部参数。v3 的全图深度分带把大量独立链同时打开：Q2 从 391,700 恶化到 1,305,922，额外搬运 49,856,640 B，其中 Spill 39,931,008 B。

|候选|官方 Makespan|added COPY|Spill|
|---|---:|---:|---:|
|父方案|391,700|9,925,632|0|
|v3 全局深度分带（历史失败）|1,305,922|49,856,640|39,931,008|
|完整组件归核、逐链执行|503,472|0|0|
|容量受控波前，1.0 包络|292,272|0|0|
|容量受控波前，1.5 包络|286,992|0|0|
|选中波前，2.0 包络|285,686|322,560|322,560|

零 Spill 不是最优目标。最终方案允许少量 Spill，但恢复更多计算重叠，反而比零 Spill 的 1.5 包络更快。Q1 没有沿用整组件迁核收益，候选没有战胜 392,541，因此保留父方案。

|配置|共同父方案|v3继续优化|v4继续优化|

结果是 v4 3胜1平0负。提升不只是因为多给了搜索时间；同时 085 的平局表明 v4 仍应作为候选源与完整 Anytime 组合，而不是独立替代。

## 兼容性

COMMON 入口仍是 propose(g,n,cfg,q,incumbent,feedback,deadline)。新增 make_proposer(Options(...)) 支持联合求解器关闭重复自由度，例如结构线已经做核迁移时设置 allow_core_migration=False。

trusted_run.py 仅增加可选 --plugin 参数，默认旧 epochs/local 行为不变。Windows 入口 run_adaptive_v4_windows.ps1 直接复用同一 warm-start 运行器。

## 失败和负结果

本轮不是只保留胜例。大量合法候选比父方案慢，最终选择器全部拒绝；“至少不恶化”指最终 incumbent 保护，不是声称所有裸候选单调改善。084 的全局分带历史失败和整链串行失败都保留为方法设计证据。

Q3 同方案 no-L2 仍应在正式100图运行时逐个保存。小样本中缓存相对比值并非每图上升，因此没有把 Makespan 改善等同于缓存指标改善。

## 文献

新增重点阅读 A08 IOS、A31 Parallel Scheduling of DAGs under Memory Constraints、A46 Iterative Graph Optimization；与原 A16/A17/A18/A39 一起形成“受控并行宽度 + Tensor 集合 + 无环局部变换”的方法。论文自由度均按题面裁剪，官方 Spill、FIFO、图和 Tensor 不变。
