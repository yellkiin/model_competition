# Memory-1.3 独立实测：边界、驻留与 COPY 排队

## 结论与交付范围

**发现可迁移的局部收益，但不支持替换完整 ORION Anytime。** 主试验六图 × 三问 × 二/五核 × 冷/暖 × 旧/新，共 **144 条有效选中方案**；Q3 的 **48 条同方案无 L2 对照全部有效**。暖启动严格比较 36 对：5 胜、15 平、16 负，旧 Makespan / 新 Makespan 的几何均值 **0.987155**。冷启动排除两对旧臂被总截止截断的记录后，34 对为 1 胜、8 平、25 负，几何均值 **0.895814**。比值大于1才表示内存线更好，不能把这两个小于1的值包装为整体提升。

实际样本是 **002、016、044、071、059、083**，来自已经取得的完整官方附件。它是替代的开发小样本，**不是完成了优先指定的 005、051、073、090、092**。后五张图及067的完整输入、最新 day01 原始包未无损进入本会话运行环境；没有手工改写/缩小图，不把只读到的 CSV 成绩写成重评结果。原定优先样本门槛未通过，因此不启动100图、不给全量性能保证。

代码在本目录实现 COMMON 候选接口并导入旧求解器，不改公共 solver/campaign、原图/config/官方评估器或其他研究线；没有三线最终汇总代码。独立 PR 不自动合并。较大原响应的实际交付位置见 EVIDENCE_INDEX.json。

## 2. 环境、协议、截止与成本

Linux、CPython3.13.5、CPU-only，CPU配额4核/内存4GiB；主对照请求workers=2。同一机器、原config、相同并发政策，NPU核数是2/5，与workers不同。每配置冷启动先生成独立轨迹；暖启动先用完整旧版最多8次评估、60秒取得公共种子，两臂再原评估核对。每臂追加上限300秒、最多24次候选评估；内存线可因有限邻域穷尽提前停止，旧臂也可因自己的停止条件提前结束。调用数与墙钟上限均相同不表示实际用时相同，不据此宣称执行速度提升。

初次总截止1800秒；115条已有效、29条从未开始时触发。随后明确设置追加900秒总截止，**只补29个从未启动的冷作业及尚未完成的24个无L2配对**，实际315.639秒结束。没有重启、延长或重置已有搜索轨迹。两个已经启动而被总截止打断的旧臂（059 cold Q3n2、Q1n5）保留有效方案，但在 comparison.csv 中 same_budget=False，排除于34对冷启动严格汇总。原状态保存在 completion_history。

不同类实际独立作业墙钟求和（并发时间不可当实验经过时间）：36个种子649.692秒，72个暖启动1611.290秒，72个冷启动1712.478秒，6个原始基准54.841秒，48个无L2配对116.600秒。两个假想方法的端到端曲线各计完整种子成本；实际实验总成本只取得每个公共种子一次，不重复均摊。构造、生成、原评估、输出、配对字段见完整 per_case.csv；上游只提供生成与I/O合并项时保持原口径，不编造拆分。

主搜索执行版本memory1.3/adapter1.3，冻结源码在结果包。交付adapter1.4修正外部种子严格重评、进程启动偏移、原始一核、WindowsRSS接口、从未启动恢复，另在真实044运行24条固定一核/二核冷暖记录+8配对，以及4条外部种子/auto workers记录+2配对，全部有效。**没有Windows3.12实测**。144主表后来只用1.4汇总器重导出，未重新搜索；original_exports_v13保留旧导出。

本地ORION依赖是连接器所读函数体暂存副本，部分注释/文档字符串缩减，并非字节相同的完整Git checkout。旧/新两臂共享它，官方评估器完整取得且未修改；PR导入仓库现有ORION，不提交此临时依赖。后续Windows需在完整checkout上重做优先六图对照。

## 4. 好坏原因与修正过程

### 044：更多Task也可能更好，但粗方案改善不是完整旧版胜利

最初3候选构造的component_pack为132892周期，5个Task，partition3721600、Spill2474432、added6196032字节。v1.0只有合并等邻域，没有可用改进；v1.1加入同核DFS连续分块仍无收益，均保留。v1.2改为已有块内部的共享参数消费者依赖深度分带：reuse_bands_4使Task增至20、核归属完全不变，Spill降0，partition略增至3834240，总added下降为3834240，Makespan降至91528。带数2为93025、带数8为91697，后者较差也保留，不只报道最佳点。

原图11个分支共享若干73728字节参数（如1000000043/45等）。分带把不同分支同层消费者聚近，缩短Task内驻留；Q1边界增加的代价小于Spill与执行时序改善。不能把它解释成“Task越少越好”。然而完整旧版续跑在044Q1n5可到80506，新臂82514；正式day01甚至69212，所以这个机制探针并未打破已有最好成绩。

暖启动Q1n2则出现真正同机旧新收益：70712→67654（4.3246%）。Spill61440→0，但added1081952→1299552**增加**，Task4→30、没有改变核归属。观察到无任何计算重叠的COPY区间并集24247→15230周期；这是执行重叠改变的证据，不是可直接从Makespan相减的关键路径分解。冷启动Q1n2也从70712→64776，是冷34对中唯一胜例。

### 083：相同核集合/边界，顺序变化仍能改变Spill、缓存与Makespan

暖启动Q1n5旧246770、新243253（1.4252%），added5494144→4991360，Spill527360→0。新方案20组，相对共同种子只186算子换核，旧方案19组、2697算子换核；不能仅由“换核少”推出好坏，但原响应支持新方案少掉了本例的Spill。

暖启动Q3n5共同种子215741周期、124组。内存线获胜候选`residency_pull_1000001145_70`为187171，比同机旧臂203767短8.1446%；核归属和124组不变，pre-Spill搬运仍6659040字节。新方案Spill1769472，大于旧臂的0；但总added6990208小于旧8446336、缓存字节命中率0.55469大于旧0.14745，无任何计算重叠的COPY区间并集847而旧16511周期。

**同方案无L2揭示收益条件**：新方案无L2为224482，反而慢于旧方案无L2的212355；打开原配置L2后排序反转为187171<203767。因此本例不是普遍“驻留缩短必定更快”，还依赖同一合法顺序所诱发的缓存与重叠。没有改FIFO算法，也不能用缓存命中率单独替代Makespan。

### 044 Q3与071：少搬运、少Spill仍可能退步

暖启动044Q3n2内存线56011，旧49647，内存线慢12.82%左右；新Spill110848比旧376832小，新added1141344比旧1426016小，但旧L2命中率0.33754、新0.15491。无L2新58511也不优于旧58090。优化驻留/搬运不能保证FIFO时序和计算重叠更优。

v1.2原时间线发现Tensor1000000113从源0到目标4，COPY_OUT结束1377，COPY_IN释放1877，却到45028才发射，即43151周期队列等待。v1.3据此只尝试前移已有消费者子图；未改COPY队列控制。这个事实是候选方向，不是“全部等待都能被消除”的证明。071暖启动5负1平、冷启动6负，说明在短作业上该有限局部邻域和早期切换不能覆盖旧版结构/顺序候选；不写图号分支弥补。

### 059与016：相似的无收益，完全不同的原因

059Q3n5两臂150455，可信界147558.4，U/L≈1.0196，只有约1.96%的松弛差距。两方案虽有较长单条COPY排队，却都只有727周期COPY完全不与计算重叠；同方案无L2也都150455。盲目追加预算或按最大排队值分配优先级不值得。

016两臂全部6配置7715523周期、0额外搬运、0Spill；n5下界1542995、U/L约5。选中方案仍只有一个计算块，计算负载集中一核，完全无计算重叠的COPY只有548周期。这是结构并行度尚未打开，不是内存超容量。内存线保留停止/负面结果，不越界重写全局划分框架。

## 6. 后续修正，不用无效扩大掩盖问题

本轮已实际做v1.0→1.1→1.2→1.3机制修正，并用1.4适配器验证真实一核/外部种子/并发入口。下一步应把插件作为已有优质方案的候选补充，不作为冷启动替代；其冷启动三次旧评估后切换过早是已见的主要短板。尚未实测的整合收益不得事先宣称。

先按LOCAL_AGENT_PROMPT取得原定005/051/073/090/092/083和正式种子。在同机、同配置、同预算下续优化，查092具体父子方案，把省边界与省Spill分开。关注峰值发生时的物理活跃集合、已有DDR备份、目标核COPY队列与计算重叠，但任何诊断不得改变官方Spill算法。Q3尤其保留同方案无L2排序，避免把缓存依赖的局部收益当成普适内存收益。

当前没有新的理论最优证明，没有新的红蓝卵石强界，也没有平均加速比承诺。正式三问、一至五核、500条第三问同方案对照要求未取消；须在优先小样本门槛通过后另行执行。
