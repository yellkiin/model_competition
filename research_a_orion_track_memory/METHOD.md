# Memory-1.3：边界与驻留的局部修复

本目录只改变 `node_to_subgraph`、`core_schedules`。`plugin.propose(g,n,cfg,q,incumbent=None,feedback=None,deadline=None)` 遵循 `../research_a_orion_review_3pc/COMMON.md`，返回 `name/family/plan/proxy/bounds`，族名前缀 `memory/`。插件不调用评估器；独立运行器调用原 `OfficialSession`。不改变公共求解器、图、Tensor、算子周期、地址、Spill策略或FIFO策略。

## 1. 先把搬运计数的所有者弄对

对张量 t，大小 s，令 P、C 是生产者与消费者所在的所有者集合。Q1 的所有者是 Task/子图，不是核；Q2、Q3 的所有者是核。

Q1：读次数 `|C-P|`；写次数 `sum(p in P: terminal(t) or C-{p} 非空)`。同核的不同 Task 也要付边界复制和等待。Q2/Q3：每个不同源核—目标核的有序对各有一读一写；无计算生产者的输入按消费者核读；终端输出按生产者核写。`tensor_ledger` 按张量身份与集合去重，不把一个生产者的多个同核消费者逐边重复计费，也不把超图的 `(lambda-1)` 当成官方 COPY 数。

这里是固定方案的 **pre-Spill scheduled bytes**，不是 Q3 的物理 DDR 字节。共享 DDR 的公平分带宽、COPY 排队、计算重叠、L2 命中均由原事件评估决定。最终排序以 `(Makespan, added_copy_bytes)` 为字典序，搬运只是同周期的次级指标。

## 2. 已实现的局部候选

**固定核归属的复用分段（reuse_bands）**：在已有粗子图内部，按局部依赖深度分成 2/4/8 个带，核归属不变。它使不同分支对同层共享参数的消费更接近；只在观测到 Spill 或尚无正式反馈时提出。Q1 多出 Task 边界，同时缩短每个 Task 的驻留范围；Q2/Q3 仍是整核 Task，只改变合法子图优先级，不能声称清空了整核内存。保留按 DFS 连续切块的 pressure_chunks 作为失败/无收益对照。

**同核凸合并**：考察同核序列相邻块，按共享 Tensor 量优先；既有单对，也有不重叠配对的局部批量合并。每次均过 `plan_view`，拒绝收缩造成的商图或核顺序环。不是把“同核”当成“可以任意合并”。Q2/Q3 零 Spill 时限制单合并候选数量，避免反复正式评估几乎等效的分组；这是有限预算启发式，不是等价性证明。

**消费者集合迁移**：从有实际生产者和消费者的张量中选择候选，最多联合移动三个完整消费者块；重算源/目标集合而不是只移动某条边。候选可增加负载不平衡，必须由官方 Makespan 决定。1.3 修正了先截取最大张量、再排除外部输入造成的候选饥饿：现在先筛适格张量，再排序截断。

**COPY 排队修复**：读取原响应中的 `copy_in_start-copy_in_release`，只将已有消费者子图尝试前移到本核合法位置。没有改 COPY 队列、插入延迟指令或改 FIFO 缓存控制器。排队和之中可能有重叠，绝不能直接从 Makespan 扣去它。

**驻留拉近与峰值窗口**：将同核生产/消费块拉近；在共同拓扑序的至多八块连续窗口上做子集 DP，目标先最小化最大标准化 L1/UB 活跃前沿，再以超额面积破同分。前沿忽略块内执行和插入 COPY 的物理生命周期，所以是代理，不是官方峰值或可行性证明；不以平均内存替代容量。

每轮最多 48 个结构尝试、有限代表轮转；新方案必须结构合法，再交原评估。拒绝、无收益及较差的正式尝试均保存。四轮上限、24 次正式调用上限是这次适配器的实验设置，不是本题的最优性结论。未实现三个方向的最终联合选择器。

## 3. 可信界与接受

只使用既有 `core.bounds` 的计算负载、保留计算依赖路径、必需 I/O 和固定方案必要条件界进行排除。内存、缓存、COPY 排队近似不进入认证下界。`U/L` 是当前可行上界相对可信松弛界的后验范围，不能称为理论最优或固定近似保证。粗单核方案零 Spill、零额外搬运仍可能远离多核可达界；016 的本轮结果正是反例。

## 4. 冷启动、续优化与时间

旧臂调用现有 Anytime `solve`；内存冷启动先用旧构造流程至多三次评估，再做本目录候选。10 秒只是旧启动阶段的软准入参数，单次官方评估不能在函数内部安全抢占；外层进程截止覆盖总预算。续优化的种子先单独取得并记录成本，两臂都用原评估器重评，不把种子成绩免费计入冷启动。

固定轨迹只从已经完成并保存的正式事件取 30/60/120/300 秒前缀。提前穷尽或达到调用上限后，较晚时间点标为 stopped_carry_forward，不是又运行了 300 秒。构造、候选、正式评估、输出、Q3 同方案无 L2 配对分别记录；上游旧版只暴露部分生成与 I/O 的合并时间，缺失分量不编造为零。CPU workers 与题目 NPU 核数是两回事。

## 5. 本轮假设被推翻的部分

粗方案上省掉 Spill 有用，不代表能战胜完整 Anytime；“少搬运”也不总能缩短完成时间。044 的固定核复用分段使零 Spill 成立，却仍有相当的边界代价；暖启动二核的更快方案反而增加搬运。083 Q3 的更好方案保留相同核归属和 pre-Spill 边界，但 Spill 增加，仍比本轮旧臂快。详见 REPORT 与原响应。
