# memory-frozen-3.0：固定规则与证据边界

本版冻结的是候选规则，不是把前两阶段报告中表现最好的数值倒填为新实验。`policy.py`、`reuse_repair.py`、`local_repair.py` 在 `frozen_curve_20260925/source/` 留有运行前快照。新实验完整使用同一份源码、原配置和候选顺序，不按图编号或核数重调参数。

## 目标与接口

Q1/Q2 的正文要求是 1–5 核的逐核平均加速比曲线，不是只比较五核，也不是把五个核数再平均成一个比赛指标。对图集合 D，曲线点是 `mean(T1_i / Tn_i)`，不是 `sum(T1_i)/sum(Tn_i)`。Q1/Q2 原始单核定义保持为 1。Q3 的同方案 no-L2/L2 比值必须另外报告；其 T1/Tn 只作辅助分析。

两个候选模块均实现 COMMON 接口：`propose(g,n,cfg,q,incumbent=None,feedback=None,deadline=None)`。返回字典含 `name,family,plan,proxy,bounds`；`plan` 仅两个官方字段。现有 `plugin.py` 的旧接口继续保留，实际冻结入口是 `continuous_run.py`，依次调用两个候选模块；没有改公共 solver/campaign 或第三条线的 FIFO 控制器。

## 固定参数

|规则|固定值与准确语义|
|---|---|
|近界停止|官方可行 U / 可信 global lower ≤ 1.04。用于停止投资，不宣称最优。|
|阶段|epochs → local；同一个作业进程、同一个截止时钟，不把两个独立预算拼成冷启动曲线。|
|调用上限|epochs 至多16次新官方调用，local至多24次；全程至多40次。失败调用计数；安全界剪枝不消耗调用数。|
|固定核分带|深度层数候选8/16/32/64/4/128；保留每个原操作的核归属。|
|Q1凸合并|三个scale由原循环前插，实际尝试顺序8/4/2；至多3轮；每次商图及核顺序检查。|
|容量触发分带|共享外部L1参数集合累计量，阈值0.5/0.8/1.0×L1容量。它不是活跃峰值证明，也没有代替UB容量检查。|
|局部迁移|原子为整个已有子图，边界负载修复最多2/4/8步。|
|层级批次|仅有多个原计算连通分量时，cohort5/10/20与32/64层组合。|
|局部顺序|至多160个不同构造尝试、保留代理前24；张量热点前20，移动距离1/3/6；窗口宽8。|
|选择|比较官方整数 `(makespan,added_copy_bytes)`。周期下降、仅平分省字节、完全保留分别计数。|

`search_state.family` 是诊断标签，**不是新的数据驱动候选切换器**。除近界停止和原有Q1/多连通分量条件外，所有图使用上述固定阶段；不能把“有Spill才会试epochs”写成已经实现的规则。

## 张量集合计费，而非逐边求和

设张量大小为 s，P/C 为生产/消费单元集合。Q1 的单元是 Task，即子图；Q2/Q3 是核。

Q1 pre-Spill 读字节为 `s*|C-P|`，写字节为 `s*sum(terminal or C-{p}非空 for p in P)`。同核不同 Task 仍然属于不同计费单元，不能靠搬到同一核就假定免费。

Q2/Q3：没有计算生产者的外部输入按消费核数读；终端输出按生产核数写；每个 p≠c 的生产核—消费核对需要一写一读。Q3 缓存只改变执行时实际读服务，不改变这个 pre-Spill 构图口径。

最终用原 `planned_traffic` 重新计算完整候选的集合代价。凸合并内部的共享 touched-tensor 字节只用于启发排序，之前注释把它称为 exact savings 不准确，本次已纠正。Spill 和FIFO命中都不包含在上述精确 pre-Spill 计费中。

## 无环性、驻留与局限

固定核分带按 `(component-cohort,depth-band,switch-rank,core)` 打包。同一层带内部每条跨核依赖都使 switch-rank 严格增加，因而不会经另一核绕回原组。每个候选仍经过 `plan_view`，并由原官方执行合法性检查确认，不能用商图检查代替 Pipe/FIFO/容量检查。

`_peak_window` 优化的是分组边界上的 L1/UB 活跃前沿，不包含组内瞬时分配以及官方插入COPY的全部生命周期；它既不是平均内存，也不是官方物理峰值重放。官方Step2/3原样执行，官方报告的容量峰值与Spill才是成绩证据。禁止重算、改Tensor大小、自由Spill选择、地址重排和插入delay。

## 时间与父方案

每个case/q/n只有一条实际运行轨迹。阶段A候选生成器固定从初始种子构造；阶段B固定从阶段A已接受的最好方案构造，不会在同阶段每次改善后重建整个候选空间。旧 `attempt.parent_name` 字段表示该次评估前的 incumbent 名称，不应误认成该生成器的源父方案。

新候选只有在完整原响应保存并被接受后才出现在时间前缀。30/60/120/300 秒从事件列表取已完成前缀；提前停止后只延续已有值。端到端前缀包含原发布 seed_solve_seconds；在种子成本之前没有可用方案，不用零值或最终值填补。种子读取/图恢复是输入准备，原求解成本不能清零或均摊。总实验还包括Q3对照、导出和启动开销。

新实验只做用户指定的可信旧种子续优化。旧冷启动运行器保留，但本次不是旧新同机等冷启动预算比较。不得用本次增益宣称新方法全面替代旧ORION。
