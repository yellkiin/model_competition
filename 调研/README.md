## 选题时的实际取舍

有图优化和软件工程经验的队伍可优先考察 A。其评估接口明确，适合把创新落实为可复现的运行时间和通信量改进，但图规模及全场景批量评估需要尽早估时。不能用附件的随机方案生成器作为唯一性能基线。

具有物理建模和控制基础的队伍更适合 B。它的论文可以沿“单电池验证—电堆扩展—固定策略优化—反馈控制”展开，逻辑完整，但数值求解稳定性和缺失参数的可辨识性是关键门槛。若没有能通过验证的单电池模型，不宜直接投入复杂控制器。

C 适合愿意做严谨机制论证与信号处理的队伍。题目要求解释视觉刺激到观测脑电的过程，单纯训练分类器不足以答题。三个额区 EEG 通道能够支持的潜在机制有限，应比较多个可解释模型并报告不确定性，不能用背景中提及的疾病应用代替本题实验结论。

D 适合擅长运筹优化、GIS和约束检查的队伍。优先做一个物理和资源规则完全可行的方案，再优化及时性、能耗与架次数。第四问是冻结第三问方案后的分区资源核算，必须继承已有任务而非另起一套更优调度。

E 适合有深度学习实验经验及可用训练环境的队伍。附件已提供特征，可先以较小融合模型建立有效基线；第一问仍需完成给定100条原视频的特征提取与对齐，不能被预提取特征替代。解释性实验需要验证删除重要片段是否改变预测，以及证据是否能对应回原视频。

F 不要求训练大语言模型，适合统计建模和优化能力较强的队伍，但不能因此低估工作量。质量信号需全量处理，数据来源和可比性决定广义标度律是否成立。建议先用真实观测建立可信基线，再将半合成数据用于假设和敏感性检验；不能混合拟合后宣称获得真实因果规律。

## 六题共用的论文组织方式

1. **问题与数据。** 解释各小问的递进关系，给出数据字段、单位、缺失情况、样本或任务划分和来源边界。
2. **假设与基线。** 只写会影响结果的假设，说明如何检查；先给出简单、可运行、可比较的基线。
3. **模型与求解。** 定义决策变量、目标、约束或生成机制。公式中的每个参数都需有来源、估计方法或敏感性范围。
4. **验证与结果。** 区分训练拟合、验证选择和独立测试。报告全部规定场景，不只展示最好样例；失败实例同样具有解释价值。
5. **消融与稳健性。** 逐项移除新增机制，检验改进是否来自关键建模选择；对噪声、预算、初值和关键参数做敏感性分析。
6. **结论与适用范围。** 回答每个小问，报告可以由数据支撑的结论。尚未验证的延伸方向放在展望中。

每题的详细目录、建议图表、实验矩阵与阅读次序见对应报告。正式论文应以团队独立推导、真实运行结果和引用原文为基础，保留 AI 在资料检索、整理和调试环节的使用记录；具体披露按所选题面要求完成。

## 建议的前三天工作

| 时段 | 目标 | 可检查的产物 |
|---|---|---|
| 0–8小时 | 读题、核对附件、建立统一口径 | 小问清单、字段与单位字典、不能擅自修改的条件 |
| 8–24小时 | 跑通最小模型并估算算力和时间 | 一个端到端可复现基线、失败日志、资源需求 |
| 24–48小时 | 实现主要改进并进行对照 | 固定划分和种子的基线对照、核心结果表、可行性检查 |
| 48–72小时 | 消融、稳健性、解释和写作 | 图表、误差与约束分析、论文初稿及复现说明 |

这是准备阶段的组织建议，应按实际比赛时长和队员分工调整。数据预处理可以先行，模型复杂度需服从可验证性和时间预算。
