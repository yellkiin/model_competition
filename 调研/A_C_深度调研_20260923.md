# A/C 深度调研：方法论、可验证方向与执行建议

日期：2026-09-23。本文建立在仓库现有 A/C 基础调研之上，重点补充“可形成论文贡献的方法”“如何验证”“哪些方向值得做、哪些不值得优先做”。正式数据未提交 GitHub，因此本文把验证分为：可在任意机器上完成的合成/单元验证，以及需要队伍本地原始附件才能完成的正式验证。

## 0. 结论先行

A 题更适合以“结构感知图聚类 + 内存/通信感知分核 + 官方仿真器闭环搜索”为主线。不要把纯强化学习放在第一优先级。官方评估器具有非平滑、离散、共享 DDR 争用、Step2 spill、Step3 内存复用补边等复杂机制，最稳妥的创新是构造强代理指标，再用真实评估器做局部改进和候选筛选。

C 题建议升级为“三层联合模型”：形态保持预处理/鲁棒分解 → 低维神经群或状态空间生成层 → 单试次 EEG-选择-反应时联合认知层。相比只做 ERP 平均和分类器，这条路线更贴合题目“计算模型”和认知机制要求，同时能通过留出预测、参数恢复和后验预测检查进行严格验证。

本地合成实验支持两个判断：A 中单独追求跨核切边会牺牲负载均衡，因此建议 Pareto 或 ε-constraint，而不是固定权重单目标；C 中 Robust PCA/Principal Component Pursuit 对“重复 ERP + 稀疏伪影”合成数据能够显著降低恢复误差且基本保持主峰位置，可作为问题 1 的可验证候选。

# 1. A 题：进一步的方法论

## 1.1 把官方评估器视为黑盒目标，构造三级代理

正式目标始终是官方 makespan。建议搜索中使用三级成本：

1. 一级：极廉价图特征代理，用于大量候选的筛选；
2. 二级：近似事件/内存模型，用于几百到几千候选；
3. 三级：官方评估器，用于最终几十到几百候选。

廉价代理不要只统计跨核边数。建议使用：

- 核负载下界：每核 Cube/Vector/MTE 工作量与总 cycles；
- 关键路径长度；
- 张量切边字节数，并按 fan-out 去重；
- tensor lifetime pressure：生产到最后消费者的拓扑跨度 × size；
- L1/UB 独立峰值近似；
- scene A 的 task boundary 次数；
- scene B 的跨核 tensor bytes；
- scene 3 的共享只读输入复用距离近似；
- pipe mix imbalance：不同 core 上 PIPE_M / PIPE_V / MTE2 / MTE3 的比例差。

最近系统研究强调：DNN 图调度不能只看计算量，memory traffic、memory reuse 与硬件结构会决定性能。Welder 用 tile traffic cost model 统一考虑跨算子和算子内数据复用；MLSys 2023 的静态内存工作强调并行执行下 tensor lifetime 与安全复用约束；2024 年结构感知 DAG 调度工作也说明结构特征本身值得直接进入分配与调度策略。这些思想与本题官方 Step2/Step3 的行为高度对应，但必须以官方实现为最终真值。

参考：
- Welder, OSDI 2023, https://www.usenix.org/conference/osdi23/presentation/shi
- Safe Optimized Static Memory Allocation for Parallel Deep Learning, MLSys 2023, https://proceedings.mlsys.org/paper_files/paper/2023/hash/676d8419c61f299feb88c28b40edd3b1-Abstract-mlsys2023.html
- A Structure-Aware DAG Scheduling and Allocation on Heterogeneous Multicore Systems, IEEE SIES 2024, DOI 10.1109/SIES62473.2024.10767927

## 1.2 主方法 A1：Pareto 图聚类 + 列表调度

把每个非 COPY op 初始看作一个 cluster，定义两个主要代价：

- 计算不平衡：max_core_load / mean_core_load；
- 通信/内存压力：跨 cluster tensor bytes、长生命周期 tensor、L1/UB 峰值风险。

对候选合并 (u,v) 计算 delta：

score_merge =
  + α * reduced_boundary_bytes
  + β * increased_tensor_reuse
  + γ * pipe_complementarity
  - δ * critical_path_damage
  - η * memory_pressure_growth

不要固定一个全局 α...η 后直接报最优。建议保留一条 Pareto frontier：例如同一图保留 20–50 个不同“通信-负载”折中分区，再进入官方 evaluator。

为了保证商图无环，可以优先使用：
- 拓扑连续 interval clustering；
- dominator/post-dominator 启发；
- series-parallel / motif 合并；
- 每次 contraction 后 Kahn 检查。

分核采用 critical-path-aware list scheduling。优先级可用：
rank_u(v)=cycles(v)+max_succ(rank_u(succ)+comm_proxy(v,succ))
再结合：
- 当前 core pipe load；
- tensor producer affinity；
- DDR 拥塞代理；
- UB/L1 pressure。

这比纯 HEFT 更贴本题，因为“处理器”同构但 pipe、内存和共享 DDR 并不等价于传统同构多核模型。

## 1.3 主方法 A2：ε-constraint 而非固定加权和

本地合成 DAG 验证显示，仅优化“负载+较强通信惩罚”的局部搜索，切边字节显著降低，但最大核负载上升。固定加权和很容易在图间失效。

推荐做法：
- 先设负载约束：max_load <= (1+ε) * ideal_load；
- 在满足约束的方案中最小化通信/驻留压力；
- ε ∈ {0.05, 0.10, 0.20, 0.35} 形成候选族；
- 最终用官方 evaluator 选择。

也可以反过来限制 cut bytes，再最小化 makespan proxy。

这能在论文里自然解释为多目标组合优化，并通过 Pareto 图展示“过度通信优化”与“过度负载均衡”两种失败模式。

## 1.4 主方法 A3：官方 evaluator 驱动的局部搜索

候选操作建议：

- move：一个 cluster 从 core a 移到 b；
- swap：交换两个 core 的 cluster；
- merge/split；
- reorder：同核两个无依赖 cluster 交换；
- chain contraction；
- replicate-read affinity：把共享只读输入消费者在 scene 3 中靠近；
- memory relief：拆分导致长 lifetime 的 cluster。

每次邻域动作先做廉价合法性检查，再跑官方 evaluator。使用：
- tabu cache：方案 canonical hash → makespan；
- first-improvement + occasional best-improvement；
- deterministic seed；
- 限定 evaluator 次数，例如 500/1000/2000 次三档预算；
- 按图规模自适应 budget。

论文里必须报告“达到最终成绩用了多少次真实 evaluator”，否则搜索成本不可复现。

## 1.5 可选增强 A4：学习型 surrogate，而不是端到端 RL

纯 RL 的问题：
- 正式图只有 100 个；
- reward 是昂贵 evaluator；
- 图规模/拓扑异质；
- 一次动作会引发 Step2/Step3 非局部变化；
- 比赛时间内难以证明泛化。

更推荐训练一个 ranking surrogate：
输入 graph/partition 特征，预测候选 A 是否优于 B，或预测 Δmakespan。
模型可从 LightGBM/XGBoost 开始，不急着上 GNN。

训练数据来自搜索过程中自然产生的 evaluator 日志。每个图几十到几百条方案即可形成数千样本。重点不是绝对预测精度，而是 top-k recall：便宜模型能否把真正好的候选留在前 10%。

如果时间充裕，再试 GNN encoder + pairwise ranking。2023–2025 的 DAG/GNN 调度研究说明 GNN 能编码结构，但这些论文的动作空间、通信模型和本题不同，只能作为方法启发，不能直接宣称适用。

## 1.6 Scene 3 专门方向：FIFO Cache reuse scheduling

问题 3 最有论文味道的创新是“访问时序感知”，而不是只看 tensor 是否共享。

为只读 DDR 输入 t 定义：
- consumer set C(t)
- size s(t)
- reuse distance d_t between accesses
- FIFO occupancy estimate Q_t
- concurrent cache bandwidth pressure

近似命中收益：
benefit(t) ≈ s(t)/60 - s(t)/250
但只有预计仍驻留 FIFO 时才计入。

调度中鼓励同一共享输入的消费者在时间上聚集，但需避免：
- 把多个高带宽输入同时拉进来导致 cache bandwidth 拥塞；
- 为复用牺牲关键路径并行度；
- 大 tensor 把小而高频 tensor 提前逐出。

可以用“reuse window”邻域：只调整若干无依赖 cluster 的局部顺序，并对每个候选直接读取官方 cache hit/miss 统计。

## 1.7 A 题正式实验矩阵

每个核数 2–5、三个问题场景，至少比较：

- single-core official baseline
- random/stub（仅格式参考）
- topo-block + round-robin
- topo-block + load-balance
- HEFT-like
- A1 聚类+列表
- A1 + ε-constraint
- A1 + evaluator local search
- 可选 surrogate-guided search

消融：
- 去掉 tensor bytes
- 去掉 lifetime pressure
- 去掉 pipe balance
- 去掉 critical path
- 去掉 local search
- scene 3 去掉 reuse window

除了平均 speedup，建议报告：
- median / geometric mean / worst-case；
- cut bytes；
- spill bytes；
- cache hit bytes；
- evaluator calls；
- wall-clock search time；
- failure/illegal count。

# 2. C 题：进一步的方法论

## 2.1 数据条件决定模型必须“低维 + 可辨识”

只有 Fz/F3/F4 三个原始 EEG 通道，256 Hz。任何大规模源定位、复杂连接组网络、几十参数 neural mass 都高度不可辨识。

建议始终区分三层：
1. 观测层：三导 EEG；
2. 功能状态层：2–4 个 latent population/state；
3. 认知层：evidence accumulation / memory / response。

模型目标应是“解释和预测观测”，不是“恢复真实脑区”。

## 2.2 主方法 C1：形态保持 Robust Low-Rank + Sparse + Smooth

问题 1 的一个强路线：

X = L + S + E

优化：
0.5||X-L-S||_F^2
+ λ*||L||_*
+ λ1||S||_1
+ λt||D2 L||_F^2

解释：
- L：跨试次稳定的诱发/任务响应子空间；
- S：眨眼样、突发、大幅稀疏伪影；
- D2：抑制不合理高频曲率。

注意：持续肌电或漂移不一定稀疏，因此同时保留温和带通基线。

本地合成验证（80 个试次，ERP jitter + Gaussian noise + 漂移 + 随机大幅脉冲）：
- raw MSE ≈ 0.6174
- RPCA MSE ≈ 0.0608
- 相对误差下降约 90%
- clean / raw / RPCA 主峰 sample 为 96 / 97 / 97

这是“算法机制可行”的合成证据，不是正式数据结果。

正式数据必须进一步比较：
- ERP split-half correlation；
- 250–500 ms 候选正成分的 amplitude/latency；
- 左右条件差异效应；
- 留出分类/预测；
- 被剔除/稀疏成分比例。

参数选择必须只在训练块进行。

## 2.3 主方法 C2：状态空间 / Neural Mass 生成模型

比纯 Wilson-Cowan 更建议使用“可辨识优先”的层次：

latent state z(t):
dz = f(z,u,θ)dt + Q^(1/2)dW

observation:
y(t)=H z(t)+baseline(t)+ε

f 可以比较三档：
- 线性延迟状态空间 / VAR；
- 2-population Wilson-Cowan；
- 简化 Jansen-Rit / neural mass。

不要求复杂模型一定胜出。用 held-out likelihood / prediction error / posterior predictive check 比较。

关键限制：
- H 固定尺度约束；
- 大多数动力学参数跨左右条件共享；
- 左右只开放少数 input gain / lateral bias；
- 时间常数使用合理范围；
- 用 profile likelihood / bootstrap 展示参数不确定性。

近期 neural mass 工具（例如 eCOALIA 2024）说明从神经群到 EEG forward model 可以系统化，但本题只有三导，不宜照搬 whole-brain 模型。

## 2.4 主方法 C3：单试次 EEG–Choice–RT 联合模型

这是 C 题最值得新增的方向。

2023 年 Ghaderi-Kangavari 等提出 integrative neurocognitive framework，把单试次 EEG 指标与 drift-diffusion parameters 联合描述，并通过 simulation-based inference 估计无闭式似然的联合模型。

本题可以做一个更轻量、比赛友好的版本：

trial i:
drift_i = β0 + β1 * neural_feature_i + β2 * direction_i + b_record
ndt_i   = softplus(γ0 + γ1 * early_latency_i)
bias_i  = δ0 + δ1 * memory_state_i

choice_i, RT_i ~ WienerDDM(drift_i, boundary, ndt_i, bias_i)

其中 neural_feature_i 不必手工取单一峰值，可以来自：
- C2 latent state 的积分/峰值；
- 预定义窗的 first PC；
- 250–500 ms slope/area。

如果完整 Wiener likelihood 实现时间紧，可用：
- HDDM / pyddm（本地装包后）
- simulation-based likelihood
- quantile probability method

最重要的是做“联合是否真的比行为-only 好”的留出检验。

比较：
- behavior-only DDM
- EEG covariate → choice logistic + RT regression
- joint DDM

指标：
- held-out choice log loss
- RT quantile error
- calibration
- timeout probability
- posterior predictive checks

## 2.5 记忆任务的模型不要直接声称海马信号

如果题目 Task 2 涉及记忆或规则转换，可用 latent memory state h：

dh/dt = -h/τ + κ * event(t)

然后让 h 调节 drift 或 starting bias。

模型能说明“一个缓慢记忆状态变量能够改善数据解释”，不能说明“Fz/F3/F4 测到了海马”。

## 2.6 事件解析是 C 题最值得先写代码的部分

正式分析之前先生成 trial table：
- cue onset
- cue direction
- response onset
- response side
- RT
- correct / error / timeout / repeat
- file / task / block
- trial start/end

需要把 VisCue 的持续电平压缩成事件起点，不能每个非零 sample 当一次事件。

Task 2 的 correctness 必须按题目定义的映射计算，不能假设 sign(cue)==sign(response)。

正式 train/test split 应以连续 block 为单位，所有来自同一 trial 的窗口进入同一 fold。

## 2.7 C 题统计与稳健性

推荐：
- 记录内 block CV；
- leave-one-record-out；
- 若无法确认被试身份，不写 leave-one-subject-out；
- bootstrap 单位用 trial block / record，而非 sample；
- latency/amplitude 多时间点探索使用 cluster permutation；
- 预定义窗口和探索窗口分开报告。

误差条优先报告 bootstrap CI，而非只给标准差。

# 3. A/C 的“创新性”该怎么写

不要把“用了某算法名字”当创新。论文贡献建议写成：

A：
1. 建立官方硬件机制一致的多层代理成本；
2. 提出 Pareto/ε-constraint 的切图-映射联合搜索；
3. 以真实 evaluator 驱动局部改进，并显式统计搜索预算；
4. 针对 FIFO cache 提出 reuse-window 调度。

C：
1. 以保形指标而非平滑程度选择去噪；
2. 在三导条件下使用受约束低维生成模型并报告可辨识性；
3. 联合建模单试次 EEG、选择与反应时；
4. 把错误、超时、删失纳入同一验证框架。

# 4. 选 A 还是 C 时的技术风险

A 的主要风险是工程量和 evaluator 吞吐；优点是目标函数明确，可快速做真实闭环。
C 的主要风险是统计样本量、事件映射和生理过度解释；优点是论文叙事空间大，模型创新更容易写出“机制层”。

如果正式 A 数据能在本地快速批量跑 evaluator，我建议优先把 A 做成一个强 baseline + local search，在半天内观察真实 speedup 分布。若 A evaluator 单图耗时很高或频繁遇到不可行方案，则 C 的联合模型路线更适合集中投入。
