# A 深度方法报告：先保证可执行，再优化真实数据移动

2026-09-23。文献编号见 [LITERATURE.md](LITERATURE.md)，代码/验证范围见 [README](README.md)。本文区分**实现**、**数值/结构验证**和**待研究**，不报告未经运行的正式分数。

## 1. 相比基础调研，重点推进什么

既有调研已经提出 HEFT、无环聚类、张量亲和与官方仿真搜索。本轮不重复“加一个遗传算法/强化学习”的泛化建议，而将路线收敛成：

**有向超图表示通信 → 拓扑保序分块保证基础合法 → 多尺度方案组合 → 官方评估驱动的合并/拆分/迁移 → 固定方案的 Cache 对照。**

这是一个可逐层增加复杂度的优化器，而非自己重写评分器。当前交付已包含这一骨架和批处理入口；真实驻留代理、带宽时间线拟合和前沿状态搜索仍属于扩展。

### 三问不能套同一通信代价

题一每子图一个 Task，同核不同 Task 也不能免掉搬运；题二同核子图合为一个 Task，分核改变了张量驻留和跨核通信；题三在题二之上加入只读 FIFO Cache。最终执行还包含官方核内调度、内存额度复用依赖及 Pipe FIFO。依据：仓库 A 附件 README、`contest_io.py`、`stub_multicore_cut_and_schedule.py`、`schedule_step2.py`。

固定参数应从 config 读取。既有核验值为 L1=524288 B、UB=131072 B、共享 DDR=60 B/cycle；题一跨核/同核等待为 1000/100 cycle，题二跨核 COPY 延迟 500 cycle；题三 Cache=1048576 B、独立带宽 250 B/cycle。它们不是可调超参数。代码不将 DDR 带宽按核数复制，不修改 cycles、size、pipe 或原图。

## 2. 方向一：超图通信代价，而不是逐边收费

[A-HYP] 的关键可迁移点是：一个生产结果可以有多个消费者，通信不宜通过每条普通 DAG 边独立相加表示。对唯一生产 Task 为 p、消费者 Task 集合为 C 的张量 t，可构造代理

$$\widehat B_t=s_t\bigl(|C\setminus\{p\}|+\mathbf1[C\setminus\{p\}\ne\varnothing]\bigr).$$

第一项对应各远端消费 Task 的一次读，第二项对应需要外传时的一次生产者写。外部输入没有生产者写项。题一这里的 Task 是子图；题二是核心。这只是搜索代理，不计 Spill、别名、多次重载和 Cache 时序；真实值必须以官方 `data_movement_bytes` 为准。

**本地反例。** 一个 1024 B 张量扇出到三个算子：若它们属于同一个远端 Task，上式为 2048 B；属于三个远端 Task 时为 4096 B；逐边各算一次读写会得到 6144 B。该实验验证了集合去重的必要性，并不声称官方所有图的流量恰好服从上式。实现：`boundary_bytes`；测试：`test_fanout_deduplicated`。

下一步应从官方 Trace 提取“代理值−实际流量”的误差，并按原输入重用、跨核中间量、Spill 重载分别归因。若误差与生命周期/扇出高度相关，再增加对应特征，而不是先上大代理网络。

## 3. 方向二：把可执行性当成搜索空间的设计约束

### 3.1 可证明的安全部分

取计算操作的一个全局拓扑序，按连续区间切成子图。任意跨子图依赖都从较早区间指向较晚区间，因此商图无环；每核也按这个区间顺序执行，加入这些子图级核内顺序后仍不产生回边。代码先沿 COPY 路径收缩依赖，不能删除 COPY 节点后把两侧计算依赖也删掉。

但是，这个证明**没有涵盖官方 Step3 新增的 Pipe 顺序、内存 WAR/WAW 依赖和跨核 COPY 同步**。基础校验通过不应被命名为“保证可执行”。每个候选都要经过真实 CLI；失败日志本身就是研究数据。

另一个基本反例是链 0→1→2：把 0、2 合并，留下 1，商图便出现 A→B→A。原 DAG 无环不保证任意聚类无环。实现测试同时覆盖这个反例和 COPY 收缩。

### 3.2 已实现的搜索

优先级使用计算部分剩余关键路；额外生成固定随机种子的拓扑序。切分规模覆盖核心数、2/4/8 倍核心数与单操作级别；分核含轮转和 Pipe 工作量/张量亲和代理。题一不奖励同核跨子图的缓存复用。

初始池探索后，以一定概率从**当前官方最优方案**生成合并相邻区间、拆分区间、迁移子图的局部候选。每次重建恰好覆盖全部计算操作的方案，检查基础约束，规范化哈希去重，再调用原版评分器。缺少新候选时提前停止；非法结果不参与选优。

目标是字典序 `(official makespan, official physical DDR bytes)`，后项缺失时退回 scheduled COPY bytes。整图式候选首先评估，作为可保留的低风险起点；它仍必须通过官方执行检查。超过 2000 个计算操作时跳过单操作粒度的全量亲和扫描，避免这一代理的二次开销；不跳过单操作轮转候选。

代码没有承诺全局最优，也没有把标准 HEFT 的插入式最早结束时间分核完整移植过来。当前 rank/负载选择只是受 [A-HEFT] 启发的确定性候选器。

### 3.3 值得研究但尚未实现的冲突学习

官方等待环能返回类型化边。可把失败候选中的“若干特定分核＋核内排序选择”抽成局部禁配模式，减少重复评估。但是**一个坏方案不证明其中任意单个合并/分核动作永远坏**，不能直接对节点对打永久黑名单。保守做法是记录完整候选签名；进一步学习必须验证冲突子集足以复现环。衡量指标是同等合法评估预算下的最优分数及失败调用减少量。

## 4. 方向三：优化驻留“面积”和并行损失，而非只看峰值

[A-MEM] 提供了内存感知调度和驱逐的参考，但其科学工作流模型与本题固定时长、异类 Pipe、统一 DDR 并不相同。[A-WELDER] 的跨内存层数据访问视角可借鉴，不能把 tile 重写直接带入本题。

建议下一层代理同时跟踪两个量：

$$P_{k,r}=\max_t M_{k,r}(t),\qquad A_{k,r}=\int M_{k,r}(t)\,dt,\quad r\in\{L1,UB\}.$$

峰值接近容量说明溢出风险；驻留面积大说明长期占用。两个候选可以峰值相同但生命周期差异很大。尤其“把大张量的全部消费者塞到同核”可能减少跨核字节，却让关键路串行或加重 UB 驻留。

可定义局部合并的筛选量

$$\Delta\widehat T=\text{同步与搬运节约}-\text{并行损失}-\text{预期 Spill 代价},$$

只作为排序或淘汰明显劣解的依据。不能把并发重叠的成本机械相加后当作真实 makespan。应在少量真实评估之后画出该量与官方差值的散点及误排序率，再决定是否值得继续精化。

对一个**已执行的固定方案**，可由实际图关键路、各 Pipe 工作量、实际 DDR/60、L2 命中字节/250 解释瓶颈。实际流量随方案变化，这样的解释性界不能当作所有分区共享的最优性证书。

## 5. 方向四：题三研究“何时请求”，不仅是“谁共享”

L2 是 FIFO，不是 LRU。容量为两个等大条目的序列 `A,B,A,C,A`，FIFO 只有一次命中，LRU 有两次；命中 A 不会把它在 FIFO 队列中移到末端。实现了这一最小反例，但它不是官方多核 Cache 模拟器的复刻。

可检验假设是：将同一原始输入的消费者在时间上聚集，在不严重阻塞计算 Pipe 的前提下提高复用。但同时发出大量命中 COPY 也可能拥塞独立 L2 带宽；请求数、命中字节、DDR 减少量与总时间不必单调对应。中间结果是否可缓存严格依官方定义，不泛化为“所有跨核量均可命中”。

**实验必须拆开两种增益：**

$$G_{cache}(P)=T_{P2}(P)/T_{P3}(P),$$

$$G_{joint}=T_{P2}(P_2^*)/T_{P3}(P_3^*).$$

前者固定方案隔离硬件 Cache 效果，后者包含重新优化方案的作用。批处理已实现前者的配对回放；分别优化得到的结果也保存在各场景目录，可另行计算后者。不要把两个比值混为一谈。

## 6. 两个有潜力的高阶方向

**前沿宽度受限的动态规划/束搜索。** 不按全图节点数衡量难度，而按拓扑扫描时未完成消费的张量前沿衡量。状态至少含前沿依赖、核尾部时刻、分层驻留摘要；从短窗口中求局部最优，再拼入全局方案。[A-IOS] 支持算子间调度的动态规划思路，但不能宣称其状态压缩对本题直接有效。FIFO、地址复用与全局 DDR 的历史依赖会破坏过度简化的状态等价。

**小型精确对照。** 用 [A-CP] 的区间/NoOverlap 概念做受限子问题，或枚举极小图的划分/分核/核内顺序并交官方评分。必须声明精确的是哪个限制域：若额外禁止 Pipe 重叠、把通信强制串行，得到的是更受限模型的最优值，不自动是官方问题下界。此路线适合验证启发式的局部缺口，而不是承诺对 100 张大图求全局最优。

## 7. 实验与选题闸门

本地结构实验覆盖 20 个合成 DAG、1–5 核、三个问题、每组合至多 12 个候选，共 3,600 个结构可接受方案，另有连续 200 次变异测试。CLI 成功/失败/超时、输出目录防覆盖、LFS 指针拒绝、基准来源匹配、Cache 同方案对照均经过 mock 集成测试。**真实评估器在本环境未运行；这些结果不能证明无官方等待环或任何加速。**

建议先在一张图、2 核、题一、6 次候选预算跑通，再检查较小/较大、宽图/窄图、Cube/Vector 不同比例等代表实例，最后以统一预算覆盖 100 图。主汇总为每图先求比值再平均；附加最差值、几何均值、失败率、搜索开销和实际调用数。不能静默跳过失败图，也不能用 ratio-of-means 替代平均加速比。

消融应先做：轮转 vs 亲和；无局部改进 vs 有局部改进；同一真实评估次数下不同拓扑/粒度；题三固定方案无/有 Cache。未来增加驻留代理后，再单独消融峰值项和面积项。正式得分差异应给逐例配对表，避免只展示好看的平均数。

**A 的选题闸门：** 若低预算候选在所有代表图均能稳定通过官方执行，且能从 Trace 解释优势/差例，A 适合作为主线；若合法性失败主要来自未理解的核内等待环，先修这一层，不急于加入更复杂的搜索。正式数据恢复后才能判断当前候选器是否真的优于朴素基线。
