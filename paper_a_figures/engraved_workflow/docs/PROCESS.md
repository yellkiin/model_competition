# 作图过程与复核记录 · 2026-09-26

> 本文件保留第一版黑白源母版的制作记录。当前展示、编辑和排版请使用 [第二版 ink_v2](../ink_v2/README.md)；第二版来源与制作说明见其 `docs/`。

## 1. 内容拆解

解压用户论文包，读取论文三问、方法补充、缓存事件补充、术语账本、理论对齐记录、已绑定算法和实际来源选择实现。查看原题中的计算图与硬件对象。访问仓库确认理论快照相同，并选择独立目录提交。未打开旧总流程图作为布局参考，未复制旧绘图代码。

## 2. 重建图的结构

把“介绍模块”的图重构为“同一对象经历操作”的图：左侧二部图与联合决策，中间四种候选来源，右侧固定执行器剖面，底部完整评价与回流。四个来源共同依赖一份当前最好状态；不表现为四个独立求解器。将第三问同方案对照单独放在输出侧。

先确定 A–D / o1–o6 / t0–t6 的对应关系，再绘制迁移前后核心序列、驻留区间重排、FIFO 候选窗口。保留有效下界的严格大于号、可行性与字典序严格接受等关键条件。

## 3. 本地矢量构建

使用 Python 标准库写入 SVG；不调用直接生图服务。用具名分组管理语义模块，用真实 text/tspan 保留文字与数学上下标。基础组件包括张量格、带细分刻线的算子节点、虚线子图包络、三维薄片、核心剖面和收束曲线。主箭头只有一条语义路径；邻近细曲线表示该路径的线刻外形，不表示额外依赖边。

主版黑、白、灰，不使用大面积彩色面板、渐变或装饰性图标。实黑仅用于本轮操作对象等关键位置。排线用于子图内部、存储侧面、管线活动块与数据对象，不添加无意义花纹。

## 4. 迭代修订

实际修订包括：将基础来源案例改为与主图一致的六算子拓扑；修正候选迁移后的核心序列；明确下界等号保留；明确 Q1 同核跨子图也经过 DDR；区分 COPY_IN 发射查询与完成填充；把 L2 命中读线接到读取管线一侧；修正数学上下标；拉开驻留标签、候选汇流箭头、L2 注释与步骤文字；移动底部回流避免穿过接受条件；去掉重复且与主路径相撞的标签；修正张量网格图案的填充属性。

## 5. 检查与导出

`build.py` 先生成 SVG 与样式页，再运行 8 项单元测试，随后由 Inkscape 导出 PDF、6000 像素 PNG 和预览。测试涵盖：分组完整且互斥；两套核心序列唯一归属且合图无环；迁移保持分组；驻留示意遵守依赖；拆分不丢失/重复算子；FIFO 提议位于假设窗口；SVG 有可编辑文本且不含 image/script/foreignObject；关键术语与严格筛选条件。

用 Inkscape `--query-all` 检查对象是否超出 3000×2120 画布。用 Poppler 将 PDF 渲染为 PNG，按输入图、候选来源、执行器、底部反馈分别放大查看，并查看样式页。修订文字相碰、线条穿字、网格填充及字距问题后重新构建。`pdfinfo` 检查页数和尺寸，`pdffonts` 检查字体嵌入。视觉检查与结构测试分别记录，不以测试通过替代人工看图。

检查范围是图件表达、可编辑性、机制示例一致性和渲染质量。本次未重跑论文实验，也未新增实验结论。

## 6. 包装与维护

交付包括母版、矢量 PDF、高分辨率 PNG、样式页、生成器、案例语义、测试、方法对照与本记录。PR 使用独立分支；原有论文、求解器、评估器、旧图与实验数据不变。CI 只为本次同仓库专用分支提交生成图件，不自动合并。

以后修改某个方法：先更新 `SOURCE_MAP.md` 中的对应依据与案例语义，再改具名模块和测试；构建后同时检查母版与 PDF。手工编辑 SVG 与代码生成版分开保存，避免下次构建覆盖手工改动。
