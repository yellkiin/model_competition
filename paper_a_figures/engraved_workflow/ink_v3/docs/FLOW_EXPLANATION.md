# 图 1.1 第三版：流程图的详细说明

## 这张图要表达的核心思想

这套方法不是先把图切好、再独立分配核心、最后单独优化缓存，而是把**子图划分、核心归属和核内子图顺序作为一个完整方案共同优化**。在给定计算图、问题编号和核数的条件下，算法维护一份已经验证的当前最好方案，从若干互补来源提出候选；候选通过低成本筛选后，必须进入统一执行模型重新计算。执行结果既决定是否保留候选，也为下一轮的结构、驻留与缓存时序改进提供依据。因此，全图的主线是“完整方案—候选改进—执行评价—反馈更新”，而不是逐条展开程序的条件分支。

图中三个大模块从左向右阅读，底部回路表示预算内的持续改进。最后的输出框表示搜索结束后的交付结果。所有算子、时间条和缓存窗口均为机制示意，不是某张真实算例的运行轨迹。

## 01 联合决策：优化的是一份完整方案

左上角保留第二版的六算子案例。原图记为 $G=(T\cup O,E)$，张量通过依赖边连接算子。图示将非边界算子分为四组：$A=\{o_1\}$、$B=\{o_2,o_4\}$、$C=\{o_3,o_5\}$、$D=\{o_6\}$。子图包络表示哪些算子被放进同一组，下面的两条核心轨道表示这些子图如何归核和排序：图示初始方案将 A、B、D 放在核心 $k_1$，C 放在核心 $k_2$。

完整方案写成 $x=(\mathcal P,a,\pi)$。其中，$\mathcal P$ 决定子图如何划分，$a$ 决定每个子图属于哪个核心，$\pi$ 决定各核心上的子图先后顺序。子图划分必须覆盖待分配的非边界算子，不能遗漏或重复；每个子图也只能在一个核心序列中出现一次。原始计算工作与依赖关系被保留，任务边界所需的 COPY 操作则随方案和执行规则重建。

这三项决策彼此关联。合并子图可能减少边界搬运，却也可能降低并行度；把子图迁移到空闲核心可能改善负载，却可能增加跨核通信；改变核内顺序可能缩短张量驻留，也可能改变缓存读请求的时机。因此，图中没有把“划分”“归核”“排序”画成三个互不反馈的阶段，而是把它们汇入同一个当前方案。

当前方案必须经过完整验证。初始构造产生的方案或同配置的已有方案，只有通过完整执行验证后，才能作为后续改进的基点。这里的“同一当前方案”指一个固定图、问题编号和核数配置内部的共同状态，不表示第一、二、三问必须共用同一份最终优化结果。

## 02 多邻域迭代改进：不同来源围绕同一方案协同搜索

中间的四个小图不是四道依次执行的工序，也不是四个互相独立的求解器。每轮选择一个可用来源，综合考虑近期改进收益、生成和评价成本等因素，分配有限的搜索机会。基础构造可以继续探索新的完整方案；依赖当前方案的局部来源则随方案和执行轨迹更新。

**基础构造。** 围绕原始计算图探索不同分组粒度，并结合关键路径和负载映射形成完整候选。小图用同一组算子的不同包络表示分组尺度的变化，强调算法不只在某一个初始划分附近微调。

**依赖结构与负载。** 通过迁移、交换、拆分等方式调整子图分布和顺序，平衡串行依赖、可用并行度、负载与通信。图中 B 从 $k_1$ 移到 $k_2$ 是一次迁移的示意；$B\rightarrow B_1\mid B_2$ 表示还可以探索拆分。它们是候选操作的例子，并不表示每一轮都要同时执行迁移和拆分。右侧处理器上 A、D 与 B、C 的排布延续了“B 迁移到 $k_2$”这一示意。

**驻留数据重组。** 根据张量关联和当前执行中的驻留情况，调整分组或核内子图顺序，使相关计算更靠近，尝试缩短张量从产生到最后使用之间的跨度，从而减少片上容量压力及不必要的换出、取回。图中较长的跨越弧线变成较短弧线，用来表达这种思想。是否真的减少 Spill，仍由固定执行规则决定，不能仅凭示意图或工作集代理判定。

**FIFO 事件时序，仅用于 Q3。** 在这一来源中保持划分 $\mathcal P$ 和归核 $a$ 不变，只调整完整子图的核内顺序 $\pi$。图中阴影表示一次缓存驻留窗口，$f_t$ 和 $e_t$ 分别表示图示的填充与淘汰边界；将原读取时机 $s_t$ 调整为 $s'_t$，表达的是“让复用有机会落在有效驻留期间”。这些时刻只是提出候选的依据。方案变化会重新改变发射、完成、换出和淘汰的交错，所以不能把旧窗口当成新方案必然命中的保证。

四类来源最终都输出完整候选 $y=(\mathcal P',a',\pi')$。候选先经过结构预检、去重和有效下界筛选，再进入完整执行。结构预检可排除覆盖、归核或依赖合图方面的问题，但结构无环并不等于整个执行一定可行。下界和代理的作用是减少不必要的评估，不替代最终完成时间。

## 03 统一执行评价：把局部变化放回整体环境中检验

右侧保留第二版的核心剖面、流水线、L1/UB、共享 DDR，以及第三问的只读 L2。这个模块要说明：一个局部看起来合理的变化，必须放回包含计算、存储和通信争用的执行环境中，才能判断是否真正有效。

三个问题共享完整方案的表示，但执行规则不同：Q1 以子图为任务；Q2 以核心为任务；Q3 在 Q2 的核心级任务规则上加入共享只读 L2。图中顶端的 Q1/Q2/Q3 是执行场景的区别，不是算法按顺序运行的三个步骤。

对候选方案重新建立任务与边界搬运，按固定规则处理存储分配和自动换出、流水线顺序及全局共享带宽事件。DDR 读写共享题定的带宽池；Q3 中读入命中可以走 L2 服务路径。L2 按发射时的缓存状态查询，读完成时尝试填充，命中不刷新 FIFO 位置。图面没有列出每个执行器步骤或全部等待常数，这些属于论文模型和实现细则，而不是总体流程图需要展开的主线。

评价的主目标是总体任务执行时间，即 $C_q(y)=\max_{j\in J_q(y)}f_j$。这里的操作集合包括新方案执行规则产生的相关边界搬运与换出、取回操作。图内使用 $\max_j f_j$ 的简写。减少某一项搬运量、缩短某个局部等待或增加缓存命中，不一定缩短整图最后的完成时刻，因此必须以重新执行得到的整体结果评价候选。

## 底部反馈回路：持续保留更优的可行方案

执行结果返回共同状态。新候选完整执行可行并改善比较目标时，更新当前方案及其执行记录；否则保留原方案。原方法的比较规则仍然是周期优先、周期相同时额外 COPY 字节较小者优先，即比较 $(C_q,D_q)$ 的字典序。第三版只是把这一实现层面的判断菱形改为“保留更优可行方案”，没有改变算法的接受规则。

接受新方案后，相关局部来源围绕新的方案和执行轨迹重新提出候选；不依赖父方案的全局构造仍可保留探索进度。这使得不同来源能够接续彼此的改进，而不是各自完成搜索后才在最后汇总。

图中把跨模块连接压缩为四条：当前方案进入候选改进，候选进入执行评价，执行结果沿一条回路返回共同状态，搜索结束时输出结果。内部图中的依赖箭头、迁移箭头和读写路径仅解释局部机制，不增加外部控制流程。

## 输出及 Q3 对照的含义

达到预算或其他停止条件后，输出已经完整评价并保存的最好方案、相应执行记录及指标。“最好”指本轮搜索已验证方案中的最好者，不是对全局最优的无条件保证。该流程图不新增算法性能结论，也没有把图示当成重新运行真实算例的证据。

Q3 的有无 L2 对照放在输出侧：固定同一个第三问选中方案，分别在有 L2 和无 L2 的环境中执行，可以计算 $C_2(x_3)/C_3(x_3)$。这一步用来分析固定方案下的缓存影响，不回到主搜索的接受判断，也不等于比较两问分别独立优化后的方案。

## 可配合论文使用的图下注释

图 1.1 联合决策与多邻域迭代优化框架。方法以子图划分、核心归属和核内顺序构成完整方案，通过基础构造、依赖结构与负载调整、驻留数据重组及第三问的 FIFO 事件时序候选开展互补搜索；候选经低成本筛选后，在统一执行模型中重新评价，并依据执行结果更新当前最好可行方案及其轨迹。搜索结束后输出已验证方案与指标，第三问另对固定方案进行有无 L2 的配对分析。图中局部结构与时间窗口为机制示意。
