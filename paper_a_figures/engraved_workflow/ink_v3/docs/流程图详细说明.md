# 图1.1第三版：联合决策与多邻域迭代的总体思路

## 读图主线

这张图表达的是：**把子图划分、核心归属和核内顺序放在同一个方案中，利用互补的候选来源探索改进，再以完整执行结果决定下一轮搜索的起点。** 三个大区从左向右对应“怎样表示方案”“怎样寻找改进”“怎样计算方案代价”；下方只有一条反馈回路和一个输出区。图不是代码流程的逐行转写，也没有把三问画成必须依次执行的三个算法。

## 1. 联合建模：三项决策共同决定一份方案

左侧延续第二版的六算子依赖示例。A、B、C、D是子图，圆形节点表示算子；为了突出依赖与分组关系，第三版省略了原二部图中逐个张量节点，画的是算子依赖的概念投影。它不是某个官方算例的实测结果。

划分P决定哪些算子属于同一个子图，归核a决定子图放在哪个核心，顺序π决定同一核心上的子图先后。三者组成完整方案x=(P,a,π)。图中的核心序列只展示分配与先后关系，矩形长度不代表运行时长，也不代表子图具有相同计算量。初始方案可以来自构造或已有方案，但进入搜索前需在当前配置下验证。

联合考虑三项决策，是因为划分更细通常会提供更多可调度单元，同时增加边界搬运；把相关子图放在同核，可能增加复用机会，也可能牺牲并行空间并加重片上容量压力。核内顺序又会影响张量生命周期和请求时机。因此，不能仅凭分组大小、核心负载或搬运字节中的某一项选择最终方案。

## 2. 多邻域迭代：互补来源共享一个当前方案

中间四张卡片是一组可选择的候选来源，不是四个顺次执行的步骤，也不是四套各自独立收敛的算法。每轮根据来源的可用性、近期收益、生成与评价成本以及剩余预算选择一个来源，围绕共享状态提出候选；基础构造还保留探索其他初值与粒度的机会。

**基础构造**通过不同分组粒度和初始布局探索方案空间。卡片上下两组图元只说明相同算子可以有不同分组，不包含性能比较。

**结构与负载**通过子图迁移、交换、拆分及关联移动调整并行空间和交接关系。示例将B从一个核心移向另一个核心，说明改变的是完整子图的归属和相应顺序，不是删除依赖。

**驻留与通信**围绕张量的生产者、消费者以及活跃区间提出迁移或重组。图中同一张量t关联两个子图，突出复用关系；是否真正减少搬运、是否引起自动换出，由相应问题的执行规则决定。特别是第一问中，同核跨子图边界仍经DDR，不能把图示理解为三问都允许免费跨子图复用。

**缓存时序**只在第三问开放。它保持P和a不变，通过调整完整子图在π中的位置，使相关读入有机会落在完成填充与首次淘汰之间的有效驻留窗口。图中窗口内外的两个圆点及回弯箭头表达调整前后的目标方向，不代表对同一请求任意指定发射时间，也不是已经测得的改善。顺序改变后，新的填充、淘汰和读入时刻要重新计算。

四类来源生成的候选先做结构预检、去重及有效下界筛选。图面将这些操作合并为一个短条，因为它们的共同作用是减少无效的完整评价；具体覆盖条件、不等号和队列维护留在论文方法部分。

## 3. 统一执行评价：在共同决策空间内区分三问

右侧Q1、Q2、Q3是当前问题所对应的执行场景，按问题选用，不是三个连续处理阶段。Q1以子图为Task，跨子图数据经DDR交接；Q2以核心为Task，同核子图可在容量允许和固定执行规则下延续驻留；Q3保留核心级Task，并增加共享只读L2及FIFO规则。

两个核心与L1、UB、DDR、L2构成的是资源结构示意，内部小横条不是实测甘特图。DDR承担共享读写服务，L2是第三问额外的共享只读服务池。两者并排画出，避免把L2误画成所有请求必须经过的串行环节；无箭头的资源连接线表示共享关系，不表示数据只沿某个方向传输。

完整执行评价综合依赖、容量、流水线占用与带宽竞争，重建候选方案的执行事件并计算完成周期。目标仍是总体任务执行时间（Makespan）最小，周期相同时再比较额外COPY字节。这一目标保留在图中，但原来的“04 可行且字典序严格改善？”菱形被删除，不再让程序分支占据总图的主要空间。具体实现仍只保留可行且字典序改善的结果；删去图形判断框没有改变算法。

## 4. 反馈与输出：由执行结果引导下一轮

下方唯一的回路表示执行结果回到候选搜索：接受改进后，更新共享的当前方案及相关执行记录，以新状态继续提出局部候选。没有改进时保留原方案；与父方案无关的全局构造保留探索进度。反馈也用于调整不同来源后续获得的搜索机会。

搜索在预算、质量界、来源耗尽或停滞等条件满足时结束，输出已验证的调度方案、执行指标和搜索改进记录。第三问另对选出的同一份方案进行有L2与无L2配对，保持P、a、π一致以观察固定方案的缓存影响。该对照放在输出区，既不接回主搜索的接受判断，也不拿第二问独立寻优的方案充当同方案对照。

## 本图保留与移出的内容

保留联合方案、互补来源、结构与下界筛选、分场景执行、统一目标和反馈更新。删除底部图例、接受/停止菱形、逐步执行器名称、同步等待常数、来源选择公式及密集条件箭头。它们是从总图移到说明或正文中，不是从方法中删除。

六算子分组、迁移、共享张量和缓存窗口均为机制示意；本次没有新增实验、修改成绩、训练模型或改变求解算法，也未把参考CAD论文中的SFT、GSPO等环节引入调度方法。
