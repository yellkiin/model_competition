# 固定运输中继 CP-SAT 与支配删列：独立代码审查

审查日期：2026-09-23。仅审阅 `outputs/run_radio_cpsat_fixed.py`、`outputs/run_radio_dominance.py`，对照 `outputs/runtime/research_fd/d_radio.py`。未修改正在运行的脚本，也未用审查代替最终计划验证。本次另用 `.venv` Python `-B` 隔离提取 `dominant()` 函数执行两个边界反例；没有执行被审脚本的模块入口。

**结论：当前固定运输、60 s 会话资源网格下，覆盖、机身/能源累计容量、资源着色与分阶段保留 incumbent 的逻辑未发现阻断性错误；“严格/精确支配删列”需要收窄表述。浮点容差可改变极小尺度的目标次序，已实测构造反例。联合可行性仍须对最终计划进行细采样与导出检查。**

## 发现：容差支配不是严格支配

位置：`run_radio_cpsat_fixed.py:22–24`、`run_radio_dominance.py:19–22`。判定允许候选 A 比 B 晚返回 `1e-9 s`、多耗能 `1e-12 kWh`，因此不满足字面意义的“不晚返回、不增加能耗”。CP-SAT 又在第 57–59、65 行使用 `ceil(returned*1000)`、`round(energy*1e9)`，跨取整边界时可多一个目标整数单位。

已实际执行的最小反例（资源区间均合法、起止点为整秒，假设两列 covers 相同）：

| 字段 | A | B |
|---|---:|---:|
| 资源开始 / s | 60 | 0 |
| 机身结束 / s | 180 | 180 |
| 能源结束 / s | 240 | 240 |
| 返仓 / s | 119.0000000005 | 119 |
| 能耗 / kWh | 1 | 1 |

实际 `dominant(A,B)=True`，但毫秒向上取整后 A=119001、B=119000，A 的 CP 返仓目标差 1 ms。A 由于开始较晚在排序中先出现，B 可以被删除。第二个反例让返仓相同，A 能耗 `1.0000000005004`、B 能耗 `1.0000000004995`；同样判定 A 支配 B，而整数能耗系数分别 1000000001、1000000000。

影响：这是严格最优性/精度声明的问题，不是发现当前输出出现秒级错误或资源冲突。当前机身、能源端点在 60 s 网格上，端点容差不会改变不同网格点的包含关系。没有证据证明本次真实池触发了该目标边界案例。

建议：后续 CP 删列使用整数资源端点以及实际 `ceil`/`round` 后的目标系数比较；浮点 MILP 若要严格支配，使用无容差的不等式，或明确称“在声明容差内不劣”。不改正在跑的程序、不把已有可行结果作废。报告不要宣称该实现“严格保持所有连续目标的最优值”。

## 已核查的约束与模型对应

| 检查点 | 核查结论 |
|---|---|
| 固定运输合法性 | CP 入口要求 `fixed_starts`，检查硬违约、覆盖、重复和资源重叠。原 CLI 将同一个 jobs 列表及其路线传入。该后端不支持联合调时，不能作为 retime 后端描述。 |
| 通信覆盖 | 原 `demands_for_options()` 仅对直连失败的实际轨迹采样建立需求。每个需求约束 `sum(z_cover)>=1`；空覆盖集生成不可行约束，不会静默漏需求。固定运输下所有对应选项为必选，等价于原条件覆盖约束中 `x=1` 的情形。 |
| 接入与回传 | 复用 runtime 候选与物理 session_pool：候选点先通过回传门槛，会话 covers 再检查接入与服务时段。新脚本没有放松通信预算、修改能耗或删除不可达需求。 |
| 准备时间 | 官方会话 `departure` 是准备开始的资源占用时刻，真实起飞另外保存 `takeoff`。CP 占用从 departure 开始，与 runtime 语义一致，并未漏掉准备占用。 |
| 机身与能源 | 同一 `z[i]` 同时控制 `[departure,aircraft_end)`、`[departure,pack_end)` 两个 optional interval；累计容量分别使用 relay.count 与 relay.packs。没有把飞机数当成电池数或忽略回充占用。 |
| 半开区间与取整 | runtime 将两类结束时刻向上取整到 60 s 网格；CP 转为整秒且检查误差不超过 `1e-7`，不接受任意非整数网格。已读取当前 `.venv` OR-Tools `add_cumulative` 文档，其条件明确为 `start <= t < end`，允许一任务在另一结束时启动。与 runtime 网格占用的半开语义一致。 |
| 运输资源 | 固定运输不再增加 CP 累计约束是合理的：它不改 jobs，入口已检查固定计划资源。若以后允许改变运输出发，则必须重新引入运输的机身/电池资源。 |
| 目标 | 固定运输的迟到与能量是常数，删去常数后优化“联合返仓、再中继能耗”与原词典序方向一致。返仓下界包含全部运输返回；每个选中中继任务增加返回下界。返仓目标单位为毫秒，能耗目标单位为 `1e-9 kWh`。原始浮点实际值另存，不应把整数 objective/bound 直接当秒/kWh。 |
| 分阶段状态 | 每阶段有独立时限。前阶段 FEASIBLE 也会进入后阶段并固定其已知上界，因此可能只得到保留 incumbent 的修复，不能称词典序全局最优。后阶段 UNKNOWN 时 `chosen_ids` 保留前阶段解；未伪造后阶段成绩。 |
| Hint | 当前恰好两个目标，首次求解后添加一次 z hints，第二次求解前不存在重复 hints；第二次结束后的 hints 不再参与求解。以后增加第三目标时须清理/替换 hints。 |
| 资源着色 | 按开始时刻排序、分配最早可用资源，对于同型可互换、均从同仓满状态开始的半开区间成立：若所有资源都未释放，则该开始时刻并发量已超过累计容量。机身/能源独立着色与允许更换能源组件相符；若以后增加绑定或异地状态则不再充分。 |
| 截断 | 两脚本申请原池最多一百万列，并在触及上限后抛错，不将截断结果伪称完整。这里“未截断”仅指原生成器的有限候选池，生成器只枚举有限位置、服务起点及少数长度，绝非所有连续会话。 |

## 支配规则在无容差情况下的证明与边界

对覆盖集合完全相同的会话 A、B，若 A 的开始不早于 B，且机身结束、能源结束均不晚于 B，则 A 的两种资源占用区间分别是 B 的子集。将解中的 B 换为 A 保持所有采样覆盖、不会增加任一时刻累计资源；若 A 已在解中，直接删除冗余 B 即可。再要求 A 返回不晚、能耗不高，则两个目标均不劣。由此该规则对当前二元覆盖模型成立，且不要求 A/B 位置相同。

这里不能只依赖 `before==after` 的覆盖并集断言；并集相同本身不保证资源可行性。真正的理由是逐列具有相同 covers 与两种区间包含关系。脚本当前分组、排序、前沿删列实现对应上述逻辑，数值容差是上一节列明的偏离。

不同位置虽然拥有同一粗采样 covers，细采样、不同射线步长下可能覆盖不同。因此任何删列/CP 成功结果仍应运行更细通信验证；失败则重建更细需求及对应候选，不可凭旧 covers 证明连续通信。新 backend 也不改变 runtime 已有“会话覆盖半开、验证端点含容差”的数值约定。
