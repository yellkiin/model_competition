# Anytime Wu v4：结构触发尾核修复 + 真实 FIFO 时序续优化

本结果只使用未修改的官方 A 题 evaluator、原图和 config。v4 是 **warm-start continuation**：从已验证 incumbent 继续搜索，只有官方 Makespan/added-copy 字典序更优的合法方案才替换 incumbent；因此新候选失败或退步不会删除已有好解。冷启动性能单独保留，不与暖启动收益混为一谈。

## 1. 本轮结论

七个目标图 Q3/五核的最终选择为：001/059/084 保留正式 day01 方案，024/044/083/086 采用本轮 v4 官方实测改善。七图算术平均 `T1/T5` 从 **4.2245106 → 4.2501991（+0.6081%）**。若只把这四个已验证新方案替换进正式100图 Q3/五核表、其余96图完全不动，账本均值从 **4.2949348 → 4.2967330（+0.04187%）**；这是混合账本，不是100图重跑。

## 2. 024：结构特判为什么成立

024 是目标七图中唯一明显的尾核过载：正式 Q3/五核方案的每核子图数约 `[55,19,21,100,22]`，最慢核相对第二慢核晚约3.6%。v4 的 tail-rebalance 不读取 case ID；只有观测最慢核结束差≥1.5% Makespan，且该核 schedule 长度显著高于中位数时才生成候选。

真实离线候选扫参发现，将尾核子图 `s214` 移到两个较轻核都把 2,220,997 降至约 2,217,28x；该候选也是同批候选中 timing proxy 最低者。因此最终实现不是硬编码 `s214`，而是“最晚5个子图 × 两个轻核 → 同一 proxy 排序”。

同机、同正式 seed、20秒/16次上限：v3 **2,218,901**，v4 **2,217,280**，均5次官方评估；v4 再降1,621 cycles。结构流延后准入，修复了早期结构候选抢占评估位造成的42周期退步。

## 3. FIFO

v4 保留 consumer-window，并新增两个严格基于官方 cache event 的候选：`fifo_fill_advance` 找真实在途fill的读取者并前移其已有子图；`fifo_evictor_delay` 找真实驱逐事件并后移驱逐者已有子图。两者都不插入sleep/delay、不改FIFO/LRU或op时长。

044 从46,827到44,768；086从48,028到47,682；083小幅到180,934。024再次证明命中率不是目标：新plan命中约45.9%，同方案no-L2只慢0.1198%，主要收益来自结构/调度。

## 4. all-q 预算门控

024/044/059 的 Q1/Q2 五核暖启动，10秒/8次上限：024 Q1 2,323,699→2,322,592，Q2 2,225,709→2,220,008；044两问持平；059两问持平，059 Q2 由全局bound gap直接停止、0次新增官方评估。

## 5. 额外图048负结果

真实case_048做15秒Q3/五核冷启动：old=117,513，v4=124,681，v4明显更差。随后以old已验证117,513作为incumbent做同样15秒暖启动，v4=116,941，同方案no-L2=117,098。因此v4定位为**安全续优化器/候选池**，不是单独冷启动替代算法。

## 6. 证据边界

024最终20秒轨迹5次官方评估；044 12次、083 8次、086 5次。059 Q3使用认证剩余改善空间≤2.05%的预算停止，保留seed且0次新评估；这不是最优证明。084不宣称新v4分数，直接保留正式391,700。

Ansor(A12)只迁移有限预算/族探索；A42迁移incumbent改善后的局部刷新；A49/A39/A02支持结构异常下局部再平衡；COSMA(A16)用于区分访存/命中与Makespan；CADE(A40)的LRU周期模型不直接采用。
