**时间线计算口径**

- 核结束周期取 `per_core_timeline[].tasks[].end` 的最大值；各 pipe 忙量是该核 `ops` 中对应 `pipe` 的 `duration` 之和。不同 pipe 可以重叠，不能将各 pipe 忙量相加当作求解时间或核利用率。
- Q1 的依赖间隔是 `target_task.start − source_task.end`，来源为 `task_dependencies` 和各核 Task 时间线。它含题定等待及其他排队，不能全部解释为通信开销。
- Q2/Q3 的释放延迟是 `copy_in_release − copy_out_end`；下文“释放后等待”是 `copy_in_start − copy_in_release`，均取自 `cross_core_transfers`。它可能含 pipe、调度、内存和顺序限制。中位数或最大值只是时间线观察，不能相加称作关键路径，也不能作为严格因果归因。
- 额外搬运分别报告 `data_movement_bytes.partition_added_copy_bytes` 和 `spill_added_copy_bytes`。它们是评估器的字节量，不是 DDR 忙周期；Cache 命中率按 `hit_bytes / (hit_bytes + miss_bytes)` 计算。

**003：更多边界与搬运，换来更均匀的计算分配；仍有较长等待**

003 的 Q1 fast 是 stage=8，best 是 DP。两者 PIPE_M 总忙量均为 438792 周期，但分配明显不同：

| 核 | fast PIPE_M | best PIPE_M | fast 核结束 | best 核结束 |
|---|---:|---:|---:|---:|
|0|320008|195012|434569|266157|
|1|18284|60020|430464|262052|
|2|34532|63996|436452|268040|
|3|31304|62156|436464|268052|
|4|34664|57608|436452|268040|

主核的 PIPE_M 忙量减少 124996 周期，其余四核获得更多计算工作。这与 Makespan 降低同时出现，是负载重分配的直接证据；并不证明所有下降都由这一项独立造成。

Q1 代价也有实测：Task 数 20→39；跨核 Task 依赖 31→91；所有核 COPY_IN 操作数 1609→2441；分区额外搬运 2020210→3604462 字节，Spill 均为 0。依赖间隔的中位数 40132→5274、最大值 400029→237643 周期。边界更多却整体更快，说明仅按 Task 数或额外字节数评价方案会漏掉计算分布与执行时序。Q1 原始操作记录没有可直接用于逐张量重复读取归类的 tensor_id；本文不能把 COPY_IN 增量精确拆成“同一输入的重复读取”与其他边界搬运。

Q2 同样表现为计算分布改善，同时增加通信：

| Q2 方案 | 周期 | 跨核 transfer 数 | transfer 字节 | 分区额外搬运字节 | Spill 字节 | 释放后等待中位数 / 最大值 |
|---|---:|---:|---:|---:|---:|---:|
|fast|440920|721|366464|1356046|0|3783 / 408511|
|best|261615|1586|1033670|3421602|0|2239 / 235280|

两者每条 transfer 的释放延迟均为 500 周期。best 仍存在很长的释放后等待；从这些字段可以确认发生了等待，不能直接断言瓶颈是网络带宽或某一条最长 transfer。

003 的 Q1/Q2/Q3 best_plan 内容相同；Q3 的无 Cache 回放方案也与 best_plan 相同。Q3 best 的 transfer 数仍为 1586，释放后等待中位数 / 最大值为 1783 / 229036。Cache 命中字节率为 29.2245%，同方案 Q2=261615、Q3=256649，周期比 1.019349（周期减少 1.8982%）。这说明本例的字节命中比例明显高于最终周期改善比例；没有证据将全部命中字节按固定带宽直接折算为 Makespan 收益。

003 Q1 作业保留了合法 DP incumbent，最终状态为 complete；最后一次 directed_move 官方调用记录为 timeout，`call_wall_seconds` 约 4.406 秒，作业停止原因 `wall_or_recipe_limit`，整次求解约 90.109 秒。不能把“有合法最终结果”解释为所有候选都完成，也不能将整次求解时间当作 DP 配方的独立构造耗时。

**007：计算忙量相同，边界和溢写变化；Cache 冷读取没有收益**

fast 为 component，best 为 wave=4。所有五个核在相应方案中具有相同的以下数值：

| 每核指标 | fast（Q1/Q2） | Q1 best | Q2 best |
|---|---:|---:|---:|
|核结束周期|203834|198502|197052|
|PIPE_M 忙量|195804|195804|195804|
|PIPE_V 忙量|50616|50616|50616|
|PIPE_MTE2 忙量|17390|74792|35980|
|PIPE_MTE3 忙量|15080|58052|33670|
|COPY_IN 数|114|336|184|
|COPY_OUT 数|111|222|181|
|官方 Task 数|1|2|1|

`核结束 − PIPE_M 忙量` 从 fast 的 8030 周期降为 Q1 的 2698、Q2 的 1248。它表明该 pipe 在完整执行窗口内的非忙时间减少，包括开始前、操作之间和尾部时间；它不是全部空闲时间，也不是严格的关键路径分解。即使 MTE 忙量增加，计算与搬运的重叠和操作时序也可能改善。这里只确认同时出现的实际时序变化，不声称单一机制已被因果实验隔离。

Q1 总 Task 数 5→10，产生 5 条同核依赖、没有跨核依赖；每核两个 Task 的间隔恰为 100 周期。分区额外搬运从 110592 升至 4372992 字节，Spill=0。Q2 best 每核有两个 subgraph，但官方将其纳入一个 Task；分区额外搬运仍为 110592，新增 Spill=2150400，二者合计额外 2260992 字节。Q2/Q3 best 没有跨核 transfer，不能将本例改善解释为减少跨核等待。

Q1/Q2/Q3 的 best_plan 内容相同。Q3 记录 0 次命中、920 次 miss，命中字节 0、miss 字节 2065920；同方案 Q2/Q3 均为 197052 周期，Cache 周期比为 1。

具体时序示例：`cache_events` 中 tensor 1000000001（9216 字节）在 t=0 被五核分别 miss，首次 insert 在 t=770。先发起的并发冷读取没有因为后来的插入而成为命中。该原始事件解释了这一张量没有享受共享 Cache 的原因；不能仅凭该示例概括所有张量。全例 0 命中由官方 `cache_stats` 直接确认。

依据：`case_007_q1_n5`、`case_007_q2_n5` 中 fast/best 对应原始响应；`case_007_q3_n5/best_official.json.gz`、`e002_official.json.gz` 及各 `result.json`。

**035：低加速与当前分配的核心负载偏斜相伴；命中不保证缩短尾部**

Q1 best 是 component，各核只有一个 Task，没有 Task 依赖，Spill=0。核结束为 `[95460, 26828, 18153, 21926, 11775]`；PIPE_V 忙量为 `[77834, 26406, 15704, 12509, 11456]`。主核承担明显更多的 PIPE_V 工作，其他核较早结束。本例低加速不能笼统归因于 Task 边界、跨核等待或 Spill。这里只证明当前方案负载偏斜，未证明这些操作不可进一步并行。

Q2 best 的核结束为 `[91394, 30119, 20528, 20635, 66026]`，PIPE_V 忙量为 `[74594, 26406, 15704, 12509, 14696]`。它记录 40 条 transfer、36512 字节；固定释放延迟 500，释放后等待中位数 253、最大值 711 周期；分区额外搬运 82240 字节，Spill=0。核心 0 仍是结束最晚的核。仅靠这组统计不能证明某一个特定 Task、tensor 或依赖是完整关键路径。

Q3 独立 best 与 Q2 独立 best 不是同一方案。必须使用 Q3 best 的专门回放：

| 同一份 Q3 best_plan | Makespan | 各核结束周期 |
|---|---:|---|
|无 Cache 的 Q2 回放|91400|[91400, 29696, 19952, 20300, 21459]|
|有 Cache 的 Q3|91401|[91401, 29484, 19739, 20291, 21460]|

命中字节为 9216、miss 字节为 433390，命中字节率 2.0822%（2 次命中，341 次 miss）。同方案周期比为 `91400 / 91401 = 0.9999890592`，Cache 使 Makespan 多 1 周期，而非获得正收益。部分核确实提前结束，但最晚结束的核心 0 多 1 周期。回放与 Q3 的释放后等待中位数都是 263，最大值分别为 719、718。现有汇总不足以将这 1 周期严格归因于某一次 Cache 操作或带宽竞争，故不补造解释，也不忽略负收益。

依据：`case_035_q1_n5/best_official.json.gz`、`case_035_q2_n5/best_official.json.gz`；`case_035_q3_n5/e006_official.json.gz`、`e007_official.json.gz` 及各 `result.json`。

**当前证据支持的后续关注点**

003 应保留能改善计算分布的 DP 构造配方，并在后续得到授权的方法修改中同时查看计算负载、搬运和等待，不能仅最小化搬运字节。007 应保留 wave 配方的实测收益，承认 Q2/Q3 Spill 增加以及本例 Cache 零收益；进一步重复读取优化需逐张量时序证据。035 值得关注当前主核的 PIPE_V 工作集中，而不是默认增加评估预算；是否能在不增加更大通信代价的前提下转移这些工作，现有记录尚不能证明。

这些是局部官方记录支持的诊断方向，不是已验证的新算法。本文没有运行任何新候选，没有把代理分数或计算下界写成官方周期或已认证最优性缺口，没有用停止原因 `global_compute_gap` 证明最优，也没有根据三个案例判断是否超过旧论文。完整覆盖、失败/超时、整体用时和本轮最终统计以主报告为准。
